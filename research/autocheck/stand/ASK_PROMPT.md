# Задание: вопросы `ask` к рубрикам пилота

Файлы рубрик: `research/autocheck/stand/rubrics/{opt,state,urls,weak,async}.json`. Задачи к ним: `research/autocheck/stand/tasks/<тема>.json` (id, kind, prompt, code, key). Другие файлы репозитория не читай.

Рубрика сообщает ученику, чего сайт НЕ нашёл в его ответе. Сайт может ошибаться: ученик мог записать то же иначе. Поэтому сайт не выносит приговор, а задаёт вопрос, на который ученик отвечает «есть» или «нет».

## Что сделать в каждом из пяти файлов

1. kind=code: каждому элементу `must` добавь поле `ask` — вопрос ученику.
2. kind=oral: каждому элементу `concepts` добавь поле `ask`; каждому элементу `false` добавь поле `ask`.
3. Проверь все тексты `miss` и `msg` (code, predict `wrong[].msg`, `why[]`, oral) по правилу «не выдавай ответ» ниже и перепиши нарушающие. Остальные тексты не трогай.
4. Больше ничего не меняй: `pat`, `accept`, `outs`, `groups`, `complete`, порядок и состав элементов остаются как есть.

## Правила для `ask`

1. Одно предложение, до 120 символов, заканчивается знаком «?».
2. Спрашивает, есть ли в ответе нужная вещь: «Есть ли у тебя ранний выход для случая nil?», «Проверяешь ли ты статус ответа до декодирования?». Не «Ты забыл…», не «Почему нет…», без упрёка.
3. Называет идею, а не строку кода: нельзя писать готовую конструкцию из ключа (`guard let id else { return nil }`). Можно называть ключевое слово или API одним словом (`guard`, `weak`, `await`), если без него вопрос непонятен.
4. Для `concepts`: «Сказал ли ты, что …?» / «Объяснил ли ты, почему …?» — по смыслу `label`.
5. Для `false`: вопрос-уточнение, действительно ли ученик утверждал заблуждение: «Ты имел в виду, что ?? заменяет и пустую строку?».

## Правило «не выдавай ответ» для `miss`, `msg`, `why`

Текст объясняет, что не так и почему это важно, но не содержит готового решения: никакой строки кода из ключа целиком и никакого фрагмента кода длиннее трёх слов-токенов подряд из новой части ключа. Называй конструкцию или идею словами. Длина до 220 символов.

## Проверка

После правки каждый файл должен парситься: `python3 -c "import json,sys;d=json.load(open(sys.argv[1]));print(len(d))" <путь>` → 10. В финальном сообщении: сколько `ask` добавлено и сколько текстов переписано по каждому файлу.
