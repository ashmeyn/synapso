# Задание: ответы-кандидаты для стенда автопроверки

Ты получаешь файл с 10 учебными задачами по Swift/iOS (JSON: id, kind, prompt, code, key).
Ученик — новичок, пишет ответ по памяти в пустое текстовое поле на телефоне, ключа не видит.
`code` — условие/каркас, который ученик видит. `key` — эталон: сначала ответ, после пустой строки — пояснение.

Для КАЖДОЙ задачи напиши 8 реалистичных ответов ученика. Не читай никаких других файлов репозитория.

## Классы ответов (поле cls) и истина (поле truth)

Для kind=code (написать/дописать/исправить/переписать код):
1. `same` ×1 — truth ok. Тот же ответ, что в ключе, но набран иначе: другие отступы, пробелы, переносы строк, лишний комментарий, пустые строки.
2. `alt` ×2 — truth ok. Верное решение, написанное ИНАЧЕ: другая конструкция (if let вместо guard let, тернарный оператор, другой порядок независимых строк, другие имена локальных переменных, явный self., явный тип, развёрнутое замыкание вместо $0 и т. п.). Только то, что точно компилируется и выполняет ВСЕ требования prompt (если prompt требует конкретную конструкцию — не нарушай). Если не уверен, что вариант корректен, — возьми более консервативный.
3. `near` ×2 — truth bad. Почти верно, одна содержательная ошибка: перепутано условие, не тот оператор, пропущена одна обязательная строка, не то свойство, нарушено одно явное требование prompt.
4. `novice` ×2 — truth bad. Типичная ошибка новичка: force unwrap вместо безопасного разворачивания, забыл return/else/await/try/weak, `=` вместо `==`, незакрытая скобка, перепутал let/var, не тот тип, обращение не к той переменной.
5. `wrong` ×1 — truth bad. Неверный по сути ответ (другая идея, не решает задачу) или обрывок.

Для kind=predict (предсказать вывод): ответ — то, что ученик записал бы как вывод, иногда с коротким объяснением.
1. `same` ×1 ok — вывод как в ключе (построчно).
2. `alt` ×2 ok — те же значения в том же порядке, но записаны иначе: в одну строку через запятую, с кавычками или без, с коротким пояснением на русском после.
3. `near` ×2 bad — одна строка/значение неверны или перепутан порядок двух строк.
4. `novice` ×2 bad — типичное заблуждение по теме (например: «?? заменит пустую строку», «deinit сразу после = nil первой ссылки»).
5. `wrong` ×1 bad — неверно по сути.

Для kind=oral (устный ответ своими словами, по-русски, 1–4 предложения, без кода или почти без):
1. `same` ×1 ok — полный ответ близко к ключу, но своими словами.
2. `alt` ×2 ok — полный и верный ответ совсем другими словами, разговорно, с другим порядком мыслей, синонимами.
3. `near` ×2 bad — верно, но пропущена одна ключевая мысль из ключа.
4. `novice` ×2 bad — содержит ложное утверждение-заблуждение (при этом может использовать правильные термины).
5. `wrong` ×1 bad — набор терминов без смысла или ответ не на тот вопрос.

## Реализм

1. Ученик часто набирает ТОЛЬКО новые/изменённые строки, а не весь код. Если каркас `code` длиннее 12 строк — в 6 из 8 ответов пиши только дописанный/изменённый фрагмент (строку, функцию или тело). Если каркас короткий — чередуй: половина ответов полный код, половина только фрагмент.
2. Для kind=code пояснение прозой добавляй только в 2 ответах из 8 (после пустой строки, по-русски, коротко). Истина определяется только кодом.
3. Пиши как человек с телефона: местами 2 пробела вместо 4, нет пробелов вокруг операторов, скобка на той же строке.
4. Ошибки должны быть разными и правдоподобными именно для ЭТОЙ задачи. Не повторяй одну и ту же ошибку в двух ответах.
5. Ответы не должны совпадать друг с другом после удаления пробелов.

## Формат результата

Один JSON-файл — массив из 80 объектов:
{"task": "<id задачи>", "cls": "same|alt|near|novice|wrong", "truth": "ok|bad", "answer": "<текст ответа, переводы строк как \n>", "note": "<по-русски, одной фразой: что именно отличается или в чём ошибка>"}

Запиши файл инструментом Write, затем проверь, что он парсится: `python3 -c "import json,sys;d=json.load(open(sys.argv[1]));print(len(d))" <путь>` — должно быть 80. В финальном сообщении — только число объектов и путь.
