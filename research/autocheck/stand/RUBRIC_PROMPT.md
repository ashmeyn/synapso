# Задание: рубрики автопроверки (`check`) для задач

Ты получаешь файл с 10 учебными задачами по Swift/iOS (JSON: id, kind, prompt, code, key, иногда points).
`code` — каркас, который видит ученик. `key` — эталон: сначала ответ, после пустой строки — пояснение.
Ученик-новичок пишет ответ по памяти в пустое поле: иногда только новые строки, иногда весь код.

Сайт должен офлайн, без ИИ, решить: ответ верный, неверный (и что именно не так) или «не уверен».
Для этого к каждой задаче нужна рубрика `check`. Ты её пишешь. Ответов учеников ты не видишь —
рубрика должна сработать на любых разумных ответах. Не читай другие файлы репозитория.

Главный принцип: ложное «верно» хуже ложного «неверно». Сомневаешься — делай рубрику строже.

## kind = code

```json
{"task": "opt.s3", "check": {
  "accept": ["guard let id = id else {\n    return nil\n}\nreturn \"/users/\\(id)\""],
  "must": [
    {"pat": ["guard let id else { return nil }", "guard let $a = id else { return nil }"],
     "miss": "Нет раннего выхода через guard let: при nil функция должна сразу вернуть nil, иначе дальше работать не с чем."},
    {"pat": ["return \"/users/\\($a)\""],
     "miss": "Не вижу сборки пути \"/users/<id>\" из развёрнутого значения."}
  ],
  "not": [
    {"pat": ["id!"], "msg": "Force unwrap: при nil приложение упадёт. Здесь нужен guard let — он и разворачивает, и даёт ранний выход."},
    {"pat": ["if let ... { ... }"], "msg": "Задание просит guard let, а не if let: guard оставляет развёрнутое значение доступным до конца функции."}
  ],
  "complete": true
}}
```

1. `accept` (0–3) — ДРУГИЕ заведомо верные варианты того фрагмента, который ученик должен написать (только новая/изменённая часть, не весь каркас). Сам ключ сюда не клади — он принимается автоматически. Переименование локальных переменных и другое форматирование движок прощает сам — такие варианты не нужны. Нужны варианты с другой конструкцией (длинная форма `guard let id = id`, `if`/тернарный оператор, если задание не запрещает, и т. п.). Только то, что точно компилируется и выполняет все требования prompt.
2. `must` (2–5) — признаки, которые ОБЯЗАНЫ быть в верном ответе. Каждый: `pat` — список шаблонов (достаточно одного совпавшего), `miss` — что сказать ученику, если признака нет. Признаки описывают суть задачи (новую часть), а не каркас. Вместе они должны покрывать все требования prompt, проверяемые по коду.
3. `not` (1–4) — типичные ошибки новичка именно в этой задаче. `pat` — список шаблонов, `msg` — объяснение. Шаблон из `not` не должен совпадать ни с ключом, ни с вариантами `accept`, ни со строками каркаса `code`.
4. `complete` — `true`, если ты уверен: ответ, где есть ВСЕ `must` и нет ни одного `not`, верен. Если верность зависит от того, что шаблонами не выразить (порядок далёких строк, логика), ставь `false` — тогда сайт скажет «признаки на месте, сверь сам».

### Язык шаблонов

Шаблон — фрагмент Swift. Сравнение идёт по токенам: пробелы, переносы строк и комментарии не важны; `self.` игнорируется; `guard let x = x` и `guard let x` считаются одним и тем же. Шаблон ищется в любом месте ответа ученика.

1. `$a`, `$b`, `$name` — ровно один идентификатор (любое имя). Одинаковое `$имя` внутри шаблона — одно и то же имя. Используй для локальных переменных, которые ученик называет сам. Имена из каркаса и API пиши буквально.
2. `...` — любое количество любых токенов (в том числе ноль), со сбалансированными скобками. Используй, где содержимое не важно: `DispatchQueue.main.async { ... }`.
3. Строковый литерал сравнивается целиком, дословно.
4. Делай шаблоны короткими и терпимыми: лучше 2–3 варианта в `pat`, чем один длинный. Не включай в шаблон то, что можно написать иначе без потери смысла.
5. Шаблон `not` должен ловить именно ошибку, а не верный код. Проверь мысленно: совпадает ли он с ключом? Если да — сузь.

### Сообщения `miss` и `msg`

Голос ментора, по-русски, до 220 символов: что не так → почему это важно (последствие) → куда смотреть. Не выдавай готовую строку кода целиком — называй конструкцию или идею.

## kind = predict

```json
{"task": "opt.s1", "check": {
  "outs": [["Гость", "", "0"]],
  "why": ["a равно nil — ?? подставил запасное значение.", "b — пустая строка, это не nil: ?? её не трогает.", "title — пустая строка, count равен 0."],
  "wrong": [{"out": ["Гость", "Гость", "5"], "msg": "Ты решил, что ?? заменяет пустую строку. Он срабатывает только на nil; \"\" — существующее значение."}]
}}
```

1. `outs` — список допустимых последовательностей вывода (обычно одна). Каждая — массив строк вывода по порядку, дословно как напечатает программа (пустая строка = `""`). Если допустимо несколько порядков — несколько массивов.
2. `needAll` — `true`, если задание требует назвать ВСЕ допустимые порядки (тогда ученик должен перечислить каждый).
3. `why` — по одной фразе на каждую строку первого массива: почему там именно это значение.
4. `wrong` (1–3) — типичные неверные предсказания (полная последовательность) и какое заблуждение за ними стоит.
5. Если ответ задачи — не вывод программы, а рассуждение, которое нельзя свести к списку значений, поставь `{"task": "...", "check": {"self": "причина"}}`.

## kind = oral

```json
{"task": "opt.s5", "check": {
  "concepts": [
    {"label": "?? срабатывает только на nil", "groups": [["nil"], ["тольк", "лишь", "именно", "если нет значен"]],
     "miss": "Не сказано главное: ?? подставляет запасное значение только когда значения нет (nil)."}
  ],
  "false": [
    {"groups": [["пуст"], ["замен", "подстав"]], "msg": "Похоже, ты говоришь, что ?? заменяет пустую строку. Это не так: пустая строка — существующее значение."}
  ]
}}
```

1. `concepts` (3–5) — обязательные мысли ключа. `groups` — список групп; мысль считается найденной, если из КАЖДОЙ группы в ответе встретилась хотя бы одна подстрока (регистр не важен). Пиши основы слов без окончаний («удержива», «освобожда»), добавляй синонимы и разговорные варианты, английский термин и русский. 1–3 группы на мысль.
2. `false` (0–3) — заблуждения: сочетания подстрок, которые встречаются в неверном ответе и вряд ли встретятся в верном.

## Формат результата

Один JSON-файл — массив из 10 объектов `{"task": "<id>", "check": {...}}`, по одному на задачу, в порядке задач.
Запиши файл инструментом Write, затем проверь, что он парсится: `python3 -c "import json,sys;d=json.load(open(sys.argv[1]));print(len(d))" <путь>` — должно быть 10. В финальном сообщении — только число объектов и путь.
