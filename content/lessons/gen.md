## Не теряй тип между полками

Назови два результата: первая id-полка даёт Int 71, полка названий — String «Эскиз». Один алгоритм «возьми первый» не должен превращать ответ в значение неизвестного типа.

## Пишем в лоб: Any всё принимает

Проверь смешанный массив: функция принимает Any, поэтому строка спокойно попадает туда, где caller надеялся получить id. Приведение as? вернёт nil вместо ожидаемого Int.

```swift
func firstLoose(_ values: [Any]) -> Any? { values.first }
let mixed: [Any] = ["Эскиз", 71]
let id = firstLoose(mixed) as? Int
print(id == nil)
```

Вывод true. Any полезен, когда неоднородность действительно нужна; здесь он ослабил контракт. Generic связывает тип входа и выхода, а не просто скрывает его имя.

## Один параметр типа связывает данные

Напиши `<T>`: имя временного параметра типа. В каждом вызове компилятор выбирает конкретный T; [T] и T? относятся к тому же типу. Функция не может без основания обещать операции любого неизвестного типа.

```swift
func firstValue<T>(_ values: [T]) -> T? {
    values.first
}
print(firstValue([71, 72]) ?? 0)
print(firstValue(["Эскиз", "Фото"]) ?? "Нет")
```

Вывод 71, затем «Эскиз». Для пустого [Int] результат Int? со значением nil. Если передать массив другого типа, это другой вызов того же алгоритма, не необходимость as? на выходе.

## Тип выводится, но не исчезает

Попробуй let titles: [String] = ["Эскиз"], затем let value = firstValue(titles): value имеет String?. Для пустого литерала дай контекст, например let empty: [Int] = []. Аналогия: шаблон ящика одинаков, но этикетка каждого ящика заранее задаёт, что внутри.

## Generic-тип хранит один выбранный тип

Создай `Shelf<Int>` и `Shelf<String>` отдельно. add принимает Item, first возвращает Item?. В Int-полку нельзя добавить String. Item — параметр нашего типа; специальный язык протоколов для этого не нужен.

```swift
struct Shelf<Item> {
    private var items: [Item] = []
    mutating func add(_ item: Item) { items.append(item) }
    func first() -> Item? { items.first }
    var count: Int { items.count }
}
```

После двух add в `Shelf<Int>` count равен 2, first равен 71. Generic не означает «любой тип при каждом добавлении»; конкретный экземпляр уже выбрал Item.

## Подвох: T не обещает равенство

Не вызывай contains(value) без ограничения: он требует сравнение ==, которого произвольный T не обещает. Добавь T: Equatable; это контракт из proto, который предоставляет возможность сравнения.

```swift
func has<T: Equatable>(_ value: T, in values: [T]) -> Bool {
    values.contains(value)
}
print(has(71, in: [71, 72]))
print(has("Фото", in: ["Эскиз"]))
```

Вывод true, false. Нельзя исправлять ошибку принудительным приведением к Int: функция должна оставаться полезной и для String.

## where ограничивает нужную часть

Оставь add и first доступными любому Item, а contains добавь только для Equatable. extension продолжает Shelf, объявленный выше; where задаёт условие доступности этого расширения.

```swift
extension Shelf where Item: Equatable {
    func contains(_ item: Item) -> Bool { items.contains(item) }
}
```

Структура без Equatable по-прежнему может храниться в Shelf, но для неё contains недоступен. Не ограничивай весь контейнер, если сравнение нужно лишь одному методу. Если задача просит заменить совпадения old на new, пройди [T], сравни каждый элемент и собери новый [T]; в такой функции аргументы old/new тоже имеют T, а ограничение Equatable разрешает сравнение.

## Итог: два контракта без cast

Собери функцию, контейнер и условный метод. Одинаковый код обслуживает id и названия, а компилятор сохраняет тип и проверяет доступность сравнения.

```swift
func firstValue<T>(_ values: [T]) -> T? { values.first }
struct Shelf<Item> {
    private var items: [Item] = []
    mutating func add(_ item: Item) { items.append(item) }
    func first() -> Item? { items.first }
}
extension Shelf where Item: Equatable {
    func contains(_ item: Item) -> Bool { items.contains(item) }
}
var ids = Shelf<Int>()
ids.add(71); ids.add(72)
print(ids.first() ?? 0)
print(ids.contains(72))
print(firstValue(["Эскиз", "Фото"]) ?? "Нет")
```

Вывод 71, true, «Эскиз». Специализация — возможная оптимизация компилятора для конкретных типов; она не обещает отдельной копии машинного кода для каждого вызова и не является причиной типобезопасности.

## Проверь себя

Объясни ограничение, прежде чем добавлять его.

- Чем T? отличается от Any? в этом контракте?
- Почему `Shelf<Int>` не принимает String?
- Зачем where на расширении, если first не сравнивает элементы?

## Ответы к «Проверь себя»

- `T?` сохраняет конкретный тип: `firstValue([71, 72])` возвращает `Int?`, и caller сразу получает число без приведения. `Any?` скрывает тип, поэтому на выходе нужен `as? Int`, и при смешанном массиве он молча даёт `nil` вместо id. Generic связывает тип входа и выхода, и ошибку типа ловит компилятор, а не проверка во время работы.
- Экземпляр `Shelf<Int>` уже выбрал `Item = Int`, поэтому `add(_ item: Item)` у него принимает только `Int`. Как этикетка на ящике: шаблон общий, но этот ящик заранее подписан под числа. Попытка `ids.add("Эскиз")` — ошибка компиляции, а не значение, которое потом придётся отбрасывать.
- `where Item: Equatable` ставит условие только на это расширение: `contains` требует `==`, а `add` и `first` сравнения не делают. Если ограничить весь `Shelf`, структура без Equatable перестанет в нём храниться, хотя хранению сравнение не нужно. Поэтому сравнимым элементам достаётся `contains`, а `add` и `first` остаются у любого `Item`.

# ГЛУБЖЕ

## Несколько требований в where

Если функция использует имя и сравнение, укажи оба контракта: where T: Named, T: Equatable. Не добавляй ограничения ради предполагаемой скорости; каждое должно оправдываться операцией в теле.

## Специализация не гарантирована

Не обещай, что generic всегда быстрее другого подхода. Видимость тела, оптимизация и границы модулей влияют на специализацию; общий код тоже может передавать сведения о конкретном типе. Производительность устанавливается измерением, контракт типов — компилятором.

## Не ставь Equatable на весь контейнер

Попробуй `Shelf<Preview>` для структуры без Equatable: добавление и чтение должны оставаться доступны. Условный contains ограничивает одну способность, не основной способ хранения.

## Один T и два разных типа

Если аргументы разделяют T, функция связывает их одним выбранным типом. Для независимых типов объявляют отдельные параметры A и B. Если явно выбрал Any в качестве T, неоднородность возвращается по твоему решению; generic сам по себе не запрещает Any.
