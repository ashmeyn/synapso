## Что должен сделать экран

```swift
struct Folder {
    let name: String
    let files: [Int] // размеры файлов в КБ
    let subfolders: [Folder]
}
```

У папки есть свои файлы и подпапки, у подпапок — свои подпапки, и так сколько угодно уровней. Экран спрашивает: сколько весит «Фото» со всем содержимым?

## Пишем в лоб: цикл на каждый уровень

Можно сложить файлы «Фото», потом пройти циклом по подпапкам, внутри — ещё одним циклом по их подпапкам. Но сколько циклов вложить? Глубина заранее неизвестна: два уровня сегодня, семь завтра. Нужен способ сказать «с подпапкой сделай то же самое, что с папкой».

## Матрёшка

Чтобы узнать, что внутри матрёшки, открываешь её — внутри матрёшка поменьше, с ней делаешь то же самое. Так до самой маленькой, которая уже не открывается: на ней всё и заканчивается. Рекурсия — это функция, которая вызывает саму себя на меньшей части задачи.

У неё всегда две части:

- **Базовый случай** — самая маленькая матрёшка: ответ известен сразу, без нового вызова.
- **Шаг** — открыть матрёшку: свести задачу к такой же, но меньшей, и вызвать себя.

Шаг обязан приближать к базовому случаю. «Меньше» бывает разным: `n - 1`, `n / 10` (число без последней цифры, а саму эту цифру даёт остаток `n % 10`), половина массива, подпапка вместо папки.

```swift
func sum(upTo n: Int) -> Int {
    if n <= 0 { return 0 }       // базовый случай
    return n + sum(upTo: n - 1)  // шаг: та же задача на n - 1
}
print(sum(upTo: 3)) // 6
```

`sum(upTo: 3)` ждёт `sum(upTo: 2)`, тот ждёт `sum(upTo: 1)`, тот — `sum(upTo: 0)`. Ноль отвечает сразу, и ответы складываются обратно: 0 → 1 → 3 → 6.

## Стек вызовов

Каждый вызов функции получает свою ячейку в стеке вызовов: там лежат его параметры и место, куда вернуться. Пока вложенный вызов не закончился, внешний стоит на паузе — на той строке, где вызвал себя.

```swift
func countdown(_ n: Int) {
    if n <= 0 {
        print("старт")
        return
    }
    print("до \(n)")
    countdown(n - 1)
    print("после \(n)")
}
countdown(2)
```

Вывод:

```swift
// до 2
// до 1
// старт
// после 1
// после 2
```

Всё, что стоит **до** рекурсивного вызова, печатается по пути вглубь, в прямом порядке. Всё, что **после**, — на обратном пути, когда вызовы снимаются со стека, в обратном порядке. В момент «старт» на стеке три вызова: `countdown(2)`, `countdown(1)`, `countdown(0)`.

## Рекурсия по дереву

Папка — это и есть матрёшка: внутри лежат такие же папки. Размер папки — её файлы плюс размер каждой подпапки, а размер подпапки считается той же функцией.

```swift
func totalSize(of folder: Folder) -> Int {
    var sum = folder.files.reduce(0, +)
    for sub in folder.subfolders {
        sum += totalSize(of: sub)
    }
    return sum
}
let raw = Folder(name: "RAW", files: [900], subfolders: [])
let trips = Folder(name: "Поездки", files: [300, 200], subfolders: [raw])
let photos = Folder(name: "Фото", files: [100], subfolders: [trips])
print(totalSize(of: photos)) // 1500
```

Здесь базовый случай не написан через `if`: у папки без подпапок цикл не выполнится ни разу, и функция просто вернёт сумму своих файлов. Шаг — вызов на подпапке, она на уровень ближе ко дну. Функция посещает каждую папку один раз: O(n) по числу папок и файлов.

Тот же обход можно написать циклом с собственным массивом «папки, которые ещё не посмотрели»: достаём папку, добавляем её подпапки в массив, пока он не опустеет. Рекурсия делает то же, но этот массив за неё держит стек вызовов.

## Без базового случая — падение

Если шаг не приближает к базовому случаю, вызовы не кончаются. Каждый занимает ячейку стека, а стек у потока небольшой и фиксированного размера. Он переполняется — stack overflow, — и приложение падает с `EXC_BAD_ACCESS`. Это не ошибка компиляции: код собирается, падает при запуске. Так ведёт себя Debug-сборка; в Release компилятор иногда превращает последний вызов в цикл, и тогда приложение не падает, а зависает — баг тот же.

```swift
func countdownBad(_ n: Int) {
    if n == 0 { return }
    countdownBad(n - 1)
}
countdownBad(-1) // -1, -2, -3… до нуля не дойдёт никогда
```

Защита — базовый случай, который ловит всё, что «уже достаточно мало»: `n <= 0`, а не только `n == 0`.

## Сколько это стоит

Время — сколько всего вызовов: у `countdown(n)` их n + 1, O(n). Память — сколько вызовов лежит на стеке одновременно, то есть глубина: у `countdown(n)` это тоже O(n), а у `totalSize` — число уровней вложенности, а не всех папок. Для простого счёта вроде `sum(upTo:)` цикл проще и не тратит стек. Рекурсия выигрывает, когда данные сами вложенные: папки, комментарии с ответами, меню с подменю.

## Собираем

- Две части: базовый случай отвечает сразу, шаг вызывает функцию на меньшей части.
- Шаг обязан приближать к базе, база ловит всё «достаточно малое» (`<= 0`).
- Код до вызова — по пути вглубь, после — на обратном пути, в обратном порядке.
- Дерево: свой результат плюс результат функции на каждом ребёнке; лист — база.
- Нет пути к базе — stack overflow и падение; память — O(глубины).

## Проверь себя

- Что напечатает `countdown(1)` и сколько вызовов на стеке в момент «старт»?
- Где базовый случай у `totalSize(of:)`, если в ней нет ни одного `if`?
- Почему `countdownBad(-1)` собирается, но роняет приложение, и как это исправить?

## Ответы к «Проверь себя»

- «до 1», «старт», «после 1». В момент «старт» на стеке два вызова: `countdown(1)` стоит на паузе на строке вызова, `countdown(0)` печатает и возвращается. Потом `countdown(1)` продолжает и печатает «после 1».
- Базовый случай — папка без подпапок. Цикл по пустому `subfolders` не выполняется, новых вызовов нет, функция возвращает сумму своих файлов. Каждый шаг уходит на уровень глубже, а дерево конечное, поэтому рекурсия всегда доходит до таких папок.
- Компилятор не проверяет, дойдут ли вызовы до базы. С -1 шаг `n - 1` уводит всё дальше от нуля, проверка `n == 0` никогда не срабатывает, каждый вызов занимает ячейку стека — он переполняется, и приложение падает. Исправление: `if n <= 0 { return }`.

# ГЛУБЖЕ

## Два вызова — дерево вызовов

Если функция вызывает себя дважды, вызовы ветвятся. `f(n) = f(n - 1) + f(n - 2)` (числа Фибоначчи) на каждом уровне удваивает работу: время растёт как O(2ⁿ), хотя глубина только n. Одни и те же `f(k)` считаются много раз; лечится запоминанием уже посчитанного в словаре (мемоизация) или циклом снизу вверх.

## Рекурсия или цикл

Любую рекурсию можно переписать циклом с явным массивом-стеком. Так делают, когда глубина может быть огромной: связный список из ста тысяч узлов, обойдённый рекурсией, уронит приложение, а цикл — нет. На фоновых потоках стек ещё меньше, чем на главном.

## Хвостовая рекурсия

Вызов «хвостовой», если после него ничего не делается: `return f(n - 1)`. Некоторые языки гарантируют, что такой вызов не растит стек. Swift этого не гарантирует: в Release компилятор иногда так оптимизирует, в Debug — нет. Полагаться на это нельзя.

## indirect enum

Рекурсивные данные можно описать и через enum: случай, который содержит тот же enum, помечают `indirect`, чтобы Swift хранил его по ссылке.

```swift
indirect enum Expr {
    case number(Int)
    case add(Expr, Expr)
}
func eval(_ e: Expr) -> Int {
    switch e {
    case .number(let n): return n
    case .add(let a, let b): return eval(a) + eval(b)
    }
}
```

## Бинарный поиск рекурсией

Бинарный поиск — тоже «та же задача на половине». Рекурсивная версия передаёт границы `low` и `high` параметрами, база — пустой кусок `low >= high`. Глубина — O(log n), так что стеку это не страшно, но цикл из прошлой темы проще.
