## Два одинаковых названия — два события

У концерта 84 «Большой зал», у 85 — «Малый зал». На обеих кнопках написано «Концерт». Попробуй выбрать второй: должна открыться информация 85, а не первая запись с похожим названием.

Маршрут будем хранить как id. Название — подпись для человека; id — выбор конкретного события. Это сразу позволит открыть событие и из обычной кнопки, не только из строки списка.

## Пишем в лоб: ссылка без адресата

Посмотри, чего не хватает в этой самостоятельной попытке.

```swift
import SwiftUI
struct EventsScreen: View {
    var body: some View {
        NavigationStack {
            NavigationLink("Концерт", value: 84)
        }
    }
}
```

`NavigationLink` передаёт число 84, но нигде не сказано, какой экран построить для Int. У ссылки нет подходящего назначения, поэтому рассчитывать на открытие детали нельзя. Сам контейнер не угадывает экран по числу.

## Сначала стек, затем соответствие

`NavigationStack` держит корневой экран и страницы над ним. `navigationDestination` связывает тип переданного значения с экраном. `Int.self` означает сам тип Int, а `eventID` в замыкании — уже конкретное число.

```swift
NavigationStack {
    NavigationLink("Концерт", value: 84)
        .navigationDestination(for: Int.self) { eventID in
            Text("Событие \(eventID)")
        }
}
```

Это фрагмент `body` SwiftUI View. Нажатие передаёт 84; назначение для Int строит Text «Событие 84». Системная кнопка возврата снимает верхнюю страницу и показывает корень.

Ссылка похожа на номер на талоне, а назначение — на правило, к какому окну вести человека с таким талоном.

## Получаем данные по id

Окей, подставим зал. `events` — словарь id → зал, уже созданный в родительском View. Нужны две ссылки и одно правило назначения.

```swift
VStack {
    NavigationLink("Концерт", value: 84)
    NavigationLink("Концерт", value: 85)
}
.navigationDestination(for: Int.self) { eventID in
    Text(events[eventID] ?? "Событие удалено")
}
```

Фрагмент находится внутри `NavigationStack`; `events = [84: "Большой зал", 85: "Малый зал"]`. Оператор `??` из Optional подставляет текст при отсутствии ключа. Нажатие второй ссылки даёт «Малый зал». Если запись исчезла, получим «Событие удалено», а не падение из-за `!`.

Не размещай назначение внутри каждой строки ленивого списка: регистрация должна быть доступна стеку. В нашем случае она стоит на общем контейнере внутри стека.

## path делает переход управляемым

Теперь откроем событие из кнопки. `path` — массив значений маршрута; пустой массив означает корень. Int подходит, потому что соответствует Hashable — контракту для сравнения и хеширования значений, который нужен стеку.

```swift
@State private var path: [Int] = []
```

Это свойство родительского View. Свяжи стек с ним через `NavigationStack(path: $path)`. Внутри его корневого контейнера добавь кнопку:

```swift
Button("Открыть 84") { path.append(84) }
```

После нажатия `[]` превращается в `[84]`, и назначение строит деталь 84. Если из детали добавить 85, получится `[84, 85]`: сверху будет 85. Системный возврат оставит `[84]`.

`path.removeAll()` возвращает к корню. Для одного шага назад используй `if !path.isEmpty { path.removeLast() }`: проверка защищает пустой массив. Последний элемент описывает верхнюю страницу, а не выбранную строку на корне.

## Билет показываем поверх, а не добавляем в путь

Билет события удобнее открыть временным окном. `sheet` — модальное представление поверх текущего экрана; оно не добавляет id в path. Здесь нужна булева связь, которую ты уже умеешь передавать.

```swift
@State private var showsTicket = false
```

Это локальное свойство экрана события. К его контейнеру прикрепи:

```swift
Toggle("Показать билет", isOn: $showsTicket)
    .sheet(isPresented: $showsTicket) {
        Text("Билет на событие \(eventID)")
    }
```

Контекст: ты внутри `body` экрана с `let eventID: Int`. Включение показывает билет; закрытие жестом возвращает showsTicket в false. Стек остаётся на событии. В задании на память нам будет нужен путь из уведомления, а не модальное окно — сначала выбери, какое действие ожидает пользователь.

## Проверяем маршрут вручную

Начни с `path = []`. Вторая ссылка добавляет 85, назначение читает events[85], экран показывает «Малый зал». Возврат снимает 85, снова виден список. Кнопка «Открыть 84» добавляет 84, и та же регистрация ведёт в «Большой зал».

Подвох — зарегистрировать `navigationDestination(for: String.self)` при ссылках с Int. Типы не совпадут; наличие какого-то назначения недостаточно. Исправь регистрацию на Int.self, а не превращай id в строку ради обхода ошибки.

При `[84, 85]` «Все события» очищает весь путь. Если просто закрываешь билет, очищать путь нельзя: пользователь должен остаться на детали.

## Собираем управляемый стек

Вот самостоятельный экран. Деталь здесь оставлена внутри назначения, чтобы видеть всю цепочку на одном месте; позже её можно вынести в отдельный View с id и Binding к пути.

```swift
import SwiftUI
struct EventsScreen: View {
    @State private var path: [Int] = []
    private let events = [84: "Большой зал", 85: "Малый зал"]
    var body: some View {
        NavigationStack(path: $path) {
            VStack {
                NavigationLink("Концерт", value: 84)
                NavigationLink("Концерт", value: 85)
                Button("Открыть 84") { path.append(84) }
            }
            .navigationDestination(for: Int.self) { eventID in
                VStack {
                    Text(events[eventID] ?? "Событие удалено")
                    Button("Все события") { path.removeAll() }
                }
            }
        }
    }
}
```

- Тип value и тип navigationDestination должны совпадать.
- Для программного перехода меняй тот path, к которому привязан стек.
- Временное окно управляется отдельным состоянием sheet; возврат в корень — очищением path.

# ГЛУБЖЕ

## Разные типы маршрутов

Если у приложения появились событие и организатор, оба могут иметь Int id. Два назначения для Int не сообщают, какой смысл ты имел в виду. Нужен отдельный тип маршрута, например enum с вариантами события и организатора, соответствующий Hashable.

Не клади в путь большой изменяемый объект лишь ради удобства. Небольшое значение маршрута описывает выбор, а актуальные данные экран получает по нему. В нашей миссии один вид назначения, поэтому массива Int достаточно.

## Массив или NavigationPath

Для одного типа маршрутов оставь `[Int]` или массив своего enum: компилятор проверит, что туда попадает. `NavigationPath` пригодится, когда нужен путь из значений разных типов с поддержкой Hashable.

Попробуй назвать пользу до замены: тебе действительно нужны разнородные значения или просто несколько вариантов enum? Более универсальная коллекция не решает ошибки идентичности и регистрации назначения.

## Возврат не всегда означает корень

Проверь действие пользователя. «Назад» обычно снимает одну страницу, «Все события» открывает корень. Для первого проверь непустой path и удали последний элемент, для второго очисти массив.

Если путь передан дочернему View через Binding, ребёнок меняет тот же массив у владельца. Новый локальный `@State path` не управляет родительским стеком. Другой вариант одного возврата — действие dismiss из окружения SwiftUI; оно относится к контексту текущего показа, поэтому не заменяй им всякую команду навигации.

## Данные исчезли после перехода

Допустим, маршрут 85 восстановился, но событие удалено. Дай экрану состояние «Событие удалено» и доступный возврат. Сохранённый id не гарантирует, что данные всё ещё существуют.

Именно поэтому мы читали словарь через Optional и не делали force unwrap. Восстановление пути после перезапуска и ссылка из внешнего URL требуют отдельной проверки входа; эта миссия пока меняет путь только внутри приложения.
