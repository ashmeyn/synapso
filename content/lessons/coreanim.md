## View отвечает за UI, слой — за вид

У UIView уже есть backing layer, доступный через view.layer: view создаёт и управляет им. CALayer отвечает за содержимое, геометрию и визуальные свойства; сам по себе не становится UIResponder для касаний. Самостоятельный CALayer можно добавить к другому слою через addSublayer. Начни с выбора владельца: view или твоё дерево слоёв.

## Пишем в лоб: тень под ножницами

Карточке поставили cornerRadius, включили masksToBounds и добавили тень. Но маска обрезает область за границей слоя, где как раз должна быть внешняя тень. Не увеличивай shadowOpacity наугад: сначала найди правило обрезки.

```swift
import QuartzCore
import CoreGraphics
let card = CALayer()
card.bounds = CGRect(x: 0, y: 0, width: 120, height: 60)
card.backgroundColor = CGColor(gray: 1, alpha: 1)
card.cornerRadius = 12
card.masksToBounds = true
card.shadowOpacity = 0.4
card.shadowRadius = 8
card.shadowOffset = CGSize(width: 0, height: 3)
```

Сам cornerRadius не означает обрезку всех дочерних слоёв. Для нужной обрезки обычно включают masksToBounds; для внешней тени это может оказаться противоположным требованием.

## Разделяем оболочку и содержимое

Представь рамку с подсветкой: стекло держит изображение внутри, свет выходит наружу. Внешний слой отвечает за тень без обрезки, внутренний — за скругление и обрезку контента. Попробуй назвать, у какого слоя должен быть masksToBounds=true.

```swift
let outer = CALayer()
let content = CALayer()
outer.masksToBounds = false
outer.shadowOpacity = 0.4
content.cornerRadius = 12
content.masksToBounds = true
outer.addSublayer(content)
```

Это фрагмент с импортированным QuartzCore; размеры зададим в практике. Для тени полезен shadowPath с известным контуром, но после изменения размеров его нужно обновлять.

## Неявные анимации: не все слои одинаковы

У самостоятельного CALayer изменения анимируемых свойств могут запускать implicit actions — действие находится через правила слоя и текущую транзакцию. У слоя UIView поведение управляет view; обычная запись за пределами UIView animation-блока обычно не создаёт такую анимацию. Не переноси поведение одного вида слоя на другой. Для мгновенной записи самостоятельного слоя можно отключить actions внутри транзакции.

```swift
CATransaction.begin()
CATransaction.setDisableActions(true)
layer.opacity = 0.9
CATransaction.commit()
```

Здесь layer — ранее созданный самостоятельный CALayer. Это локальное отключение неявных actions; явно добавленный CABasicAnimation само по себе оно не запрещает.

## Анимация не записывает результат за тебя

CABasicAnimation описывает изменение по keyPath между fromValue и toValue. В ошибочной попытке ниже opacity модели остаётся 0.3, несмотря на toValue=0.9. Если такую анимацию добавить, она будет лишь временно показывать переход; после обычного удаления анимации со слоя отобразится прежняя модель.

```swift
let layer = CALayer()
layer.opacity = 0.3
let animation = CABasicAnimation(keyPath: "opacity")
animation.fromValue = 0.3
animation.toValue = 0.9
animation.duration = 0.25
```

Мы пока не вызываем add и не ждём времени. Ошибка уже видна в данных: target указан у animation, но не у layer.

## Модель — цель, presentation — текущий вид

Слой модели хранит целевые значения. Слой presentation, если он доступен, отражает отображаемое промежуточное состояние; presentation() возвращает Optional, и менять его не нужно. При прерывании перехода можно прочитать текущую прозрачность оттуда, иначе взять model-значение. Не обещай presentation в дереве, которое ни разу не отображалось.

## Сначала конечное состояние, затем переход

Сохрани старое model-значение как начало, без implicit action запиши конечное, затем подготовь явную анимацию. Если слой уже анимировался, начало лучше выбрать из presentation по контракту прерывания; наш простой старт идёт из известного состояния 0.3. После подготовки отдельным шагом вызывают layer.add(animation, forKey: "fade").

Не лечи неизменённую модель сочетанием fillMode=.forwards и isRemovedOnCompletion=false: это удерживает визуальный эффект, а не делает model-значение правильным.

## Итог: проверяем до add

Эта функция возвращает подготовленный CABasicAnimation, ещё не запускает его. Проверь: layer.opacity уже равен target, animation содержит прежнее начало и новую цель. Так мы можем проверять контракт без ожидания 0.25 секунды.

```swift
import QuartzCore
import CoreGraphics
func prepareFade(layer: CALayer, to target: Float) -> CABasicAnimation {
    let start = layer.opacity
    CATransaction.begin()
    CATransaction.setDisableActions(true)
    layer.opacity = target
    CATransaction.commit()
    let animation = CABasicAnimation(keyPath: "opacity")
    animation.fromValue = start
    animation.toValue = target
    animation.duration = 0.25
    return animation
}
```

Продолжительность — настройка анимации, не инструкция тесту ждать. Реальная presentation-динамика и внешний вид потребуют отдельного отображения.

## Проверь себя

Закрой код и объясни две независимые пары.

- Почему тень и обрезку часто разделяют по слоям?
- Чем model отличается от presentation и почему toValue не меняет модель?
- Почему обычная запись у самостоятельного CALayer и view.layer может анимироваться по-разному?

## Ответы к «Проверь себя»

- `masksToBounds = true` обрезает всё за границей слоя, а внешняя тень живёт именно там, поэтому на одном слое скругление с обрезкой и тень мешают друг другу. Как в рамке с подсветкой из урока, делишь роли: `outer` с `masksToBounds = false` и `shadowOpacity` даёт тень, `content` с `cornerRadius = 12` и `masksToBounds = true` обрезает контент, и `outer.addSublayer(content)`. Поднимать `shadowOpacity` наугад бесполезно: дело в правиле обрезки, а не в силе тени.
- Model хранит целевые значения, а `presentation()` — то, что видно сейчас посреди перехода; он Optional и менять его не нужно. `CABasicAnimation` с `toValue = 0.9` лишь описывает временный показ перехода, а `layer.opacity` так и остаётся 0.3, и после снятия анимации экран вернётся к модели. Поэтому сначала без implicit action пишешь `layer.opacity = target`, потом готовишь анимацию от старого значения и только затем `add`; `fillMode = .forwards` с `isRemovedOnCompletion = false` модель не чинят.
- У самостоятельного `CALayer` запись анимируемого свойства может запустить implicit action: его находят правила слоя и текущая транзакция. Поведением `view.layer` управляет сама view, поэтому обычная запись вне UIView animation-блока там обычно не анимируется. Для мгновенной записи самостоятельного слоя оборачиваешь её в `CATransaction.begin()`, `setDisableActions(true)`, запись, `commit()`; явно добавленный `CABasicAnimation` это не отключает.

# ГЛУБЖЕ

## Иерархия слоёв и владение

addSublayer связывает слой с родителем; removeFromSuperlayer разрывает эту связь. Если view управляет своим backing layer, не назначай ему произвольного delegate вместо UIKit. Для собственных слоёв можно держать ссылку и управлять их переносом; сильная локальная переменная не исчезает только из-за removeFromSuperlayer.

## Контур тени

При известной форме запиши shadowPath, например CGPath(rect:bounds,transform:nil). Это даёт контур вместо необходимости выводить его из альфа-содержимого. После изменения bounds пересчитай путь. Для скруглённой карточки выбери соответствующий закруглённый контур; прямоугольный путь из учебного теста не делает круглую тень.

## Прерванный переход

Для нового fade возьми presentation()?.opacity как начало, если есть отображаемое состояние, иначе layer.opacity. В тесте можно передать visibleOpacity параметром и проверить обе ветки без времени. Это не проверка render server; это проверка выбора начального значения.

## Копирование анимации и удаление

При add Core Animation копирует animation. Изменение твоего исходного объекта позже не равно изменению уже добавленной копии. Удаление анимации не отменяет целевое model-значение; поведение при отмене проектируй отдельно. Не жди, что key анимации является свойством слоя: это имя записи в его списке анимаций.
