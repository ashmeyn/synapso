## Проверь сначала форму вызова

Спроси, какого типа выражение слева от точки. Конкретный TripNotice и any Notice открывают разный набор объявлений. Диспетчеризация — способ выбрать реализацию метода для данного вызова, а не ещё один вид памяти.

## Пишем в лоб: имя есть, требования нет

Прогони обе строки. detail объявлен только в extension, а в самом Notice требуется лишь title. Совпадение имени у TripNotice не добавляет новое требование в протокол.

```swift
protocol Notice { func title() -> String }
extension Notice { func detail() -> String { "Общее" } }
struct TripNotice: Notice {
    func title() -> String { "Поездка" }
    func detail() -> String { "Платформа 3" }
}
let concrete = TripNotice()
let erased: any Notice = concrete
print(concrete.detail())
print(erased.detail())
```

Вывод «Платформа 3», «Общее». Через any Notice выбирается extension-only detail: он статически связан с этим интерфейсом. В конкретном вызове видно одноимённое объявление TripNotice.

## Static: цель известна по объявлению

Рассмотри обычные прямые вызовы методов конкретной struct, final-методов и private-методов: переопределение не нужно или недоступно. Extension-only метод протокола также выбирается статически по видимому интерфейсу. Не делай вывод «любой метод struct всегда вызывается напрямую»: через требование generic/протокола может участвовать соответствие протоколу.

## Class: переопределение определяется объектом

Сохрани переменную базового типа и объект подкласса. Swift-классовое переопределение использует динамический контракт; vtable — таблица реализаций методов класса.

```swift
class NoticeRenderer {
    func render() -> String { "Общее уведомление" }
}
class TripRenderer: NoticeRenderer {
    override func render() -> String { "Поездка" }
}
let renderer: NoticeRenderer = TripRenderer()
print(renderer.render())
```

Вывод «Поездка». final запрещает дальнейшее переопределение, но не обещает конкретной прибавки скорости. Оптимизатор может девиртуализировать и обычный динамический вызов, если доказал цель.

## Протокольное требование имеет witness

Добавь detail в Notice. Для соответствия типа протоколу witness table задаёт реализации требований. Реализация по умолчанию в extension может стать реализацией требования, если тип не даёт своей. Аналогия: строка в официальном списке обязанностей выбирает исполнителя; совпавшая по имени внешняя подсказка сама в этот список не входит.

```swift
protocol Notice {
    func title() -> String
    func detail() -> String
}
extension Notice { func detail() -> String { "Общее" } }
```

С TripNotice из начала через any Notice теперь получим «Платформа 3». Модель witness объясняет контракт; итоговые машинные инструкции зависят от оптимизации и границы модуля.

## Generic не отменяет требования

Напиши `heading<N: Notice>`: тело знает протокольное требование title, а не конкретный тип каждого вызова. Соответствие N протоколу предоставляет нужную реализацию.

```swift
func heading<N: Notice>(_ notice: N) -> String {
    notice.title()
}
```

Для TripNotice результат «Поездка». Если вызвать extension-only detail из generic-тела без требования, снова выберется extension. Не исправляй такой контракт cast к одному любимому типу.

## private и Objective-C имеют отдельные границы

Помни: private helper базового класса не становится переопределённым от одноимённого метода подкласса. Для Objective-C message dispatch можно явно объявить @objc dynamic в NSObject-подклассе; одно @objc делает метод доступным Objective-C, но не равно обязательному dynamic для любого Swift-вызова.

```swift
import Foundation
class AlertBadge: NSObject {
    @objc dynamic func text() -> String { "Новая поездка" }
}
print(AlertBadge().text())
```

Вывод «Новая поездка». Это краткий пример выбора Objective-C динамического механизма, без swizzling и без обещаний производительности.

## Итог: требование исправило карточку

Собери Notice с detail в контракте и проверь прямой, existential и generic-вызов. Собственные объявления TripNotice остались прежними; меняется место обязанности в интерфейсе.

```swift
protocol Notice {
    func title() -> String
    func detail() -> String
}
extension Notice { func detail() -> String { "Общее" } }
struct TripNotice: Notice {
    func title() -> String { "Поездка" }
    func detail() -> String { "Платформа 3" }
}
let concrete = TripNotice()
let erased: any Notice = concrete
print(concrete.detail())
print(erased.detail())
func present<N: Notice>(_ notice: N) {
    print(notice.title())
    print(notice.detail())
}
present(TripNotice())
```

Вывод «Платформа 3», «Платформа 3», «Поездка», «Платформа 3». Проблема была в контракте, не в форме хранения struct.

# ГЛУБЖЕ

## Наследование соответствия с default-witness

Если базовый класс принял протокол за счёт default из extension, подкласс не заменяет уже выбранный witness одним совпавшим методом. Для маршрута через переопределение реализуй требование в базе как обычный overridable-метод и override в подклассе.

## Оптимизация не меняет смысл

Различай правило выбора реализации и инструкцию готового бинарника. Vtable/witness вызовы могут быть заменены прямыми после специализации или девиртуализации. Один просмотр оптимизированного кода не отменяет смысл требования протокола.

## Private не новый override-пункт

Если подкласс должен настраивать поведение, объяви доступный overridable-метод с нужным контрактом, а приватные детали оставь приватными. Случайное совпадение имён private helper и метода подкласса не является способом расширения.

## Objective-C и граница модулей

@objc dynamic уместен при необходимости Objective-C динамической инфраструктуры. Для class/witness механизмов детали ABI и resilience влияют на доступ через модуль; не превращай учебную таблицу в гарантию одной инструкции для всех сборок.
