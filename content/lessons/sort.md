## Что должен показать экран

Задача — название, срок в днях от сегодня и приоритет: 1 — важно, 3 — когда-нибудь.

```swift
struct TodoItem {
    let title: String
    let day: Int
    let priority: Int
}
let items = [
    TodoItem(title: "Купить корм", day: 2, priority: 2),
    TodoItem(title: "Оплатить свет", day: 1, priority: 3),
    TodoItem(title: "Позвонить врачу", day: 1, priority: 1)
]
```

Нужный порядок: «Позвонить врачу» (день 1, важно), «Оплатить свет» (день 1), «Купить корм» (день 2).

## Пишем в лоб: только по сроку

```swift
let today = items.sorted { $0.day < $1.day }
```

Срок упорядочен, но две задачи первого дня стоят так, как пришли: «Оплатить свет» выше «Позвонить врачу». Правило о приоритете мы просто не сказали.

## Правило сравнения

`sorted(by:)` принимает замыкание из двух элементов. Оно отвечает на один вопрос: должен ли `a` стоять раньше `b`? `true` — раньше, `false` — нет. Сам алгоритм сортировки Swift выбирает за тебя; от тебя — только правило.

Правило должно быть строгим: `<`, а не `<=`. Для двух равных элементов «раньше» — ложь в обе стороны. С `<=` выходит, что каждый из равных стоит раньше другого, и результат сортировки становится непредсказуемым.

## Составной ключ

Сначала сравниваем срок. Если сроки разные — решает срок. Если равны — решает приоритет.

```swift
let today = items.sorted { a, b in
    if a.day != b.day { return a.day < b.day }
    return a.priority < b.priority
}
```

То же короче — сравнением кортежей, они сравниваются слева направо: `(a.day, a.priority) < (b.day, b.priority)`.

## sorted или sort

`sorted(by:)` не трогает исходный массив и возвращает новый — подходит и для `let`. `sort(by:)` переставляет элементы на месте, поэтому работает только с `var` и ничего не возвращает.

```swift
var inbox = items
inbox.sort { ($0.day, $0.priority) < ($1.day, $1.priority) }
```

Если вызвать `items.sorted { … }` и не сохранить результат, исходный массив останется прежним — компилятор только предупредит о неиспользованном значении.

## Сколько это стоит

Сортировка сравнением стоит O(n log n): для тысячи задач это порядка десяти тысяч сравнений, а не миллиона, как у O(n²). Но это всё ещё дороже одного прохода O(n). Поэтому сортируют один раз, когда список готов, а не после каждого добавления.

## Сортировка руками: вставками

На собеседовании могут попросить отсортировать без `sorted`. Самый понятный способ — вставками, как раскладывают карты в руке: берёшь следующую карту и сдвигаешь её влево, пока слева не окажется меньшая.

```swift
func insertionSorted(_ input: [Int]) -> [Int] {
    var a = input
    for i in a.indices.dropFirst() {
        var j = i
        while j > 0 && a[j - 1] > a[j] {
            a.swapAt(j - 1, j)
            j -= 1
        }
    }
    return a
}
```

Для `[3, 1, 2]`: единица уходит влево за тройку — `[1, 3, 2]`, двойка встаёт между ними — `[1, 2, 3]`. Пустой массив и массив из одного элемента цикл не трогает. В худшем случае это O(n²), на почти отсортированном — почти O(n). В рабочем коде пиши `sorted`, руками — чтобы показать, что понимаешь, как это устроено.

## Собираем

```swift
func todayList(_ items: [TodoItem]) -> [String] {
    items
        .sorted { ($0.day, $0.priority) < ($1.day, $1.priority) }
        .map(\.title)
}
```

- Правило отвечает «стоит ли `a` раньше `b`» и всегда строгое.
- Составной ключ: сначала главный признак, при равенстве — следующий.
- `sorted` — новый массив, `sort` — на месте у `var`; сортируй один раз, цена O(n log n).

## Проверь себя

- Почему правило `{ $0.day <= $1.day }` — ошибка, даже если на примере порядок выглядит верным?
- Что окажется в `items` после строки `items.sorted { $0.day < $1.day }` без присваивания, и чем это отличается от `sort`?
- Как сортировка вставками разложит `[3, 1, 2]` и почему на почти отсортированном списке она быстрая?

## Ответы к «Проверь себя»

- Правило должно отвечать «стоит ли `a` строго раньше `b`». Для двух задач с одним сроком `<=` скажет «да» в обе стороны, а это противоречие: алгоритм рассчитывает на строгий порядок и при нём может вести себя непредсказуемо. На маленьком примере это может не проявиться, поэтому правило пишут через `<`, а равные элементы разводят вторым ключом.
- `items` останется прежним: `sorted` не меняет исходный массив, а возвращает новый, и без присваивания он просто теряется — компилятор лишь предупредит о неиспользованном результате. `sort(by:)` переставляет элементы на месте, но работает только с `var`.
- Единица сдвигается влево за тройку — `[1, 3, 2]`, затем двойка встаёт между единицей и тройкой — `[1, 2, 3]`. Каждый элемент сдвигается влево, пока слева не окажется меньший. Если список почти отсортирован, сдвигать почти нечего, и проход близок к O(n); в худшем случае — O(n²).

# ГЛУБЖЕ

## Стабильность

Сортировка стабильная, если равные по правилу элементы сохраняют исходный порядок. В текущих версиях Swift `sort` и `sorted` стабильны — это указано в документации. Поэтому можно отсортировать сначала по второстепенному признаку, потом по главному: внутри одинаковых главных значений останется порядок второстепенного. Явный составной ключ всё равно надёжнее и понятнее.

## Comparable вместо замыкания

Если у модели один естественный порядок, объяви его один раз: `extension TodoItem: Comparable { static func < (a: Self, b: Self) -> Bool { … } }` (для `==` понадобится и `Equatable`). Тогда работает `items.sorted()` без замыкания. Если порядков несколько — для разных экранов — оставь их замыканиями: модель не должна знать про экраны.

## Сортировка слиянием

Merge sort делит массив пополам, сортирует половины и сливает два отсортированных списка за один проход. Гарантированно O(n log n) и стабильна, но требует дополнительную память O(n). Это частый «следующий вопрос» после сортировки вставками.

## Строки для людей

`"Файл 10" < "Файл 2"` — правда: строки сравниваются посимвольно. Для списков, которые читает человек, используй `localizedStandardCompare`: он сравнивает числа внутри строк как числа и учитывает язык.
