## Смотрим на вызов

Смотри на задачу как на разговор с будущим читателем кода. `totalMinutes(durations, 10)` непонятен: десять — это ещё одно дело или запас времени? Метки параметров должны объяснять вызов.

```swift
let durations = [25, 40, 15]
// Хочется читать: totalMinutes(for: durations, bufferMinutes: 10)
```

## Пишем в лоб

Стажёр копирует расчёт суммы в экран расписания и в экран истории. Потом правило запаса времени меняется в одном месте, а во втором забывается. Функция собирает одно поведение в одной точке.

```swift
func sum(_ durations: [Int]) -> Int {
    var result = 0
    for minutes in durations { result += minutes }
    return result
}
```

Параметр `durations` внутри функции — константа. Мы меняем локальный `result`, а не входной массив.

## Делаем вызов читаемым

У параметра может быть внешняя метка для вызова и внутреннее имя для тела. `_` убирает внешнюю метку, когда она только мешает.

```swift
func totalMinutes(for durations: [Int]) -> Int {
    durations.reduce(0, +)
}
print(totalMinutes(for: [25, 40]))
```

Здесь `for` — часть способа вызвать функцию, а `durations` — имя массива внутри неё. Функцию с другой меткой Swift считает другим объявлением; при вызове метку нельзя просто забыть.

## Добавляем запас времени

Если запас времени нужен редко, даём параметру значение по умолчанию. Так один расчёт обслуживает оба случая.

```swift
func totalMinutes(for durations: [Int], bufferMinutes: Int = 0) -> Int {
    let subtotalMinutes = durations.reduce(0, +)
    return subtotalMinutes + bufferMinutes
}
print(totalMinutes(for: [25, 40]))
print(totalMinutes(for: [25, 40], bufferMinutes: 10))
```

Минуты храним целыми числами. Положительный запас добавляет время на дорогу или паузу между делами.

## Вариативный вход — когда удобно

Небольшую ручную проверку можно сделать вызовом с несколькими числами. Вариативный параметр `Int...` внутри функции выглядит как массив.

```swift
func quickMinutes(_ durations: Int...) -> Int {
    durations.reduce(0, +)
}
print(quickMinutes(25, 40, 15))
```

Длительности из расписания уже лежат в `[Int]`, поэтому основная функция принимает массив. Вариативный вход удобен лишь для ручного примера.

## Обновляем итог недели

Теперь после завершения дня нужно увеличить существующую переменную `weekMinutes`. Функция может вернуть новое значение, но условие задачи требует обновить переданную переменную. Тут уместен `inout`.

```swift
func add(_ amount: Int, to weekMinutes: inout Int) {
    weekMinutes += amount
}
var weekMinutes = 0
add(75, to: &weekMinutes)
```

`&` у вызова предупреждает: функция может изменить этот `var`. Передать `let` так нельзя. Для обычного расчёта длительности `inout` не нужен: проще вернуть результат.

## Подвох: отрицательное время

При `bufferMinutes: -10` план станет короче, хотя «запас» не может отнимать время. Договоримся, что отрицательный запас недопустим, и явно обработаем такой ввод.

```swift
func validBuffer(_ minutes: Int) -> Bool {
    minutes >= 0
}
```

Если тебя спросят, кто гарантирует корректный ввод, покажи проверку до расчёта. В следующем уроке про ошибки можно объяснять неверный ввод через `throws`.

## Что оставляем в проекте

```swift
func totalMinutes(for durations: [Int], bufferMinutes: Int = 0) -> Int? {
    guard bufferMinutes >= 0 else { return nil }
    let subtotalMinutes = durations.reduce(0, +)
    return subtotalMinutes + bufferMinutes
}
func add(_ amount: Int, to weekMinutes: inout Int) {
    weekMinutes += amount
}
var weekMinutes = 0
if let check = totalMinutes(for: [25, 40], bufferMinutes: 10) {
    add(check, to: &weekMinutes)
}
```

- Метка описывает аргумент в месте вызова; внутреннее имя нужно телу функции.
- Значение по умолчанию упрощает частый вызов.
- `inout` используй, когда цель именно изменить переданный `var`, а не вернуть вычисление.

## Проверь себя

- Почему вызов `totalMinutes([25])` не совпадёт с сигнатурой `totalMinutes(for:)`?
- Можно ли передать `let weekMinutes` в `add(_:to:)`?
- Почему длительность дня проще вернуть, а итог недели в этой задаче меняется через `inout`?

# ГЛУБЖЕ

## Функция может быть значением

Функцию можно передать другой функции или сохранить в переменной. Внешняя метка участвует в записи имени функции, но тип значения функции описывает типы входа и выхода.

```swift
let calculator: ([Int], Int) -> Int? = totalMinutes(for:bufferMinutes:)
let check = calculator([25, 40], 10)
```

Это основа для подменяемых правил расчёта в тестах. Начинай с обычной функции; выноси её в параметр, когда действительно нужно выбирать поведение.

## Что происходит с inout

Думай об `inout` как о чтении значения на входе и записи результата обратно на выходе. Компилятор может оптимизировать реализацию, но код не должен зависеть от конкретной оптимизации. Два пересекающихся изменяемых доступа к одной памяти опасны — Swift проверяет эксклюзивность доступа.

## Значение по умолчанию не валидатор

`bufferMinutes: Int = 0` означает только «если аргумент не передан, возьми ноль». Оно не запрещает передать отрицательное число. Проверка допустимого диапазона — отдельная часть контракта функции.
