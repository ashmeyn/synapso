## Два бага одного экрана

Сверху в списке лежит «Эпизод 12», ты отметил его «В очередь». Потянул список вниз — пришёл «Эпизод 13» и встал первым. Галочка теперь у 13, а у 12 её нет.

Второй баг: открыл эпизод, дождался описания, сходил в комментарии, вернулся — снова «Загрузка…». Оба бага про одно: когда SwiftUI считает вью той же самой, а когда — новой.

## Пишем в лоб: строки по номерам

Модель и строка на весь урок:

```swift
struct Episode: Identifiable {
    let id: Int
    let title: String
}
struct EpisodeRow: View {
    let episode: Episode
    @State private var isQueued = false
    var body: some View {
        Toggle(episode.title, isOn: $isQueued)
    }
}
```

У каждой строки своя отметка в `@State`. А вот список, который дал первый баг:

```swift
List {
    ForEach(episodes.indices, id: \.self) { index in
        EpisodeRow(episode: episodes[index])
    }
}
```

`id: \.self` у индексов значит «строка — это номер 0, 1, 2». После вставки под номером 0 стоит уже «Эпизод 13», а хранилище номера 0 осталось прежним, с `isQueued == true`. «Эпизод 12» уехал на номер 1 и получил чужое хранилище с `false`.

## Идентичность — номер пропуска

Сама структура `EpisodeRow` — дешёвое значение: SwiftUI создаёт её заново при каждом пересчёте `body` родителя. `@State` живёт не в ней, а в хранилище, которое SwiftUI привязал к идентичности вью.

Представь офис с пропусками. Сотрудник в новой рубашке, но с тем же номером пропуска получает свой шкафчик. Другой человек с этим номером получит тот же шкафчик с чужими вещами. Рубашка — новое значение структуры, шкафчик — `@State`, номер — идентичность.

Пересчёт `body` при той же идентичности ничего не сбрасывает. Смена идентичности сбрасывает: старое хранилище удаляется, новое начинается с начального значения.

Чиним список — номер пропуска берём из модели:

```swift
List {
    ForEach(episodes) { episode in
        EpisodeRow(episode: episode)
    }
}
```

`Episode` соответствует `Identifiable`, и `ForEach` берёт `episode.id`: отметка привязана к 12, где бы он ни стоял. Модель без `Identifiable` — укажи в `id:` её уникальное поле. Название — плохой ключ: два «Бонуса» получат один номер на двоих.

## Ветка if — тоже идентичность

Кроме id SwiftUI различает вью по месту в коде. Ветки `if` и `else` — два разных места, даже если в них один и тот же тип.

```swift
if isCompact {
    PlayerCard(title: "Мини-плеер")
} else {
    PlayerCard(title: "Полный плеер")
}
```

Переключил `isCompact` — карточка другой ветки создаётся с начальным `@State`, хранилище ушедшей удаляется. Чтобы сохранить состояние, оставь одну вью и меняй параметр: `PlayerCard(title: isCompact ? "Мини-плеер" : "Полный плеер")`.

## .id выдаёт пропуск явно

Иногда сброс нужен. Экран эпизода хранит черновик заметки, а родитель показывает на том же месте другой эпизод. Тип и место те же — черновик останется: новый `init` не заменяет хранилище (тема state).

Пишем `EpisodeScreen(episode: current).id(current.id)`. `.id` выдаёт новый пропуск, как только меняется значение: другой эпизод — пустой черновик. Значение должно быть стабильным: `.id(UUID())` меняется на каждом пересчёте и стирает состояние постоянно.

## onAppear — это не init

`onAppear` срабатывает при каждом появлении вью, а не один раз. В стеке экран исчезает, когда сверху открыли комментарии, и появляется снова после возврата. Отсюда второй баг:

```swift
.onAppear {
    Task {
        summary = try? await loader.summary(for: episode.id)
    }
}
```

Каждое появление — новый запрос. И баг потише: закрыл экран посреди загрузки, а `Task` работает дальше — его никто не отменяет.

`loader` — заглушка сети на весь урок. `await` значит «подожди результат, не блокируя экран»; подробно — в теме async.

```swift
struct SummaryLoader {
    func summary(for id: Int) async throws -> String {
        try await Task.sleep(for: .seconds(1))
        return "Описание эпизода \(id)"
    }
}
```

## .task живёт столько же, сколько вью на экране

`.task` запускает асинхронную работу при появлении и отменяет её, когда вью исчезает. Отменённый `Task.sleep` бросает ошибку, поэтому `try?` вернёт `nil`.

```swift
.task {
    if summary != nil { return }
    guard let text = try? await loader.summary(for: episode.id) else {
        return
    }
    summary = text
}
```

Появления повторяются, но готовое описание не грузится: `summary != nil` выходит сразу. Ушёл до конца загрузки — задача отменена, `summary` остался `nil`, при следующем появлении загрузка начнётся снова.

`.task(id: value)` добавляет правило: при смене `value` старая задача отменяется и стартует новая — для данных, которые зависят от меняющегося значения.

## Собираем экран эпизода

```swift
struct EpisodeScreen: View {
    let episode: Episode
    let loader = SummaryLoader()
    @State private var summary: String?
    @State private var note = ""
    var body: some View {
        VStack {
            Text(summary ?? "Загрузка…")
            TextField("Заметка", text: $note)
            NavigationLink("Комментарии") { Text("Комментарии") }
        }
        .task {
            if summary != nil { return }
            let id = episode.id
            guard let text = try? await loader.summary(for: id) else {
                return
            }
            summary = text
        }
    }
}
```

Родитель, меняющий эпизод на месте, добавляет `.id(current.id)`: новый эпизод — пустые `summary` и `note`.

- `@State` живёт, пока жива идентичность: id в `ForEach`, место в коде, `.id`.
- Строкам — стабильный id из модели, не номер и не название.
- `onAppear` и `.task` — при каждом появлении; `.task` отменяется при уходе.

## Проверь себя

- Почему при `ForEach(episodes.indices, id: \.self)` отметка уезжает на новый эпизод, а при `ForEach(episodes)` — нет?
- Что станет со `@State` карточки плеера, когда `isCompact` переключит её из ветки `if` в ветку `else`? А если у карточки стоит `.id(UUID())`?
- Сколько раз загрузится описание, если открыть эпизод, дождаться текста, сходить в комментарии и вернуться? А если уйти назад через полсекунды после открытия и потом открыть снова?

## Ответы к «Проверь себя»

- С индексами идентичность строки — её номер, и хранилище `@State` привязано к номеру 0, а не к эпизоду. После вставки сверху под номером 0 стоит «Эпизод 13» и получает старое хранилище с `isQueued == true`, а 12 уезжает на номер 1 с чужим `false`. `ForEach(episodes)` берёт `episode.id` из `Identifiable`, поэтому отметка едет вместе со своим эпизодом.
- Ветки `if` и `else` — разные места в коде, значит, разные идентичности: карточка из новой ветки создаётся с начальным `@State`, а хранилище старой удаляется, и при возврате тоже начнётся сначала. `.id(UUID())` хуже: новое значение на каждом пересчёте `body` — новая идентичность, состояние стирается при любой перерисовке родителя. Чтобы сохранить состояние, оставь одну вью и меняй параметр.
- Один раз: при возврате из комментариев `.task` снова запускается, но `summary != nil` выходит сразу. Если уйти через полсекунды, задача отменяется — `Task.sleep` бросает ошибку, `try?` даёт `nil`, `summary` не записан. При следующем открытии это новый экран с пустым `summary`, и загрузка начинается заново — всего два запроса, один из них отменён.

# ГЛУБЖЕ

## Ленивые строки тоже появляются

`List` создаёт строки по мере прокрутки. `onAppear` и `.task` строки срабатывают, когда она выезжает на экран, и снова — когда прокрутка вернула её после ухода. На этом держится подгрузка ленты: «последняя строка появилась — грузим следующую порцию». Отсюда же лишние запросы, если строка сама грузит что-то без проверки «уже есть».

## Пауза перед поиском

`.task(id: query)` с короткой паузой в начале даёт debounce без Combine:

```swift
.task(id: query) {
    try? await Task.sleep(for: .milliseconds(300))
    if Task.isCancelled { return }
    hints = await hintLoader.load(query)
}
```

Каждая буква меняет `query`, старая задача отменяется прямо во сне, и до запроса доживает только последняя. `Task.isCancelled` нужен потому, что `try?` проглотил ошибку отмены.

## AnyView и условные модификаторы

Популярное расширение `.if(condition) { $0.border(.red) }` внутри устроено как `if/else` — значит, две идентичности. Переключил условие, и вью внутри потеряла состояние. `AnyView` стирает тип, и SwiftUI сложнее понять, что поменялось. Где можно, меняй аргумент модификатора: `.border(isWarning ? .red : .clear)`.

## Где держать то, что должно пережить экран

`@State` экрана умирает вместе с его идентичностью. Если описание должно пережить уход и повторное открытие, храни его выше: в модели списка (`@StateObject` или `@Observable` из темы obs) или в кэше. Экран тогда только спрашивает «есть ли уже» и показывает.

## init вызывается чаще, чем кажется

`init` вью вызывается при каждом пересчёте `body` родителя — это просто создание значения. Тяжёлая работа и запросы в `init` повторятся десятки раз. Подготовку данных начинай в `.task`, а хранилище, которое должно жить с экраном, — в `@State` или `@StateObject`.
