## Как проходить набор

Здесь нет общей истории приложения: название темы обещает 20 разных коротких задач. Банк темы выдаёт задачи по одной, начиная с 01: читай условие, прячь ключ, проговаривай вход и результат, затем пиши. Семь ступеней ниже — тренировка процесса, а не замена двадцатки. Объяснение — как маршрут навигатора: назови куда идёшь и почему выбранный следующий шаг ведёт туда, а не просто читай строки вслух.

## Попытка в лоб: знакомый цикл, чужое обещание

Кандидат начинает maximum с best=0 и уверенно показывает положительные примеры. На [-5,-2] результат 0, хотя его нет во входе. Сначала выясни пустой случай и допустимый диапазон, иначе можно быстро написать неверную задачу. Ниже намеренно ошибочный вариант, не готовый ответ.

```swift
func badMaximum(_ values: [Int]) -> Int {
    var best = 0
    for value in values { best = max(best, value) }
    return best
}
```

## Контракт за несколько фраз

Спроси: вход уже отсортирован? Повторы допустимы? Нужны значения или индексы? Что значит символ, пустое и отсутствие ответа? Если ограничения не заданы, предложи свои и получи согласие. Для числовых задач этого набора границы, предотвращающие переполнение, записаны в условии; не расширяй их незаметно до любого Int.

## Сначала один ручной проход

Для счётчика прочитанных символов начни с 0 и пройди [«А», семейное emoji]. Два Character дают 2, не длину UTF-8. Инвариант: count — сумма для уже обработанных строк. Теперь каждый следующий += имеет причину. Это новый пример метода, не продолжение maximum.

```swift
func totalLengths(_ values: [String]) -> Int {
    var count = 0
    for value in values { count += value.count }
    return count
}
assert(totalLengths(["А", "👨‍👩‍👧‍👦"]) == 2)
assert(totalLengths([]) == 0)
```

## Пиши шаг, который объясняешь

Выбери понятный цикл или стандартную функцию под контракт. Не добавляй generic, архитектуру и многопоточность к одному массиву лишь ради впечатления. Когда тип результата Optional, обработай отсутствие явно; когда ошибка значима, не теряй её через compactMap. Пауза для уточнения допустима, если после неё продолжается решение.

## Проверка должна опровергать попытку

Запиши нормальный вход, пустой, один элемент и край из контракта. Для максимума нужен отрицательный массив, для пары — один элемент с удвоенной целью, для сохранения — отсутствие вызова и ровно один вызов. Набор happy path не доказывает правило. Если нашёл ошибку, назови строку причины и повтори тот же контрпример после правки.

## Двадцать задач — что открывать

В банке этой темы ровно 20 самостоятельных задач, номер 01–20 стоит в названии. Они не образуют один сценарий. Начни с 01–05, затем строки и указатели 06–14, после этого правила данных и эффекты 15–20. Не переходи дальше только потому, что прочитал ключ.

- 01–05: первое непустое, положительная сумма, максимум, стабильные уникальные, частоты.
- 06–10: анаграммы, слияние, порядок слов, палиндром, два разных индекса.
- 11–14: нули в хвост, уникальный префикс, окно без повторов, скобки.
- 15–18: рейтинг с tie-break, ошибка парсинга, пропущенное число, обновление по версии.
- 19–20: отложенный захват и проверка внешнего вызова.

## Итог: новый маленький контракт

Полный пример ниже отвечает только на «все значения строго положительны». Для пустого массива условие выполнено: нет ни одного нарушителя. Это явно выбранный контракт, не вывод из результата другого упражнения. Перед запуском назови нормальный вход и ноль как контрпример для ошибочного <0.

```swift
func allPositive(_ values: [Int]) -> Bool {
    for value in values { if value <= 0 { return false } }
    return true
}
assert(allPositive([2, 3]))
assert(!allPositive([2, 0]))
assert(allPositive([]))
```

После решения расскажи: что хранит цикл, когда завершается, как растёт работа и какая память добавлена. Если использовал sorted(), учти сортировку, а не только проход после неё. Если не успеваешь оптимизировать, оставь корректный базовый вариант и объясни следующий шаг.

## Проверь себя

Оцени свою работу по наблюдаемым действиям.

- Что уточнил до первой строки и какой пример заставил сменить подход?
- Какой инвариант объясняет переход и какие края проверены?
- Почему выбранная сложность относится к этому коду и что бы улучшил при большем входе?

## Ответы к «Проверь себя»

- Сверяешь, что до кода прозвучали вопросы контракта: отсортирован ли вход, допустимы ли повторы, нужны значения или индексы, что такое символ, пустой вход и отсутствие ответа, а не заданные границы ты предложил сам и получил согласие. Образец смены подхода — maximum: `best = 0` на `[-5, -2]` даёт 0, которого нет во входе, значит старт с нуля нарушает контракт. Если подход не менялся, назови контрпример, которым пытался его опровергнуть; если такого не было, проверка лишь подтверждала попытку, а не доказывала правило.
- Инвариант — что хранит переменная после каждого шага: в `totalLengths` `count` равен сумме длин уже обработанных строк, поэтому каждый `+=` имеет причину. Края — нормальный вход, пустой, один элемент и край из контракта: для максимума отрицательный массив, для `allPositive` — ноль и пустой массив. Набор одних happy path не засчитываешь: проверка должна опровергать попытку, а после правки повторяешь тот же контрпример.
- Сложность выводишь из своего кода: что хранит цикл, когда он завершается, как растёт работа и какая память добавлена. Если внутри есть `sorted()`, считаешь и сортировку, а не только проход после неё. Если оптимизировать не успел, оставляешь корректный базовый вариант и называешь следующий шаг для большого входа.

# ГЛУБЖЕ

## После чтения ключа

Закрой ответ и восстанови функцию на другом входе, затем измени одно требование. Если воспроизвести не получилось, это место для повтора, а не повод отметить навык освоенным. Совпадение текста кода не требуется, совпадение поведения — требуется.

## Оценка сложности без лозунга

Словарь обычно даёт усреднённый доступ, но хеширование длинного Character не бесплатно. Две вложенные границы не обязательно означают O(n²): считай, сколько раз каждая движется за весь запуск. Назови единицу размера, особенно когда работаешь со String.

## Минимальный способ проверить баг

Для неправильного шага придумай короткий вход, чтобы ошибка проявилась за один ручной проход. Огромная случайная выборка может помочь позже, но не заменяет доказательство. Для mutable state отдельно проверь исходное значение и возвращённое.

## Когда задача шире алгоритма

Если просят внешний вызов, покажи подмену зависимости и его контракт вместо настоящей сети. Если просят поток или время, сначала уточни порядок и механизм проверки, не добавляй sleep. Набор 20 задач тренирует короткое решение; проектирование целой фичи — следующая тема.
