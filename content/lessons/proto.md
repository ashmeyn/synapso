## Экрану нужно название, а не устройство каталога

В загруженном каталоге урок 1 — «Начало», 2 — «Практика». Демокаталог даёт только урок 1 с названием «Пример». Попроси запись 2 у демокаталога: строка должна честно показать «Недоступно».

Мы пока работаем с готовыми локальными данными, без воспроизведения и сети. Экрану нужны подпись источника и способ запросить название по id. Как каталог хранит данные, ему знать незачем.

## Пишем в лоб: функция привязана к одному типу

Эти типы выглядят похожими, но одинаковый метод ещё не делает их взаимозаменяемыми для параметра.

```swift
struct DownloadedAudioSource {
    func title(for trackID: Int) -> String? { "Начало" }
}
struct DemoAudioSource {
    func title(for trackID: Int) -> String? { "Пример" }
}
func rowTitle(source: DownloadedAudioSource) -> String? {
    source.title(for: 1)
}
let title = rowTitle(source: DemoAudioSource()) // ❌ другой тип
```

Компилятор отклоняет передачу DemoAudioSource вместо DownloadedAudioSource. Добавить вторую функцию можно, но её общий алгоритм придётся поддерживать отдельно. Давай опишем ровно то, что требуется от обоих источников.

## Протокол задаёт контракт

`protocol` перечисляет требования, а не хранит каталог. Имя типа начинается с большой буквы. `{ get }` требует возможность прочитать свойство; метод задан без тела.

```swift
protocol AudioSource {
    var label: String { get }
    func title(for trackID: Int) -> String?
}
```

Назови требования вслух: строковая подпись и запрос названия по Int id с возможным отсутствием ответа. Optional здесь обязателен: не всякий каталог содержит каждую запись.

Протокол похож на розетку с известным разъёмом: можно подключать разные устройства, если каждое подходит к одному контракту.

## Тип обещает выполнить требования

После двоеточия укажи AudioSource. Это соответствие протоколу: компилятор проверит все обещанные свойства и методы.

```swift
struct DownloadedAudioSource: AudioSource {
    let label = "На устройстве"
    let tracks = [1: "Начало", 2: "Практика"]
    func title(for trackID: Int) -> String? { tracks[trackID] }
}
```

Это продолжение объявления протокола. `let label` подходит к `{ get }`: от источника требуется чтение, не изменение. Поиск в словаре возвращает String?, поэтому неизвестный id не вызывает падение.

Второй источник может вообще не хранить словарь. `условие ? A : B` выбирает A при true, B при false.

```swift
struct DemoAudioSource: AudioSource {
    let label = "Демо"
    func title(for trackID: Int) -> String? {
        trackID == 1 ? "Пример" : nil
    }
}
```

Проверь: подписи и названия разные, но требования выполнены одним и тем же способом вызова.

## Принимаем любой подходящий источник

Теперь функция зависит от контракта. `any AudioSource` означает значение какого-то конкретного типа, соответствующего AudioSource; через этот параметр доступны требования протокола.

```swift
func rowText(source: any AudioSource, trackID: Int) -> String {
    let title = source.title(for: trackID) ?? "Недоступно"
    return "\(source.label): \(title)"
}
```

Контекст — объявленный AudioSource. Не путай `any AudioSource` с `Any`: первый гарантирует нужные операции, второй мог бы содержать даже число без метода title.

Функция не выбирает каталог сама. Ей передают источник снаружи; подробно передачу зависимостей разберём в di. Сейчас важно, что строка работает с обоими типами без проверки их названий.

## Пройдём два источника и отсутствующий id

Сначала восстанови, какой метод вызывается на каждой строке. Объявления протокола, источников и rowText уже существуют.

```swift
print(rowText(source: DownloadedAudioSource(), trackID: 2))
print(rowText(source: DemoAudioSource(), trackID: 1))
print(rowText(source: DemoAudioSource(), trackID: 2))
```

Вывод: «На устройстве: Практика», «Демо: Пример», «Демо: Недоступно». В последнем вызове метод вернул nil, а `??` дал запасной текст. Функция не полезла в чужой словарь: всё общение прошло через контракт.

Подвох — вернуть `""` для отсутствующего id. Пустая строка не nil, поэтому запасной текст не появится. Если контракт обозначает отсутствие через Optional, верни nil; не заставляй вызывающий код угадывать смысл пустой строки.

## Когда нужно разрешить запись

У аудиоплеера есть настройка скорости. Теперь контракт должен позволять не только прочитать, но и изменить значение: для этого требуется `{ get set }`.

```swift
protocol PlaybackSettings {
    var rate: Double { get set }
}
struct AudioSettings: PlaybackSettings {
    var rate = 1.0
}
var settings: any PlaybackSettings = AudioSettings()
settings.rate = 1.5
print(settings.rate)
```

Результат — 1.5. Заметь два `var`: реализация хранит изменяемую скорость, переменная settings позволяет изменить хранимое значение структуры. `let rate` не выполнил бы get set. Обратное допустимо: изменяемое свойство может выполнить контракт только на чтение, но контракт не обещает вызывающему коду запись.

## Собираем независимую строку

Теперь весь пример можно запустить без UI. В интерфейсе его результат передавался бы в Text; здесь print помогает проверить контракт отдельно.

```swift
protocol AudioSource {
    var label: String { get }
    func title(for trackID: Int) -> String?
}
struct DownloadedAudioSource: AudioSource {
    let label = "На устройстве"
    let tracks = [1: "Начало", 2: "Практика"]
    func title(for trackID: Int) -> String? { tracks[trackID] }
}
struct DemoAudioSource: AudioSource {
    let label = "Демо"
    func title(for trackID: Int) -> String? {
        trackID == 1 ? "Пример" : nil
    }
}
func rowText(source: any AudioSource, trackID: Int) -> String {
    let title = source.title(for: trackID) ?? "Недоступно"
    return "\(source.label): \(title)"
}
print(rowText(source: DownloadedAudioSource(), trackID: 2))
print(rowText(source: DemoAudioSource(), trackID: 2))
```

- Требуй только операции, которые использует вызывающий код.
- Тип явно объявляет соответствие и выполняет все требования.
- Не меняй смысл результата между реализациями: nil в этой миссии означает отсутствие записи.

## Проверь себя

Закрой код и объясни, почему замена источника вообще возможна.

- Почему одинакового имени метода без общего контракта не хватило для первой функции?
- Почему let label подходит к get, но let rate не подходит к get set?
- Что покажет строка для неизвестного id, если источник вернёт nil, а что — если ошибочно вернёт пустую строку?

# ГЛУБЖЕ

## Соответствие не равно наследованию

Попробуй сделать один источник структурой, другой классом. Оба могут выполнить AudioSource: протокол не требует общего класса и не копирует в них хранилище.

Если контракту нужны именно ссылочные объекты, его можно ограничить AnyObject. Нашему чтению названия это не требуется. Не добавляй ограничение только потому, что один из текущих источников написан как class.

## extension помогает, но не расширяет обещание автоматически

`extension` добавляет реализацию к существующему типу или протоколу. Для требования можно дать общее поведение: например, пустой каталог по умолчанию не содержит записей.

```swift
extension AudioSource {
    func title(for trackID: Int) -> String? { nil }
}
struct EmptyAudioSource: AudioSource {
    let label = "Пусто"
}
print(rowText(source: EmptyAudioSource(), trackID: 1))
```

Контекст — AudioSource и rowText из основы. EmptyAudioSource выполняет требование через extension; вывод — «Пусто: Недоступно». Реализации каталогов из основы имеют собственный title и используют его.

Теперь остановись на ловушке. В AudioSource нет требования badge, поэтому одноимённый метод конкретного типа не подменит помощник при вызове через any AudioSource.

```swift
extension AudioSource {
    func badge() -> String { "Каталог" }
}
struct BadgeDemoSource: AudioSource {
    let label = "Демо"
    func title(for trackID: Int) -> String? { nil }
    func badge() -> String { "Демо" }
}
let source: any AudioSource = BadgeDemoSource()
print(source.badge())
```

Здесь тоже существует AudioSource из основы. Вывод — «Каталог». Чтобы выбор badge зависел от реализации через контракт, добавь `func badge() -> String` в требования протокола; тогда этот вызов даст «Демо». Не требуй знание этой ловушки в базовой практике: сначала нужно уверенно выполнять сам контракт.

## Метод, меняющий структуру

Если потребуется не настройка свойства, а команда изменения — например, «запомнить последний урок», — протокол может потребовать `mutating func remember(trackID: Int)`. `mutating` разрешает методу менять саму структуру.

Реализация в структуре тоже отмечает изменяющий метод mutating; классу это слово не нужно. Наши title и text только читают каталог, поэтому такое требование в основной контракт не добавляли. Сначала назови изменение, потом разрешай его.

## any не заменяет весь разговор о типах

Через any AudioSource ты скрываешь конкретный тип за набором требований. У него есть своя стоимость хранения и вызова, а доступные операции ограничены контрактом. Здесь это ясный способ принимать разные источники.

Если позже понадобится сохранить связь одного конкретного типа между несколькими параметрами, пригодятся generics и some. Не меняй простой параметр лишь ради модного слова: сначала покажи, какую гарантию текущий any не даёт. associatedtype и такие связи разберём в соответствующих темах.
