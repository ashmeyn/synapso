## Что считается тем же уроком

Сначала задай правило библиотеки: один id означает один урок, даже если название обновилось. Два экземпляра с id 24 должны считаться равными для списка сохранённых уроков.

Это решение модели, не готовое свойство любого класса. Для статуса загрузки того же урока ключ тоже id: изменение isDownloaded не создаёт новый урок. Для закладки другое правило: место задаётся парой lessonID и second, поэтому две позиции одного урока могут различаться.

## Пишем в лоб: сравниваем адресатов

Предскажи результат до запуска. Созданы два экземпляра класса с одним id; проверка === отвечает, один ли это экземпляр, а не один ли это урок библиотеки.

```swift
final class SavedLesson {
    let id: Int
    var title: String
    init(id: Int, title: String) { self.id = id; self.title = title }
}
let first = SavedLesson(id: 24, title: "Вступление")
let second = SavedLesson(id: 24, title: "Новое название")
print(first === second)
```

Вывод false. Если отсеивать повтор урока только через ===, новое сетевое представление того же id пройдёт как отдельная запись. Нам нужно собственное правило равенства.

## Equatable задаёт правило ==

Напиши правило словами перед кодом: сравниваем id, игнорируем title. Equatable — контракт сравнения через ==; классу нужно реализовать его, а === остаётся проверкой идентичности.

```swift
final class SavedLesson: Equatable {
    let id: Int
    var title: String
    init(id: Int, title: String) { self.id = id; self.title = title }
    static func == (lhs: SavedLesson, rhs: SavedLesson) -> Bool {
        lhs.id == rhs.id
    }
}
```

Для двух объектов с id 24 получится first == second — true, first === second — false. static означает метод типа; lhs и rhs — левая и правая стороны сравнения.

## У структуры можно получить сравнение автоматически

Попробуй другое правило той же миссии: закладка равна другой, только когда совпадают и урок, и секунда. Все хранимые свойства этой структуры уже умеют сравниваться.

```swift
struct AudioBookmark: Equatable {
    let lessonID: Int
    let second: Int
}
let first = AudioBookmark(lessonID: 24, second: 30)
let copy = AudioBookmark(lessonID: 24, second: 30)
let later = AudioBookmark(lessonID: 24, second: 45)
print(first == copy)
print(first == later)
```

Вывод true, false. Для подходящей структуры компилятор синтезирует Equatable по всем хранимым свойствам. Если добавить поле или написать своё ==, смысл равенства может измениться — проверяй контракт.

## Hashable должен согласоваться с ==

Перед Set зафиксируй второе правило: если a == b, хэш должен совпадать. Hashable наследует Equatable; hash(into:) передаёт существенные компоненты в Hasher через combine. В нашем классе существенен только id.

```swift
static func == (lhs: SavedLesson, rhs: SavedLesson) -> Bool {
    lhs.id == rhs.id
}
func hash(into hasher: inout Hasher) {
    hasher.combine(id)
}
```

Это методы внутри SavedLesson: Hashable с id и title. Аналогия: хэш выбирает ящик для поиска, а == проверяет нужную вещь внутри. Одинаковый хэш не доказывает равенство; равным вещам нельзя назначать несовместимые ящики.

## Подвох: ключ изменился внутри Set

Остановись на классе: let saved не замораживает lesson.title. Если title участвует в == и hash(into:), после переименования объекта уже внутри Set меняется его ключ, а коллекция не получает обычную операцию удаления и вставки.

```swift
let lesson = SavedLesson(id: 24, title: "Вступление")
let saved: Set<SavedLesson> = [lesson]
let insertedTitle = lesson.title
lesson.title = "Обновлено"
print(insertedTitle)
print(lesson.title)
```

Этот фрагмент для ошибочного варианта, где равенство и хэш включают title. Напечатается «Вступление», «Обновлено»: изменён сам объект, уже помещённый в Set. Результат contains/remove после нарушения контракта не обещаем; он может зависеть от реализации, хэша и входов.

## Стабильный ключ сохраняет контракт

Вернись к правилу библиотеки: id неизменяемый, title — отображаемые данные. Включи только id и в ==, и в hash(into:). Тогда переименование не меняет ключ сохранённого урока.

Если задаче действительно нужно равенство по изменяемым данным, используй неизменяемый снимок значения: удали старое значение из Set, создай новое и вставь. Мутировать поле ключа общего объекта внутри коллекции нельзя.

## Итог: разные объекты, один урок

Собери самостоятельный пример. После переименования первый объект по-прежнему обозначает урок 24; второй экземпляр подходит для поиска и не добавляется как новый элемент.

```swift
final class SavedLesson: Hashable {
    let id: Int
    var title: String
    init(id: Int, title: String) { self.id = id; self.title = title }
    static func == (lhs: SavedLesson, rhs: SavedLesson) -> Bool {
        lhs.id == rhs.id
    }
    func hash(into hasher: inout Hasher) { hasher.combine(id) }
}
let first = SavedLesson(id: 24, title: "Вступление")
let second = SavedLesson(id: 24, title: "Новое название")
print(first === second)
print(first == second)
var saved: Set<SavedLesson> = [first]
first.title = "Обновлено"
print(saved.contains(second))
print(saved.insert(second).inserted)
print(saved.count)
```

Вывод false, true, true, false, 1. insert возвращает inserted: false, потому что равный элемент уже есть. title не обещает отдельный элемент, а === не подменяет правило библиотеки.

## Проверь себя

Объясни поведение на новом названии без запуска.

- Почему == true и === false могут быть одновременно?
- Почему hash(into:) не должен использовать title, если == сравнивает только id?
- Что нарушает изменение поля ключа у объекта, уже находящегося в Set?

## Ответы к «Проверь себя»

- `==` — правило равенства из `Equatable`, которое ты задаёшь сам: здесь `lhs.id == rhs.id`. `===` проверяет идентичность, то есть один ли это экземпляр класса. Два отдельно созданных объекта с id 24 — разные экземпляры, но один урок библиотеки, поэтому `first == second` — true, а `first === second` — false.
- Контракт `Hashable`: если `a == b`, хэши обязаны совпасть. Если `==` смотрит только на id, а `hash(into:)` добавит `title`, два равных урока с разными названиями получат разные хэши, и `Set` будет искать равный элемент не в том «ящике». Поэтому в обоих местах одни и те же компоненты: `lhs.id == rhs.id` и `hasher.combine(id)`.
- `Set` разложил объект по хэшу его ключа в момент вставки, а объект-класс можно поменять снаружи — `let saved` не замораживает `lesson.title`. Если `title` входит в `==` и `hash(into:)`, переименование меняет ключ без удаления и повторной вставки, и контракт коллекции нарушен: результат `contains`/`remove` уже не обещан. Поэтому ключ строишь на неизменяемом `id`, а для смены ключа удаляешь старое значение и вставляешь новое.

# ГЛУБЖЕ

## Не сохраняй числовой hashValue

Не превращай hashValue в id урока или ключ файла. Hasher использует случайную начальную настройку, а числовые хэши не гарантированы между запусками и версиями библиотеки.

Тестируй контракт и поведение Set, не ожидай конкретное число. В одном запуске равные значения должны дать равные хэши, но разные значения могут столкнуться.

## Качество хэша и коллизии

Представь два разных id, попавших в один хэш. Set всё равно использует == для различения, поэтому совпадение хэшей не делает уроки равными. Коллизии допустимы.

Но хорошая реализация должна включать существенные компоненты равенства: не своди все объекты к константе и не выкидывай часть составного ключа ради краткости. Чем хуже распределение, тем дороже поиск; точную цену не выводят из одного примера.

## Составная идентичность

Проверь границы id: в разных каталогах может существовать урок 24. Если система разрешает это, ключом становится пара catalogID и lessonID. Обе части должны участвовать и в ==, и в hash(into:).

Для AudioBookmark добавляется second: библиотечная идентичность урока и идентичность места прослушивания различаются. Сначала опиши сущность, затем выбирай компоненты.

## Обновление элемента значения

Если закладка — struct с Hashable, её копия меняется отдельно от значения, лежащего в Set. Чтобы заменить позицию 30 на 45, удали старую закладку и вставь новую.

Автоматический Hashable для подходящей структуры учитывает все хранимые свойства. Если добавишь служебный текст, а правило должно его игнорировать, напиши явные == и hash(into:) вместо надежды на синтез.
