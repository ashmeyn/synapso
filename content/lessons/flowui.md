## Что должно происходить в корзине

Начнём с одной книги: id 18, количество 1, цена 300 рублей. Нажми «Добавить» — количество станет 2, сумма 600. Ещё раз — 3 и 900. Следующее добавление запрещено, но «Сбросить» должно вернуть 0 и 0.

Ты уже знаешь `@State` и `Binding`. Теперь посмотрим, где принимается решение об изменении. Нам нужен понятный маршрут: данные идут от владельца к экрану, действие пользователя возвращается владельцу.

## Попытка в лоб: две цифры живут отдельно

Угадай, что покажет надпись после одного нажатия. Этот фрагмент — самостоятельный ошибочный экран.

```swift
import SwiftUI
struct CartScreen: View {
    @State private var quantity = 1
    @State private var total = 300
    var body: some View {
        VStack {
            Text("Количество: \(quantity), сумма: \(total)")
            Button("Добавить") { quantity += 1 }
        }
    }
}
```

Будет «Количество: 2, сумма: 300». `total` — отдельное состояние, поэтому изменение `quantity` его не исправляет. Дописать `total += 300` можно, но при следующем сбросе легко снова забыть вторую запись. Лучше убрать саму возможность расхождения.

## Сумму вычисляем, количество храним

Вернись к данным книги. `total` ниже — вычисляемое свойство: при чтении оно возвращает результат выражения, а не хранит ещё одно число.

```swift
struct CartItem {
    let id = 18
    var quantity = 1
    var total: Int { quantity * 300 }
}
```

Родитель будет хранить `@State private var item = CartItem()`. Когда SwiftUI снова вычислит его `body`, `item.total` получится из актуального количества. При 2 это 600, при 0 это 0. Отдельный `@State total` больше не нужен.

## Ребёнку вниз — только нужные данные

Не передавай весь `CartItem`, если блоку нужна только цифра. Начнём с части управления, которая пока умеет только показать количество.

```swift
import SwiftUI
struct QuantityControl: View {
    let quantity: Int
    var body: some View {
        Text("Количество: \(quantity)")
    }
}
```

Из родителя вызови `QuantityControl(quantity: item.quantity)`. Это значение для текущего построения интерфейса. Когда родитель обновится, он передаст новое значение; ребёнку не надо прятать его в собственный `@State`.

Аналогия здесь одна: родитель ведёт ведомость, а дочерний блок показывает выписку и отправляет запрос на изменение.

## Наверх — действие, а не второй источник

Добавим ребёнку `onAdd`. Тип `() -> Void` означает функцию без параметров и возвращаемого результата. Переданный кусок кода называется замыканием; он выполняется при нажатии, а не при создании кнопки.

```swift
struct QuantityControl: View {
    let quantity: Int
    let onAdd: () -> Void
    var body: some View {
        VStack {
            Text("Количество: \(quantity)")
            Button("Добавить", action: onAdd)
                .disabled(quantity >= 3)
        }
    }
}
```

`disabled` — модификатор: он возвращает представление с заданным поведением. Здесь блокируется только «Добавить». В родителе вызов выглядит так; `item` уже объявлен через `@State`, как в предыдущем разделе.

```swift
QuantityControl(quantity: item.quantity) {
    guard item.quantity < 3 else { return }
    item.quantity += 1
}
```

Сначала ребёнок вызывает действие. Затем родитель проверяет предел и меняет своё состояние. Проверка в действии защищает правило даже при другом вызове этого кода; `disabled` помогает пользователю увидеть ограничение.

## Модификаторы применяются по очереди

Окей, теперь оформим сумму. Не читай цепочку как список независимых настроек: следующий модификатор получает результат предыдущего.

```swift
Text("Сумма: 300 ₽")
    .padding(12)
    .background(Color.blue)
```

Сначала появился отступ вокруг текста, затем фон закрыл и текст, и этот отступ. Поменяй порядок:

```swift
Text("Сумма: 300 ₽")
    .background(Color.blue)
    .padding(12)
```

Теперь фон относится к области текста, а отступ находится снаружи. Для нашей плашки суммы выбираем первый порядок. Не переноси `disabled` на всю корзину ради краткости: у него тоже есть область действия, и сброс нам нужен даже при пределе.

## Пройди весь круг руками

На старте `item.quantity = 1`. Родитель читает `item.total = 300` и передаёт ребёнку 1. Нажатие вызывает `onAdd`, родитель записывает 2, новое построение показывает 600 и передаёт ребёнку 2.

После следующего нажатия получаем 3 и 900. «Добавить» отключается, «Сбросить» остаётся доступным и записывает 0; сумма становится 0, добавление снова разрешено. Заметь: нигде не пришлось вручную исправлять сумму или дочернюю копию количества.

Если поставить `.disabled(item.quantity >= 3)` на общий `VStack`, отключится и сброс. Исправление — оставить модификатор на самой кнопке «Добавить», как выше.

## Собираем корзину

Теперь восстанови целую цепочку. Сумма — результат чтения модели; изменение количества — решение владельца.

```swift
import SwiftUI
struct CartItem {
    let id = 18; var quantity = 1
    var total: Int { quantity * 300 }
}
struct CartScreen: View {
    @State private var item = CartItem()
    var body: some View {
        VStack {
            Text("Сумма: \(item.total) ₽").padding(12).background(Color.blue)
            QuantityControl(quantity: item.quantity) {
                guard item.quantity < 3 else { return }
                item.quantity += 1
            }
            Button("Сбросить") { item.quantity = 0 }
        }
    }
}
struct QuantityControl: View {
    let quantity: Int
    let onAdd: () -> Void
    var body: some View {
        Button("Добавить: \(quantity)", action: onAdd).disabled(quantity >= 3)
    }
}
```

- Храни независимые данные; результат расчёта получай из них.
- Передавай вниз значение, наверх — действие. Когда нужно прямое редактирование свойства, используй знакомый Binding.
- Проверяй порядок модификаторов и то, к какому представлению они применены.

## Проверь себя

Не подглядывай в итог. Объясни каждую часть одной фразой:

- Почему после сброса сумма меняется без отдельной записи в `total`?
- Кто решает, можно ли увеличить количество, и зачем ещё нужен `disabled`?
- Почему фон после `padding` охватывает отступ, а `disabled` на общем контейнере ломает сброс?

## Ответы к «Проверь себя»

- Сброс пишет только `item.quantity = 0`, а `total` — вычисляемое свойство `var total: Int { quantity * 300 }`, которое ничего не хранит. При новом вычислении `body` родитель читает `item.total` из актуального количества и получает 0. Второго числа, которое можно забыть обновить, просто нет, поэтому сумма и количество не расходятся.
- Решает владелец состояния — родитель: ребёнок лишь вызывает `onAdd`, а родитель в замыкании проверяет `guard item.quantity < 3 else { return }` и только потом пишет `item.quantity += 1`. Эта проверка защищает правило при любом вызове действия. `.disabled(quantity >= 3)` на кнопке «Добавить» нужен пользователю: он заранее видит, что предел достигнут.
- Модификатор получает результат предыдущего, поэтому `.padding(12).background(Color.blue)` сначала добавляет отступ, а фон закрывает уже текст вместе с ним; в обратном порядке фон останется только под текстом. У `disabled` тоже есть область действия: на общем `VStack` он отключит всё внутри, в том числе «Сбросить». Поэтому модификатор ставишь на саму кнопку «Добавить».

# ГЛУБЖЕ

## Когда уместен Binding

Представь, что добавление заменили на `Stepper`. Он ожидает связь к числу, а не callback — переданную функцию действия. Для простого редактирования количества это подходящий вариант.

```swift
struct QuantityEditor: View {
    @Binding var quantity: Int
    var body: some View {
        Stepper("Количество: \(quantity)", value: $quantity, in: 0...3)
    }
}
```

В родителе передай `QuantityEditor(quantity: $item.quantity)`. Диапазон `0...3` ограничивает управление через Stepper; сама модель от этого не запрещает другим местам записать 9. Если добавление требует проверки остатка или другого правила, действие у владельца делает решение явным.

## Почему ребёнок не должен запоминать вход

Получил `quantity` в параметре и решил положить его в дочерний `@State`? Сначала спроси, чей это черновик. Собственное состояние хранится для идентичности дочернего View, а начальный параметр не задаёт постоянную синхронизацию с родителем.

В нашей корзине это лишний источник истины. После родительского сброса ребёнок может показывать старое число. Оставь `let quantity` для чтения или `@Binding` для прямого редактирования. Отдельный черновик оправдан, если ты сознательно добавляешь «Сохранить» и «Отменить», чего в этой миссии нет.

## disabled наследуется контейнером

Проверь ловушку: снаружи отключён весь блок, внутри кнопку пытаются включить обратно.

```swift
VStack {
    Button("Сбросить") { item.quantity = 0 }
        .disabled(false)
}
.disabled(true)
```

Фрагмент находится в `body` владельца с `@State item`. Родительское отключение побеждает попытку дочерней кнопки включиться. Поэтому исправляй место внешнего `disabled`, а не добавляй `false` внутрь. Это поведение относится к `disabled`; не переноси такое правило автоматически на все модификаторы.

## Дополнительная доставка — тот же маршрут

Добавим в CartItem флаг `express = false`. Метод `express.toggle()` меняет Bool на противоположный. Выражение `express ? 100 : 0` выбирает 100 при true и 0 при false: это короткая запись условия.

```swift
struct CartItem {
    let id = 18
    var quantity = 1
    var express = false
    var total: Int { quantity * 300 + (express ? 100 : 0) }
}
```

Проверь книгу с количеством 1: обычная доставка даёт 300, экспресс — 400, отмена экспресса — снова 300. Дочерней кнопке можно передать `express` для подписи и действие `{ item.express.toggle() }` для запроса. Если выбираешь Toggle, передай вместо этого `@Binding var express: Bool` и используй `Toggle("Экспресс +100", isOn: $express)`; родитель отдаёт `$item.express`. Проверь: это два способа записать в один флаг, а не две копии состояния. В этой версии доплата равна 100 при express == true независимо от количества; правило оплаты пустой корзины здесь не проектируем.

## Растущая корзина не меняет направление

Если появятся несколько книг, владелец будет хранить коллекцию `CartItem`, а строки — получать данные и действия для нужного id. Не ищи книгу по названию: оно может повторяться. Не передавай позицию как постоянный идентификатор: порядок способен поменяться.

Попробуй описать обновление книги 18 словами: строка сообщает действие для id 18, владелец находит книгу и меняет количество, затем заново вычисляется общая сумма. Способ хранения становится сложнее, но данные по-прежнему идут вниз, а запрос изменения — к владельцу.
