## Смотрим, что пришло

Наш экран — заголовок профиля. Данные для него приходят из сети, и вот модель:

```swift
struct User {
    let id: Int
    let name: String?
}
```

Видишь вопросик после `String`? Это главное в задаче. Представь `String?` как **коробку**: в ней может лежать строка, а может быть пусто. Пустая коробка в Swift называется `nil`.

Бэкенд честно предупреждает: имя может не прийти. Попробуем просто положить его в заголовок.

## Пишем в лоб — и сразу ошибка

Стажёр обычно пишет так:

```swift
func title(for user: User) -> String {
    return user.name   // ❌ Value of optional type 'String?' must be unwrapped
}
```

Функция обещает отдать строку, а у нас в руках коробка. Если она пустая — что показать? Во многих языках такой код компилируется и падает уже у пользователя. Swift переносит этот вопрос на этап сборки: пока не ответишь, приложение не соберётся.

Запомни: Optional — это не ошибка, это **вопрос, на который ты обязан ответить**: «а что делаем, если пусто?»

Отвечать стажёру не хочется. Он ищет, как заставить компилятор замолчать.

## Попытка №2: восклицательный знак

И находит «волшебный» способ:

```swift
return user.name!   // компилируется...
```

`!` рвёт коробку, не заглядывая внутрь: «я клянусь, там не nil». На тестовом аккаунте с именем всё работает. А потом приходит пользователь без имени, коробка пустая — и приложение **крашится**.

Правило: данные из сети, из базы, из ввода пользователя — **никогда** через `!`. Там `nil` — нормальная ситуация, а не чудо.

Значит, коробку надо сначала открыть и посмотреть, что внутри.

## Делаем нормально: if let

Так и делает `if let`: есть имя — показываем его, нет — «Гость». Но сначала короткая пауза.

> Предскажи, не читая дальше: что напечатают две строки `print`?

```swift
let saved: String? = "Нора"
if let name = saved {
    print(name)
}
print(saved)
```

Ответ: `Нора`, потом `Optional("Нора")`. Внутри скобок `if let` достал строку и положил её в `name` — обычный `String`, без вопросика. Снаружи `saved` по-прежнему коробка `String?`: разворачивание не меняет исходное значение. Оно создаёт новое имя и только в скобках, где Swift доказал, что строка есть.

Отсюда рабочая функция:

```swift
func title(for user: User) -> String {
    if let name = user.name {
        return name        // здесь name — обычный String
    } else {
        return "Гость"
    }
}
```

Экран больше не падает. Но шесть строк ради одной мысли «имя или Гость» — многовато.

## Короче: одна строка через ??

Для случая «содержимое коробки или запасной вариант» есть оператор `??`:

```swift
func title(for user: User) -> String {
    user.name ?? "Гость"
}
```

Читается по-человечески: «имя, а если коробка пустая — Гость». Если нужно не само имя, а что-то о нём, коробку можно даже не вскрывать. `user.name?.count` заглядывает внутрь и отдаёт новую коробку `Int?`: число букв или `nil`.

На тестах всё зелёное. Пока QA не присылает скриншот с пустым заголовком.

## Подвох: имя пришло, но пустое

Смотрим ответ сервера для этого пользователя — там `"name": ""`.

Это не `nil`. Коробка **не пустая**: в ней лежит строка, просто в ней ноль букв. А `??` проверяет только, пуста ли коробка, поэтому такую строку пропускает.

> На собесе это любят: «Что вернёт `name ?? "Гость"`, если `name == ""`?» — Пустую строку. `??` проверяет «есть или нет», а не «нормальное ли значение».

Чиним: проверяем и коробку, и содержимое. Это можно сделать в `if let` через запятую, но удобнее `guard let`: он отсекает плохие случаи у входа, а дальше функция работает с чистым значением.

```swift
func title(for user: User) -> String {
    guard let name = user.name, !name.isEmpty else {
        return "Гость"
    }
    return name
}
```

`guard` читается так: «убедись, что имя есть и оно не пустое, **иначе** выходи с Гостем». Ветка `else` обязана выйти из функции, поэтому после `guard` `name` доступна до конца. Если запасного значения нет, функция может честно вернуть коробку сама: `-> String?` и `return nil` в `else`. Короткая запись `guard let name else` значит то же, что `guard let name = name else`.

Экран готов к трём случаям: имя, `nil` и `""`. Осталось забрать главное.

## Что забираем с собой

Три правила про коробку:

- Видишь `?` в типе — сразу спроси себя: «а что показываем, если коробка пустая?»
- Нужен просто запасной вариант — `??`. Нужно проверить условие и выйти — `guard let`. Нужна развилка внутри кода — `if let`.
- `!` — только если пустая коробка означает баг в твоём же коде. Данные извне — никогда.

## Проверь себя

Ответь вслух, не листая вверх:

- Почему `return user.name` не компилируется, если функция возвращает `String`?
- Что покажет экран через `user.name ?? "Гость"`, если сервер прислал `""`? Как это починить?
- Где можно пользоваться `name` после `if let`, а где — после `guard let`?

Если где-то запнулся — вернись к этому шагу. Потом в практику: все 7 ступеней про этот же экран профиля.

## Ответы к «Проверь себя»

- `user.name` имеет тип `String?`: это коробка, в которой строки может не быть, а функция обещает строку всегда. Swift не угадывает, что показать при `nil`, поэтому требует развернуть значение. На вопрос «а если пусто?» отвечаешь прямо в коде: `if let`, `guard let` или `??`.
- Экран покажет пустой заголовок: `""` — это не `nil`, коробка не пустая, в ней строка без букв. `??` срабатывает только на `nil`, поэтому пустую строку пропускает. Чинится через `guard let name = user.name, !name.isEmpty else { return "Гость" }`.
- После `if let` развёрнутый `name` живёт только внутри фигурных скобок. После `guard let` он доступен до конца функции, потому что ветка `else` обязана выйти. Поэтому `guard` удобен, когда плохие случаи надо отсечь в начале, а дальше спокойно работать со значением.

# ГЛУБЖЕ

## Задачу усложнили: имя внутри адреса

Через неделю бэкенд присылает вложенную модель: у пользователя может не быть адреса, а у адреса — города. Нужно показать город или «Не указан».

```swift
struct Address { let city: String? }
struct User { let name: String?; let address: Address? }

let city = user.address?.city ?? "Не указан"
```

`?.` ты уже видел на одном уровне — это optional chaining: «если адрес есть — возьми город, если нет — сразу nil, дальше не иди». Сколько бы вопросиков ни было в цепочке, на выходе один Optional, и его закрывает один `??`.

## Что такое Optional под капотом

Первый вопрос на собесе по теме. Ответ: это обычный enum из стандартной библиотеки.

```swift
enum Optional<Wrapped> {
    case none
    case some(Wrapped)
}
```

`String?` — короткая запись `Optional<String>`, а `nil` — это `.none`. Поэтому по Optional можно делать `switch` с `case .some(let name)`. Никакой магии — просто enum со связанным значением.

## Преобразовать, не разворачивая: map

Надо показать имя заглавными, если оно есть. Можно без `if let`:

```swift
let upper = user.name.map { $0.uppercased() }   // String?
```

`map` у Optional выполняет замыкание, только если значение есть, и заворачивает результат обратно в Optional. Если замыкание само возвращает Optional (например, `Int($0)`), бери `flatMap` — иначе получишь `Int??`, коробку в коробке.

## Где ещё прилетает Optional

Чтобы узнавать их на ревью:

- `dict["key"]` — ключа может не быть;
- `Int("abc")`, `URL(string:)` — преобразование может не получиться;
- `try?` превращает ошибку в `nil`;
- `array.first`, `firstIndex(of:)` — элемента может не быть;
- `weak var delegate` — объект может исчезнуть.

## Где ! всё-таки пишут

- `@IBOutlet weak var label: UILabel!` — implicitly unwrapped Optional: значение появится после загрузки экрана, но до первого использования, поэтому Swift разворачивает его сам.
- `UIImage(named: "logo")!` — картинка из твоих же ресурсов. Если её нет — это баг сборки, и лучше упасть сразу на тесте, чем молча показать пустоту.

Общий принцип: `!` — это ставка «nil здесь невозможен». Ставь её только на то, что контролируешь сам.
