## Что должен увидеть пользователь

Ты выбрал ролики 31 и 33 длиной 40 и 20 секунд. Предпросмотр каждого ограничен 30 секундами: экран должен показать 50 секунд, сколько бы раз ты ни открыл очередь. Сначала проверь контракт: исходные длительности остаются 40 и 20, меняется только результат расчёта.

```swift
struct Clip {
    let id: Int
    let seconds: Int
    let selected: Bool
}
let clips = [
    Clip(id: 31, seconds: 40, selected: true),
    Clip(id: 32, seconds: 90, selected: false),
    Clip(id: 33, seconds: 20, selected: true)
]
```

## Пишем в лоб

Попробуй дважды вызвать этот расчёт. Название `map` делает код похожим на конвейер, но замыкание записывает во внешнюю переменную. Получишь 60, затем 120: второй запуск наследует работу первого.

```swift
var accumulated = 0
func total(_ seconds: [Int]) -> Int {
    let _ = seconds.map { value in
        accumulated += value
        return value
    }
    return accumulated
}
print(total([40, 20]))
print(total([40, 20]))
```

Побочный эффект — наблюдаемое действие помимо возвращаемого значения: запись в общее состояние, файл или вывод на экран. Здесь это изменение `accumulated`.

## Чистота — свойство, а не название метода

Убери общий счётчик и спроси себя: всё ли нужное пришло в параметры? Чистая функция возвращает одинаковое значение на одинаковых входах и не производит побочных эффектов. Печать ниже стоит снаружи функции: сам расчёт ничего не печатает.

```swift
func total(_ seconds: [Int]) -> Int {
    seconds.reduce(0, +)
}
print(total([40, 20]))
print(total([40, 20]))
```

`reduce` хранит промежуточную сумму внутри расчёта. Локальная мутация сама по себе не запрещает чистоту, если её нельзя наблюдать снаружи и результат зависит только от входов.

## Одна функция — одно правило

Теперь назови отдельное правило предпросмотра: меньше нуля не берём, больше 30 обрезаем. Мы не меняем ролик; получаем число для показа. На 40 выйдет 30, на −5 — 0. Все числа урока небольшие, переполнение здесь не рассматриваем.

```swift
func capped(_ seconds: Int) -> Int {
    min(max(seconds, 0), 30)
}
print(capped(40))
print(capped(-5))
```

## Новое значение вместо изменения старого

Представь чистую функцию как калькулятор: он выдаёт результат, не переписывая твои исходные записи. Для выбора ролика тоже можно вернуть новый `Clip`. Проверь обе строки после вызова: исходный выбор останется `false`, новый станет `true`.

```swift
struct Clip {
    let id: Int
    let seconds: Int
    let selected: Bool
}
func selecting(_ clip: Clip) -> Clip {
    Clip(id: clip.id, seconds: clip.seconds, selected: true)
}
let original = Clip(id: 32, seconds: 90, selected: false)
let changed = selecting(original)
print(original.selected, changed.selected)
```

`let` закрепляет значение структуры. Это не обещание глубокой неизменяемости любого объекта; случай со ссылкой разберём дальше.

## Собираем конвейер по одному ролику

Для следующих фрагментов уже существуют `Clip`, `clips` и `capped`. Пройди данные руками: `filter` оставляет 31 и 33, `map` получает 30 и 20, `reduce` складывает их в 50. Эти API ты видел в `hof`; здесь нас интересует отсутствие скрытых записей между этапами.

```swift
let selected = clips.filter { $0.selected }
let durations = selected.map { capped($0.seconds) }
let result = durations.reduce(0, +)
print(result)
```

Можно оставить три именованных шага, если так легче отлаживать. Цепочка сама по себе не делает функцию чистой: замыкания тоже обязаны соблюдать контракт.

## Передаём правило как значение

Теперь экран хочет короткий режим с пределом 15 секунд. Вместо внешней изменяемой настройки вернём настроенную функцию. Функция высшего порядка принимает или возвращает другую функцию; `makeCap` возвращает правило, которое помнит неизменяемый `limit`.

```swift
func makeCap(limit: Int) -> (Int) -> Int {
    { seconds in min(max(seconds, 0), limit) }
}
let shortPreview = makeCap(limit: 15)
print([40, 20, -5].map(shortPreview))
```

При неотрицательном `limit` результат — от 0 до этого предела. В практике режимы используют 15 и 30; такой контракт не требует скрытого состояния.

## Итог: расчёт можно вызвать снова

Восстанови ход решения до чтения кода: отбор, ограничение, сумма. Ни ролики, ни общий счётчик не меняются. В этом самостоятельном примере оба вызова дают 50; пустой список даст 0.

```swift
struct Clip {
    let id: Int
    let seconds: Int
    let selected: Bool
}
func capped(_ seconds: Int) -> Int {
    min(max(seconds, 0), 30)
}
func previewSeconds(_ clips: [Clip]) -> Int {
    clips.filter { $0.selected }
        .map { capped($0.seconds) }
        .reduce(0, +)
}
let clips = [
    Clip(id: 31, seconds: 40, selected: true),
    Clip(id: 32, seconds: 90, selected: false),
    Clip(id: 33, seconds: 20, selected: true)
]
print(previewSeconds(clips))
print(previewSeconds(clips))
```

## Проверь себя

Закрой код и объясни следующий шаг для каждого вопроса. Если ответ сводится к названию метода, вернись к тому, что функция читает и меняет.

- Почему `map` с записью в `accumulated` не становится чистым?
- Как получить выбранную копию ролика, не меняя исходный?
- Что возвращает `makeCap` и почему два режима не мешают друг другу?

## Ответы к «Проверь себя»

- Чистота — свойство того, что функция читает и меняет, а не название метода внутри. Замыкание в `map` делает `accumulated += value`, то есть пишет во внешнее состояние: это побочный эффект. Поэтому второй вызов `total([40, 20])` наследует работу первого и даёт 120 вместо 60; чинится через `seconds.reduce(0, +)` без общего счётчика.
- Возвращаешь новый `Clip` вместо изменения старого: `func selecting(_ clip: Clip) -> Clip { Clip(id: clip.id, seconds: clip.seconds, selected: true) }`. Как калькулятор, функция выдаёт результат и не переписывает исходную запись, а `let` закрепляет значение структуры. После вызова `original.selected` остаётся `false`, `changed.selected` — `true`.
- `makeCap(limit:)` возвращает функцию `(Int) -> Int`, которая помнит неизменяемый `limit`: `{ seconds in min(max(seconds, 0), limit) }`. `makeCap(limit: 15)` и `makeCap(limit: 30)` — два отдельных правила, каждое со своим пределом. Общей изменяемой настройки нет, поэтому короткий режим не может сбить длинный.

# ГЛУБЖЕ

## let и ссылки внутри значений

Не делай вывод о чистоте по одному `let`. Если это ссылка на объект, его изменяемые свойства могут поменяться; структура со ссылкой внутри тоже может разделять состояние. Проверь такой код: обе переменные смотрят на один `Download`.

```swift
final class Download { var percent = 10 }
let original = Download()
let result = original
result.percent = 100
print(original.percent)
```

Для независимого результата верни структуру-снимок или создай отдельный объект с нужными данными; простое присваивание ссылки не копирует объект.

## Композиция маленьких функций

Если тебя спросят про композицию, покажи маршрут значения: сначала ограничение, затем подпись. Это соединение функций, когда результат первой становится входом второй. Проверь типы: число превращается в число, потом в строку.

```swift
func clamp(_ value: Int) -> Int { min(max(value, 0), 100) }
func label(_ value: Int) -> String { "\(value)%" }
func display(_ value: Int) -> String { label(clamp(value)) }
print(display(120))
```

Не нужно делать универсальную композицию для каждой пары строк. Отдельные функции полезны, когда правило повторяется или его нужно независимо проверять.

## Каррирование коротко

Попробуй зафиксировать первый аргумент сложения, а второй передать позже. Каррирование представляет функцию нескольких аргументов как последовательность функций с одним аргументом; ниже `adding(5)` возвращает такую вторую функцию.

```swift
func adding(_ delta: Int) -> (Int) -> Int {
    { value in value + delta }
}
let addFive = adding(5)
print(addFive(10))
```

Получится 15. Возвращаемое замыкание не обязано быть чистым: если оно читает изменяемое внешнее состояние или пишет в него, свойство теряется.

## Эффекты на границе приложения

Экран всё равно должен обновить подпись — это эффект. Раздели работу: чистый расчёт получает снимок входов, внешний код отображает результат. Время, случайное число или ответ хранилища передай параметром, если они влияют на ответ. Так ты сможешь повторить расчёт на одном и том же входе; это не обещает отсутствия ошибок в самих правилах.
