mission: ОПЕРАЦИЯ 02 · СТАТЬИ НА ВЕЧЕР
scenario: В ленте две разные статьи с одинаковым названием. Нужно сохранить порядок карточек, открыть выбранную статью по id и запомнить, какие публикации уже читали.
goals:
- выбирать `Array`, `Dictionary` и `Set` для порядка, поиска и отметки открытия
- связывать данные одной статьи через `id`, а не через название или позицию
- безопасно обрабатывать неизвестный `id` и повторное открытие

## Смотрим на карточки

Смотри на экран глазами читателя: сверху первая статья, под ней вторая. Обе называются «Выходные», но одна про прогулку, другая про поездку. Название не отличает их друг от друга — для этого нужен `id`, постоянный номер статьи.

```swift
struct Article {
    let id: Int
    let title: String
    let readingMinutes: Int
}
let articles = [
    Article(id: 41, title: "Выходные", readingMinutes: 5),
    Article(id: 73, title: "Выходные", readingMinutes: 12)
]
```

`Article` объединяет данные одной публикации. В примерах ниже продолжаем работать с этими двумя статьями; новый набор данных каждый раз не создаём.

## Пишем в лоб и отмечаем лишнюю статью

Тут легко написать «читал название» вместо «читал статью». Открыл первую карточку, запомнил её заголовок — и вторая тоже выглядит прочитанной.

```swift
var openedTitles: Set<String> = []
openedTitles.insert(articles[0].title)
print(openedTitles.contains(articles[1].title)) // true
```

`Set<String>` хранит уникальные строки. Он работает правильно: строки действительно одинаковые. Ошибка в нашем выборе данных. **Отмечать нужно `id` публикации**, иначе изменение заголовка тоже сломает историю чтения.

## Порядок карточек доверяем Array

Окей, сначала сохраним то, что уже работает: порядок ленты. `[Article]` — короткая запись массива статей. Массив, или `Array`, держит элементы в заданной последовательности.

```swift
var feed = articles
print(feed[0].id) // 41
feed.append(Article(id: 90, title: "Дорога", readingMinutes: 8))
print(feed.count) // 3
```

`var` позволяет менять массив, а `append` добавляет карточку в конец. `feed[0]` берёт первую позицию, но ноль здесь — **индекс, а не id статьи**. Пример не падает, потому что в `feed` точно есть элементы; для пустого массива безопаснее `feed.first`, который вернёт `Article?`.

## Находим статью через Dictionary

Теперь представь: нажал карточку, экран получил `id = 73`. Перебирать названия не нужно. Словарь, или `Dictionary`, связывает ключ с его значением: здесь номер статьи с самой статьёй.

```swift
var byID: [Int: Article] = [:]
for article in feed {
    byID[article.id] = article
}
if let selected = byID[73] {
    print(selected.readingMinutes) // 12
}
```

`[:]` создаёт пустой словарь. Тип `[Int: Article]` читается как «ключ Int, значение Article». Цикл `for` берёт статьи по одной; строка внутри записывает каждую под её номером. Результат `byID[73]` — `Article?`: такого номера может не быть. `if let` достаёт статью, когда она найдена.

## Запоминаем открытие через Set

Смотри, для истории чтения нам не нужны ни заголовок, ни минуты. Нужен ответ «этот номер уже встречался?». Поэтому храним множество номеров — `Set<Int>`.

```swift
var openedIDs: Set<Int> = []
print(openedIDs.insert(41).inserted) // true
print(openedIDs.insert(41).inserted) // false
print(openedIDs.contains(73)) // false
```

`inserted` сообщает, добавилось ли новое значение. Второе открытие первой статьи не создаёт вторую отметку и не затрагивает статью 73. Порядок карточек остаётся в массиве: у множества обещанного порядка обхода нет.

## Подвох: карточку успели удалить

Вот тут остановись: пользователь нажал старую ссылку на статью 999, которой уже нет. Если сначала отметить её открытой, история начнёт хранить события, которых не было.

```swift
let selectedID = 999
if let article = byID[selectedID] {
    openedIDs.insert(article.id)
    print(article.title)
} else {
    print("Статья недоступна")
}
```

Сначала находим статью, затем записываем открытие. В ветке `else` множество не меняется. Тебя спросят: «Почему нельзя взять `byID[selectedID]!`?» Потому что отсутствие статьи здесь ожидаемо, а `!` при `nil` завершит программу.

## Собираем рабочий маршрут

Окей, теперь прочитай код как маршрут одного нажатия: сохранили порядок, построили поиск, нашли статью, отметили её номер. Здесь заголовок нигде не заменяет идентификатор.

```swift
struct Article {
    let id: Int
    let title: String
    let readingMinutes: Int
}
let feed = [
    Article(id: 41, title: "Выходные", readingMinutes: 5),
    Article(id: 73, title: "Выходные", readingMinutes: 12)
]
var byID: [Int: Article] = [:]
for article in feed { byID[article.id] = article }
var openedIDs: Set<Int> = []
let selectedID = 73
if let article = byID[selectedID] {
    let firstOpen = openedIDs.insert(article.id).inserted
    print(article.title, article.readingMinutes, firstOpen)
} else {
    print("Статья недоступна")
}
```

- Если важен порядок карточек — сохраняй его в массиве.
- Если известен `id` и нужны данные статьи — ищи в словаре по этому `id`.
- Если нужна отметка «уже открывал» — храни `id` в множестве.

## Проверь себя

Закрой код и объясни путь нажатия своими словами. Если помнишь названия коллекций, но не можешь выбрать их для экрана, вернись к соответствующему шагу.

- Почему одинаковое название не делает статьи 41 и 73 одной публикацией?
- Что произойдёт с `openedIDs`, если пользователь выберет неизвестный номер?
- Почему второй `insert(41).inserted` вернёт `false`, а не добавит ещё один номер?

## Ответы к «Проверь себя»

- Публикацию определяет `id`, постоянный номер статьи, а название — просто текст, который может совпасть или поменяться. У статей 41 и 73 заголовки одинаковые, но номера разные, значит это разные публикации. Поэтому ищешь в `byID` и отмечаешь в `openedIDs` именно номер: отметка по названию сделала бы обе «Выходные» прочитанными.
- Ничего: `byID[selectedID]` вернёт `nil`, `if let` не сработает, и выполнится ветка `else` с «Статья недоступна». Мы сначала находим статью и только потом пишем `openedIDs.insert(article.id)`, поэтому несуществующее открытие в историю не попадает. `byID[selectedID]!` здесь нельзя: отсутствие статьи ожидаемо, а `!` при `nil` завершит программу.
- `Set` хранит только уникальные значения: после первого `insert(41)` номер 41 в множестве уже есть. Второй `insert` ничего не добавляет и сообщает об этом через `inserted == false`. Поэтому повторное открытие не создаёт вторую отметку, а по `inserted` можно отличить первое открытие от повторного.

# ГЛУБЖЕ

## Словарь нужно обновлять вместе с лентой

Смотри, `byID` — отдельный индекс, построенный из ленты. Если обновить статью в массиве, словарь сам не изменится: `Article` — структура, её значения копируются.

Для небольшого экрана можно заново построить индекс после обновления ленты. Для частых изменений держи обе коллекции внутри одного типа и меняй их одним методом. Если во входе два объекта с одним `id`, наш цикл оставит в словаре последний; прежде чем показывать их, договорись, считать ли второй объект обновлением или ошибкой данных.

## Почему поиск по номеру помогает

Теперь можно назвать стоимость. Доступ массива по известному индексу — O(1), поиск значения через `contains` — O(n). Удаление из середины сдвигает следующие элементы и тоже требует O(n) работы. Если для каждой из n статей снова искать номер в массиве, получится до O(n²) работы.

Поиск и вставка в `Dictionary` и `Set` для наших целочисленных ключей занимают в среднем O(1). Построение `byID` занимает в среднем O(n) и требует дополнительной памяти. `append` массива амортизированно O(1): редкое расширение хранилища распределяется по серии добавлений. Запомни: стоимость относится к операции, а не к названию коллекции вообще.

## Почему в Set лежит именно id

Тебя спросят: «Почему не `Set<Article>`?» Для множества его элемент должен быть `Hashable`: тип умеет вычислять хеш для поиска и сравнивать значения на равенство. `Int` уже это умеет.

Если автоматически сделать `Article: Hashable`, в равенство войдут все его хранимые поля. После изменения времени чтения объект будет отличаться от старого, хотя `id` тот же. В нашей задаче история отвечает именно на вопрос об идентичности публикации, поэтому `Set<Int>` выражает правило проще и точнее.
