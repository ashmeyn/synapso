## Что экрану разрешено делать

У загрузки 40 прогресс начинается с 0. Команда 25 принимается, 150 отвергается, 10 после 25 тоже отвергается. Экран показывает 25 и не может сам записать невозможное значение.

Модификатор доступа ограничивает, какой код может обратиться к объявлению. Сейчас проверяем модель прогресса, не настоящий сетевой запрос. Такой контракт полезен независимо от механизма загрузки.

## Пишем в лоб: правило легко обойти

Посмотри, как экран обходит любую проверку, если свойство открыто для записи.

```swift
final class Download {
    let id = 40
    var progress = 0
}
let download = Download()
download.progress = 150
print(download.progress)
```

Вывод — 150. Команда обновления не защитит правило, пока можно просто записать progress напрямую. Закрыть всё через private тоже неудобно: экрану нужно читать цифру. Разделим чтение и запись.

## private(set) оставляет чтение

`private(set)` уменьшает доступ к setter — операции записи. Getter, чтение, остаётся с обычным доступом свойства; без другого указания это internal, то есть внутри модуля.

```swift
final class Download {
    let id = 40
    private(set) var progress = 0
    func advance(to value: Int) {
        guard value >= progress && value <= 100 else { return }
        progress = value
    }
}
```

Снаружи `download.progress` читать можно, присваивать — нельзя. Внутри advance запись разрешена, но сначала проверяются границы. `&&` требует оба условия: новый прогресс не меньше текущего и не больше 100.

Модель похожа на панель прибора: значение видно, а менять его можно только через предусмотренное управление.

## Проверь границы по шагам

Download уже объявлен выше. Попробуй пройти три команды до запуска.

```swift
let download = Download()
download.advance(to: 25)
download.advance(to: 150)
download.advance(to: 10)
print(download.progress)
```

После первой записи progress = 25. Вторая не проходит верхнюю границу, третья — запрет уменьшения. Вывод — 25. Вызов 100 пройдёт, повтор 100 тоже допустим; отрицательное значение не пройдёт из начального 0.

Теперь проверь прямую запись:

```swift
download.progress = 150 // ❌ setter закрыт
```

Это продолжение тех же объявлений. Компилятор отклоняет присваивание: setter недоступен. Нужно вызвать advance и принять решение правила, а не расширять доступ ради обхода ошибки.

## private и fileprivate решают разные задачи

Модуль — самостоятельная единица компиляции, например приложение или библиотека, которую импортируют. Внутри него код может находиться в разных файлах.

`private` ограничивает доступ объявлением и его расширениями в том же файле. `fileprivate` разрешает доступ любому коду этого файла. `internal` — любого файла текущего модуля; обычно он действует по умолчанию.

Для progress выбираем private setter: соседнему служебному типу не нужна прямая запись. Если несколько типов одного файла сознательно делят деталь, может понадобиться fileprivate. Не расширяй доступ без конкретного пользователя этой детали.

## Когда модель станет API библиотеки

Переход через границу модуля требует `public`. Само public у класса не делает автоматически публичными его свойства и init. Вот отдельная версия Download для библиотеки.

```swift
public final class Download {
    public let id: Int
    public private(set) var progress = 0
    public init(id: Int) { self.id = id }
    public func advance(to value: Int) {
        guard value >= progress && value <= 100 else { return }
        progress = value
    }
}
```

Экран другого модуля сможет создать Download(id: 40), читать progress и вызывать advance. Setter остаётся закрытым. Это декларация библиотеки; использование начинается с её import.

`public` позволяет использовать тип снаружи. `open` дополнительно разрешает наследование и переопределение классов и их соответствующих членов за пределами модуля. Внутри собственного модуля public-класс без final наследовать можно; это важная граница, не абсолютный запрет.

## final и новая команда

`final` запрещает наследование от класса; для отдельного метода — переопределение. В нашей загрузке не предусмотрено изменение правила наследником. Если расширение через наследование действительно нужно, такой запрет пересматривают осознанно.

Теперь перенеси защиту на другие данные загрузки. `private(set) var isPaused = false` читается экраном, а pause и resume меняют его внутри модели. Для downloadedBytes аналогично: add принимает только положительный кусок не больше оставшегося места.

Проверь правило словами: при totalBytes = 50 и downloadedBytes = 20 кусок 40 не проходит, кусок 30 завершает загрузку. private(set) прячет запись, но само по себе не проверяет числа — это работа команды.

## Собираем защищённый прогресс

Вот самостоятельная модель с вызовами. Контракт показывает и разрешённое изменение, и отказ на неверный вход.

```swift
final class Download {
    let id = 40
    private(set) var progress = 0
    func advance(to value: Int) {
        guard value >= progress && value <= 100 else { return }
        progress = value
    }
}
let download = Download()
download.advance(to: 25)
download.advance(to: 150)
download.advance(to: 10)
print(download.progress)
```

- Только внутренней детали нужен private.
- Чтение снаружи, запись внутри — private(set) и проверенная команда.
- API другого модуля требует явного public; final задаёт запрет наследования, а не обещает ускорение каждого вызова.

# ГЛУБЖЕ

## Инициализатор не становится public сам

Создай public-класс с начальными значениями свойств и без явного init. Его автоматически полученный инициализатор не становится публичным для клиента другого модуля. У public-структуры синтезированный инициализатор по свойствам тоже не является автоматически public.

Поэтому библиотечный пример содержит public init(id:). Проверять это нужно отдельным модулем-клиентом: два типа в одном файле приложения не обнаружат ошибку внешнего доступа.

## package между internal и public

Начиная со Swift 5.9 есть также `package`: доступ между модулями одного Swift package. Он полезен, когда несколько целей пакета должны делить API, но внешним пользователям его показывать не нужно.

Не выбирай public лишь потому, что файлы находятся в разных целях. Сначала назови настоящую границу: один модуль, один пакет или внешние потребители. Для простой модели приложения internal обычно достаточно.

## Расширение в том же файле

Попробуй вынести вспомогательный метод в extension Download того же файла. Он всё ещё может обращаться к private-членам Download. Другой соседний тип без такой связи этого права не получает.

Если перенести расширение в другой файл, доступ к private потеряется. fileprivate тоже не поможет через границу файла; потребуется пересмотреть доступ или разместить связанную реализацию вместе. Выбирай размещение и контракт одновременно.

## final и оптимизация — не одно обещание

Компилятор может использовать запрет переопределения для оптимизации вызова. Но скорость зависит от места вызова, режима сборки и других решений оптимизатора. Не объясняй final как гарантированное ускорение любой программы.

Надёжное обещание здесь одно: наследник не сможет заменить класс или final-метод. Доступность остаётся отдельной осью: final не скрывает progress, а private(set) не запрещает наследование класса.
