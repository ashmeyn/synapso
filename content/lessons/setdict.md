## Смотрим на желаемый экран

На входе `Анна, Илья, Анна`. Сводка должна сказать «Анна — 2, Илья — 1», а список участников показать `Анна, Илья` именно в таком порядке.

```swift
let authors = ["Анна", "Илья", "Анна"]
```

Одним `Set` нельзя представить оба результата: он уберёт повтор, но не сохранит обещанный порядок экрана и не даст количество сообщений.

## Пишем в лоб

Стажёр для каждого имени заново проходит весь массив и считает совпадения. Результат верный, но при n сообщениях может получиться O(n²) сравнений.

```swift
for author in authors {
    let count = authors.filter { $0 == author }.count
    print(author, count)
}
```

Кроме того, «Анна — 2» печатается дважды. Нужны два ответа: счётчик и отметка «уже добавляли в список».

## Считаем частоты словарём

Ключ — имя, значение — число сообщений. `default: 0` даёт ноль при первом обращении и позволяет увеличить счётчик без принудительного разворачивания.

```swift
var counts: [String: Int] = [:]
for author in authors {
    counts[author, default: 0] += 1
}
```

`String` соответствует `Hashable`, поэтому подходит в ключи. Обход словаря не должен задавать порядок участников на экране.

## Отмечаем первый приход

Множество хранит уже встреченные имена. `inserted` равно `true` только на первом добавлении значения.

```swift
var seen: Set<String> = []
var orderedNames: [String] = []
for author in authors {
    if seen.insert(author).inserted { orderedNames.append(author) }
}
```

Порядок даёт массив `orderedNames`, а быстрый ответ «уже видел?» — `seen`. Оба обновляются в одном месте.

## Собираем в один проход

Теперь в одном цикле увеличиваем частоту и при первом появлении добавляем имя для UI.

```swift
for author in authors {
    counts[author, default: 0] += 1
    if seen.insert(author).inserted { orderedNames.append(author) }
}
```

Мы идём по сообщениям один раз. Вопрос о точной сложности хеш-коллекций и памяти разберём в «ГЛУБЖЕ».

## Подвох: имя написано по-разному

`"Анна"` и `"анна"` — разные ключи. Если продукт хочет считать их одним автором, договорись о нормализации на входе, например приведении к одному регистру. Но показывать пользователю нормализованный текст вместо исходного имени не обязательно.

```swift
let key = author.lowercased()
counts[key, default: 0] += 1
```

Если тебя спросят на собесе, уточни: считаем ли регистр значимым? Без ответа нельзя объявить один вариант «правильным».

## Что отдаём экрану

```swift
struct ChatSummary {
    let counts: [String: Int]
    let orderedNames: [String]
}
func summarize(_ authors: [String]) -> ChatSummary {
    var counts: [String: Int] = [:]
    var seen: Set<String> = []
    var names: [String] = []
    for author in authors {
        counts[author, default: 0] += 1
        if seen.insert(author).inserted { names.append(author) }
    }
    return ChatSummary(counts: counts, orderedNames: names)
}
```

- Подсчёт частот — словарь `значение → число`.
- Проверка первого появления — `Set`.
- Нужен порядок на экране — сохраняй его отдельным массивом.

## Проверь себя

- Почему `counts[author, default: 0] += 1` работает без `if let`?
- Какой результат даст `seen.insert("Анна").inserted` при втором сообщении?
- Где в решении хранится порядок, а где число сообщений?

# ГЛУБЖЕ

## Та же идея в two-sum

Словарь может помнить не частоту, а индекс уже встреченного числа. Для каждого числа ищем дополнение до нужной суммы; важно искать **до** вставки, чтобы не использовать один элемент дважды.

```swift
func twoSum(_ values: [Int], target: Int) -> (Int, Int)? {
    var seen: [Int: Int] = [:]
    for (index, value) in values.enumerated() {
        if let first = seen[target - value] { return (first, index) }
        seen[value] = index
    }
    return nil
}
```

## Среднее O(1), не магия

`Dictionary` и `Set` используют хеширование. Операции поиска и вставки обычно O(1) в среднем, но стоимость вычисления хеша, коллизии и память имеют цену. Нельзя обещать фиксированное время любого отдельного запроса.

## Данные экрана должны оставаться согласованными

Если удалить сообщение, придётся обновить и счётчик, и список видимых имён. Для сложных изменений инкапсулируй обе структуры в одном типе или пересчитывай сводку из исходных сообщений, чтобы не получить разные ответы на одном экране.
