scenario: Карточка файла должна показывать ожидание, загрузку, отправку с номером сообщения или ошибку с причиной. Сейчас состояния хранятся набором флагов и спорят друг с другом.
goals:
- заменить конфликтующие флаги одним `enum`
- привязать данные только к подходящему случаю через associated values
- разобрать все состояния через `switch` и выбрать одно через `if case let`

## Смотрим на баг

Стажёр хранит `isSent`, `isFailed` и `messageID` отдельно. Что означает файл, у которого первые два флага равны `true`? А ID сообщения есть ещё до загрузки? Модель допускает невозможные комбинации.

```swift
struct UploadFlags {
    var isSent: Bool
    var isFailed: Bool
    var messageID: Int?
}
```

## Пишем в лоб

Экран начинает проверять флаги в определённом порядке. Если ошибку поставили после отправки, одна ветка скрывает другую. Это баг модели, который `if` не исправит надёжно.

```swift
func label(_ upload: UploadFlags) -> String {
    if upload.isSent { return "Отправлено" }
    if upload.isFailed { return "Ошибка" }
    return "В работе"
}
```

Нам нужен **один текущий статус**, а не три независимых ответа.

## Называем возможные состояния

`enum` перечисляет конечный набор вариантов. В каждый момент значение равно ровно одному случаю.

```swift
enum UploadStatus {
    case waiting
    case uploading
    case sent
    case failed
}
```

Теперь «отправлен и завершился ошибкой одновременно» нельзя записать одним значением `UploadStatus`. Но ID сообщения и причина ошибки пока потерялись.

## Прикрепляем данные к случаю

Associated value — данные, которые существуют только вместе со своим случаем. Номер сообщения нужен отправленному файлу; причина ошибки — только неудачной загрузке.

```swift
enum UploadStatus {
    case waiting
    case uploading
    case sent(messageID: Int)
    case failed(reason: String)
}
```

Нельзя создать `.sent` без сообщения. Компилятор требует передать `messageID`, поэтому неверное состояние труднее собрать случайно.

## Показываем статус через switch

`switch` заставляет обработать каждый случай enum. Мы извлекаем связанные данные прямо в нужной ветке.

```swift
func label(for status: UploadStatus) -> String {
    switch status {
    case .waiting: "Ждёт"
    case .uploading: "Загружается"
    case .sent(let messageID): "Сообщение # \(messageID)"
    case .failed(let reason): "Ошибка: \(reason)"
    }
}
```

В Swift нет автоматического перехода из одной ветки `switch` в следующую. Добавишь новый case — компилятор покажет места, где его забыли. Для такого конечного списка это лучше, чем `default`, скрывающий новый статус.

## Один случай проверяем отдельно

Экрану нужен специальный звук только для отправленного файла. Необязательно писать второй большой `switch`: можно проверить один шаблон.

```swift
func sentMessageID(_ status: UploadStatus) -> Int? {
    if case let .sent(messageID) = status { return messageID }
    return nil
}
```

`if case let` извлекает `messageID` только при `.sent`. При остальных состояниях функция честно возвращает `nil`.

## Подвох: новое состояние

Появился статус `.retrying(attempt: Int)`. После добавления case `switch` в `label(for:)` перестанет компилироваться, пока не решишь, что показывать на экране. Это полезный сигнал: продукт изменился, и UI должен выразить новый вариант.

> Если тебя спросят на собесе, почему здесь нет `default`, ответь: он скрыл бы от нас необходимость обновить экран.

## Что отдаём на ревью

```swift
enum UploadStatus {
    case waiting, uploading
    case sent(messageID: Int)
    case failed(reason: String)
}
func label(for status: UploadStatus) -> String {
    switch status {
    case .waiting: "Ждёт"
    case .uploading: "Загружается"
    case .sent(let messageID): "Сообщение # \(messageID)"
    case .failed(let reason): "Ошибка: \(reason)"
    }
}
```

- Если варианты взаимоисключающие, начни с `enum`, а не с набора `Bool`.
- Данные случая храни рядом с ним через associated value.
- Для всех случаев используй `switch`; для одного — `if case let`.

# ГЛУБЖЕ

## Raw value — другая задача

Если сервер отправляет строковые коды, enum может иметь `rawValue`. Но один enum не может одновременно иметь raw values и associated values у своих случаев. Сетевой код лучше преобразовать в нашу модель на границе данных.

```swift
enum ServerStatus: String { case waiting, uploading, sent }
let raw = ServerStatus(rawValue: "sent") // ServerStatus?
```

## Рекурсивный статус

Когда enum должен содержать сам себя, нужен `indirect`. Например, история переходов состояния может быть рекурсивной. Для обычного `UploadStatus` он не нужен; не добавляй сложность без такой формы данных.

```swift
indirect enum History {
    case start(UploadStatus)
    case changed(from: History, to: UploadStatus)
}
```

## Что делает исчерпывающий switch

Компилятор знает все случаи enum в этом модуле и проверяет, что каждый обработан. Это проверка полноты, а не только удобный синтаксис. Если модель состояния меняется, места принятия решений становятся видимыми при сборке.
