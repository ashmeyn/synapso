## Что должен сделать экран

```swift
let builds = [3, 8, 15, 21, 34, 40, 55]
```

На вопрос «есть ли 34?» экран отвечает индексом `4`, на «есть ли 30?» — `nil`. А новая сборка 30 должна встать на индекс `4`, перед 34.

## Пишем в лоб: проход по всем

`builds.firstIndex(of: 34)` проверяет элементы по порядку — это O(n). Для семи номеров незаметно, для миллиона — до миллиона сравнений на каждый запрос. При этом мы не пользуемся главным: массив уже отсортирован.

## Угадай число за семь вопросов

Загадано число от 1 до 100. Ты спрашиваешь «больше 50?» — и половина вариантов отпадает. Ещё вопрос — отпадает половина оставшихся. Семи вопросов хватает на сотню, двадцати — на миллион. Бинарный поиск делает то же: смотрит в середину и выбрасывает ту половину, где ответа быть не может.

Работает это только потому, что массив отсортирован: если в середине число меньше искомого, всё левее него тоже меньше, и туда можно не смотреть. На неотсортированном массиве поиск не упадёт, а молча ответит неправильно.

## Границы low..<high

Держим полуинтервал `low..<high` — кусок массива, где ответ ещё может быть. В начале это весь массив: `low = 0`, `high = count`. Пока кусок не пуст (`low < high`), берём середину и сужаем.

```swift
func indexOf(_ target: Int, in sorted: [Int]) -> Int? {
    var low = 0
    var high = sorted.count
    while low < high {
        let mid = low + (high - low) / 2
        if sorted[mid] == target { return mid }
        if sorted[mid] < target {
            low = mid + 1
        } else {
            high = mid
        }
    }
    return nil
}
```

`low = mid + 1` — середина уже проверена и мала, начинаем правее. `high = mid` — середина велика, а `high` не входит в кусок, поэтому так она и исключается. Каждая ветка обязана сузить кусок, иначе цикл не закончится. Если в массиве есть повторы, `indexOf` вернёт индекс одного из равных, не обязательно первого.

Пройдём 34: кусок `0..<7`, середина 3 (`21` < 34) → `4..<7`; середина 5 (`40` > 34) → `4..<5`; середина 4 — `34`, ответ 4. Для пустого массива `0..<0` пуст сразу, ответ `nil`.

## Сколько это стоит

Каждый шаг делит кусок пополам, поэтому шагов около log₂ n: 7 элементов — 3 шага, миллион — 20. Это O(log n). Но сортировка стоит O(n log n), поэтому сортировать ради одного поиска невыгодно: бинарный поиск окупается, когда массив уже отсортирован или по нему ищут много раз.

## Место вставки

Иногда нужно не «есть ли», а «куда поставить». Тот же цикл, но без раннего выхода: ищем первый индекс, где элемент не меньше искомого.

```swift
func insertionIndex(of value: Int, in sorted: [Int]) -> Int {
    var low = 0
    var high = sorted.count
    while low < high {
        let mid = low + (high - low) / 2
        if sorted[mid] < value {
            low = mid + 1
        } else {
            high = mid
        }
    }
    return low
}
```

Цикл держит правило: левее `low` всё меньше искомого, начиная с `high` — не меньше. Для 30 он сойдётся на `low == 4`: левее всё меньше 30, начиная с 4 — не меньше. `builds.insert(30, at: 4)` сохранит порядок. Для числа больше всех ответ — `count`, вставка в конец.

## Собираем

- Массив отсортирован — иначе ответ неверный.
- Полуинтервал `low..<high`, цикл `while low < high`, середина `low + (high - low) / 2`.
- `low = mid + 1` или `high = mid`: каждый шаг сужает кусок; O(log n).
- Место вставки — тот же цикл без `return mid`, ответ — `low`.

## Проверь себя

- Почему бинарный поиск по массиву `[40, 3, 21, 8]` не находит 8, хотя он там есть?
- Чем опасно написать в `indexOf` `low = mid` вместо `low = mid + 1`?
- Почему `insertionIndex` для 30 в `[3, 8, 15, 21, 34, 40, 55]` возвращает 4 и что вернёт для 60?

## Ответы к «Проверь себя»

- Поиск выбрасывает половину, опираясь на порядок. Середина — `21`, она больше 8, и поиск отбрасывает правую часть, где 8 как раз лежит; дальше середина `3` меньше 8, кусок сужается до пустого. В неотсортированном массиве такие выводы неверны: поиск не упадёт, а молча вернёт `nil` — поэтому сначала массив сортируют.
- Если середина меньше искомого, а `low` станет просто `mid`, кусок может перестать сужаться. Когда в куске один элемент, `mid` равен `low`, и цикл крутится вечно. Это проявится, например, на поиске 25 в `[10, 20]`: середина 1, `20` < 25, `low` становится 1 и дальше остаётся 1. Поэтому проверенную середину исключают: `low = mid + 1`.
- Цикл держит правило: всё левее `low` меньше 30, всё начиная с `high` — не меньше. Когда `low` и `high` встречаются, это первый индекс с элементом не меньше 30 — индекс 4, где стоит 34. Для 60 все элементы меньше, `low` дойдёт до `count`, ответ 7 — вставка в конец.

# ГЛУБЖЕ

## Почему не (low + high) / 2

В Swift сложение с переполнением роняет программу. `low + high` для огромных индексов может выйти за предел `Int`, а `low + (high - low) / 2` — нет. На 64-битных устройствах до этого массивы не дорастают, но на собеседовании эту запись ждут и могут спросить, зачем она.

## Поиск по условию

Бинарный поиск ищет не только число. Если условие по массиву сначала ложно, а потом истинно, тем же циклом находится первый индекс, где оно истинно. Так устроены задача «первая плохая версия» и `git bisect`.

## Встроенного поиска нет

В стандартной библиотеке Swift бинарного поиска нет: `firstIndex(of:)` и `contains` идут по порядку. В пакете swift-algorithms есть `partitioningIndex(where:)` — это и есть место вставки по условию. На собеседовании обычно просят написать руками.

## Когда он не нужен

Если искать надо часто, а массив постоянно меняется, вставка в середину стоит O(n). Для частых проверок «есть ли» обычно лучше `Set` — O(1) в среднем. Бинарный поиск хорош, когда данные отсортированы и меняются редко или когда нужен порядок: «первый не меньше», «все в диапазоне».
