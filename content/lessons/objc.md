## Две точки связи с плеером

На экране есть статус «Готов» и громкость 20. Предстоит вызвать статус по селектору и получить изменение громкости на 35. Сначала отдели механизм вызова от результата: Objective-C runtime — система, которая во время исполнения находит классы и методы и отправляет сообщения объектам. UIKit и многие старые Foundation API используют этот механизм.

## Обычный Swift-метод не подходит

Попробуй взять селектор у `status` ниже. Компилятор откажет: метод не виден Objective-C. `#selector` проверяет ссылку на объявленный метод, а не превращает любой Swift-код в runtime-метод.

```swift
import Foundation
final class PlayerState: NSObject {
    func status() -> NSString { "Готов" }
}
let selector = #selector(PlayerState.status)
```

`NSObject` — базовый класс Objective-C объектов. Унаследовать его недостаточно, чтобы каждый твой метод автоматически стал доступен Objective-C.

## Открываем только нужный метод

Добавь `@objc` для экспорта метода и `dynamic`, чтобы доступ к нему из Swift использовал динамическую диспетчеризацию Objective-C. Вспомни `disp`: это message dispatch. Типы параметров и результата тоже должны быть совместимы с Objective-C; здесь строка `NSString` подходит.

```swift
import Foundation
final class PlayerState: NSObject {
    @objc dynamic var volume = 20
    @objc dynamic func status() -> NSString { "Готов" }
}
```

Громкость отмечена `@objc dynamic` отдельно: это понадобится для KVO. Не распространяй аннотации на всю модель без причины.

## Селектор — имя сообщения

Представь селектор как название кнопки домофона: оно указывает, кому какое действие запросить, но не хранит тело метода. Для этого примера `status` не принимает аргументов и возвращает объект. `perform` здесь допустим именно с такой сигнатурой; полученный `Unmanaged` раскрываем через `takeUnretainedValue`, не забирая чужое владение.

```swift
let player = PlayerState()
let selector = #selector(PlayerState.status)
let value = player.perform(selector)?.takeUnretainedValue()
print(value as? NSString ?? "Нет статуса")
```

Фрагмент продолжает объявленный `PlayerState`; вывод — «Готов». В обычном Swift-коде предпочти `player.status()`: у него проверяемые типы. Не используй `perform` для произвольных числовых аргументов или возвращаемых структур.

## Доступ к известному ключу

KVC, Key-Value Coding, читает и пишет свойства по ключу-строке. Проверь путь к громкости через `#keyPath`: компилятор свяжет имя с объявленным свойством. Фрагмент использует уже объявленный `PlayerState`.

```swift
let player = PlayerState()
let key = #keyPath(PlayerState.volume)
player.setValue(35, forKey: key)
print(player.value(forKey: key) as? Int ?? -1)
```

Получишь 35. `value(forKey:)` возвращает нетипизированное значение; мы проверяем приведение к `Int`. Для собственного кода прямое `player.volume` проще и безопаснее. Незнакомый ключ может вызвать Objective-C исключение, а не Swift Error.

## Подписка вместо постоянного чтения

KVO, Key-Value Observing, сообщает об изменении свойства. Для нашего Swift-свойства нужны `NSObject` и `@objc dynamic`. Удержи возвращаемый токен: он представляет наблюдение. Ниже используется уже объявленный `PlayerState`; `.new` просит новое значение, а `change.newValue` остаётся Optional.

```swift
let player = PlayerState()
let token = player.observe(\.volume, options: [.new]) { _, change in
    print(change.newValue ?? -1)
}
player.volume = 35
```

Получишь 35. Без `.initial` само подключение не запрашивает первоначальный callback. Типизированный key path `\.volume` и строка KVC — разные способы указать свойство.

## Подвох: отключили раньше изменения

Предскажи результат этого продолжения: нового вывода не будет. `invalidate` отключает наблюдение, поэтому следующая запись не приходит в callback. Храни токен там, где живёт подписка, и отключай по её контракту; освобождение токена также завершает наблюдение.

```swift
token.invalidate()
player.volume = 50
```

Если экран хранит токен, а callback сильно захватывает экран, получится цикл. В банке разорвёшь его через `[weak self]`.

## Итог: известный ключ и управляемая подписка

Собери всё на одном объекте. Сначала получим статус, затем изменим громкость через известный KVC-ключ: KVO увидит изменение. После отключения значение снова меняется, но подпись уже не получает событие. Попробуй назвать ожидаемые две строки до запуска.

```swift
import Foundation
final class PlayerState: NSObject {
    @objc dynamic var volume = 20
    @objc dynamic func status() -> NSString { "Готов" }
}
let player = PlayerState()
let selector = #selector(PlayerState.status)
let value = player.perform(selector)?.takeUnretainedValue()
print(value as? NSString ?? "Нет статуса")
let token = player.observe(\.volume, options: [.new]) { _, change in
    print(change.newValue ?? -1)
}
player.setValue(35, forKey: #keyPath(PlayerState.volume))
token.invalidate()
player.volume = 50
```

Вывод — «Готов», затем 35. Никакой сети или настоящего плеера здесь нет: это локальная модель связи с runtime.

## Проверь себя

Убери код и объясни выбор инструмента, а не только расшифровку названия.

- Почему наследования от NSObject недостаточно для #selector своего Swift-метода?
- Кто хранит токен и когда перестаёт получать изменения громкости?
- Почему неизвестный KVC-ключ нельзя считать обычной ошибкой для Swift catch?

## Ответы к «Проверь себя»

- `NSObject` делает класс Objective-C объектом, но не экспортирует каждый его метод в runtime. `#selector` проверяет ссылку на метод, видимый Objective-C, поэтому `status` нужно отметить `@objc` (здесь `@objc dynamic`) и дать совместимые типы, например `NSString`. Без этого компилятор откажет ещё до запуска.
- `observe(\.volume, options: [.new])` возвращает токен, который и есть наблюдение: его хранит тот, кто владеет подпиской, например экран с подписью громкости. Пока токен жив, запись `volume = 35` (даже через KVC) приходит в callback. После `token.invalidate()` или освобождения токена следующая запись `volume = 50` в callback уже не попадёт.
- KVC ищет свойство по строке во время исполнения, и незнакомый ключ может вызвать Objective-C исключение, а не Swift `Error`. Swift `catch` ловит только ошибки, брошенные через `throw`, а такое исключение проходит мимо него. Поэтому ключ берёшь через `#keyPath(PlayerState.volume)`, а в своём коде предпочитаешь прямое `player.volume`.

# ГЛУБЖЕ

## Что именно выбирает runtime

Если тебя спросят про сообщение, отдели селектор от реализации: runtime ищет реализацию по классу получателя и имени сообщения. `@objc` делает объявление доступным Objective-C; `dynamic` требует динамического доступа из Swift. Не обещай одинаковый механизм для каждого метода наследника `NSObject`. Для произвольного C-вызова `objc_msgSend` нужно точно знать ABI; здесь ручной вызов не нужен.

## Проверка возможности не проверяет сигнатуру

Перед необязательным runtime-вызовом можешь спросить `responds(to:)`. Это проверка наличия метода, а не проверка типов аргументов и результата. Для `perform` всё равно нужна совместимая сигнатура; выбирай собственный объявленный метод с объектным результатом. Если объект реализует typed-протокол, предпочти вызов через него.

## KVO и время жизни экрана

Попробуй нарисовать три ссылки: экран → токен → callback → экран. При сильном захвате это цикл. `[weak self]` разрывает последнее ребро; хранение токена и явный `invalidate` решают другую задачу — длительность подписки. Изменение в примерах синхронное; не считай KVO обещанием доставки на главную очередь. UI обновляй по контракту главного потока.

## Swizzling: только разбор опасного механизма

Остановись перед этим кодом: это демонстрация, не рекомендация для приложения. Method swizzling меняет реализации двух методов класса; `method_exchangeImplementations` ниже работает только с двумя собственными методами `DemoRuntime` одинаковой сигнатуры. Изменение касается класса и всех его экземпляров, а не одного объекта.

```swift
import Foundation
import ObjectiveC
final class DemoRuntime: NSObject {
    @objc dynamic func original() -> NSString { "A" }
    @objc dynamic func replacement() -> NSString { "B" }
}
let a = #selector(DemoRuntime.original)
let b = #selector(DemoRuntime.replacement)
if let first = class_getInstanceMethod(DemoRuntime.self, a),
   let second = class_getInstanceMethod(DemoRuntime.self, b) {
    method_exchangeImplementations(first, second)
}
```

После обмена `original` использовал бы тело `replacement`, и наоборот. Повторный обмен вернул бы прежнее соответствие. Наследуемые методы, конкурирующие изменения и чужие swizzle могут нарушить поведение; здесь их не используем. Не переноси приём на системные классы и приватный API: предпочти обёртку, протокол или явную зависимость.
