## Сначала договорись о символе

Уточни: сравниваем с учётом регистра? Пробелы значимы? Swift Character объединяет расширенный графемный кластер: семейное emoji может быть одним Character и многими кодовыми единицами. В основе сравниваем последовательность Character буквально: «топот» true, «Топот» false, пустая строка true. Два указателя — как два пальца на краях строки: после проверки сдвигаем оба внутрь.

```swift
let text = "А👨‍👩‍👧‍👦Б"
print(text.count)
print(Array(text))
```

## Пишем в лоб: Int не индекс String

Не пиши text[0]: String не даёт доступ по целому индексу. Его позиции — String.Index. Повторный index(startIndex, offsetBy:) в цикле может заново проходить строку, поэтому не выдавай такой код за гарантированный линейный проход. Для задачи с памятью O(n) один раз создадим `Array<Character>` и дальше индексируем массив.

```swift
let text = "А👨‍👩‍👧‍👦Б"
// ❌ Намеренная ошибка компиляции, не рабочий пример.
// let first = text[0]
let first = Array(text).first
print(first == "А")
```

Раскомментируешь строку — компилятор откажет: у String нет индекса по Int. Не превращай строку в UTF-8 байты, если условие спрашивает пользовательские Character: это уже другой уровень текста.

## Встречное движение: инвариант

Инвариант — правило, которое сохраняется между шагами. Уже проверенные внешние пары равны; остаётся участок left...right. На «топот» сначала т/т, затем о/о; центральный п отдельно сравнивать не надо. Если пара не равна, остановись: дальнейшие сдвиги её не исправят.

```swift
let characters = Array("топот")
var left = 0, right = characters.count - 1
while left < right {
    guard characters[left] == characters[right] else { break }
    left += 1
    right -= 1
}
print(left == right)
```

Для пустого массива right=-1, но условие 0 < -1 ложно, обращения нет. Это безопасная отрицательная граница, а не отрицательный индекс при чтении.

## Пара чисел: нужно доказать движение

Условия другой задачи: массив отсортирован неубывающе, числа и target от -1000 до 1000. При сумме меньше target сдвинь left: с текущим left любое уменьшение right сделает сумму не больше. При сумме больше target уменьши right. Без сортировки доказательство ломается; не сортируй молча, если ответ должен содержать исходные индексы.

```swift
func pairIndices(_ values: [Int], target: Int) -> (Int, Int)? {
    var left = 0
    var right = values.count - 1
    while left < right {
        let sum = values[left] + values[right]
        if sum == target { return (left, right) }
        if sum < target { left += 1 } else { right -= 1 }
    }
    return nil
}
```

На [1,3,4,8], target=7: 1+8=9 → right, 1+4=5 → left, 3+4=7 → (1,2). `left<right` запрещает использовать один элемент дважды.

## Чтение и запись: другое расположение

Два указателя не всегда идут навстречу. В отсортированном массиве read читает исходный проход, write обозначает длину уникального префикса. Сравни с values[write-1]: это последний принятый элемент. При новом значении записывай и увеличивай write; хвост после возвращённой длины не часть ответа.

```swift
func compactUnique(_ values: inout [Int]) -> Int {
    guard !values.isEmpty else { return 0 }
    var write = 1
    for read in 1..<values.count {
        if values[read] != values[write - 1] {
            values[write] = values[read]
            write += 1
        }
    }
    return write
}
```

На [1,1,2,2,3] принятый префикс [1,2,3], длина 3. Не удаляем элементы во время прохода: индексы чтения сохраняют смысл.

## Строковые границы и цена

Проверка пустого, одного Character и emoji идёт тем же циклом. В оценке по числу Character при ограниченной стоимости их сравнения проход линейный; Array(text) требует дополнительную память. Unicode-разбиение, сравнение и хеширование переменного размера тоже стоят работы: не обещай O(1) для любого огромного Character. Для прохода без массива можно двигать String.Index с index(after:) и index(before:), но тогда следи за границами и не считай его Int.

## Новое условие — новое сравнение

Если просят игнорировать только обычный пробел U+0020, убери Character " " до прохода, а регистр, табы и пунктуацию оставь. Если просят «буквы без регистра», отдельно согласуй нормализацию: lowercased() и фильтрация меняют задачу. Для разворота переставляй Character целиком через swapAt, не части байтов; `Array<Character>` превращается обратно в String.

## Итог: восстанови функцию

Полный пример ниже не требует данных из предыдущих блоков. Назови до написания, когда можно читать left/right и почему каждый сдвиг допустим. Для чисел важна сортировка; для write-префикса — что уже принято.

```swift
func isPalindrome(_ text: String) -> Bool {
    let characters = Array(text)
    var left = 0
    var right = characters.count - 1
    while left < right {
        guard characters[left] == characters[right] else { return false }
        left += 1
        right -= 1
    }
    return true
}
```

Проверь "", один символ, несовпадение снаружи и семейное emoji. Для reverseCharacters используй тот же `left<right`, но заменяй сравнение на swapAt; для compactUnique нужен один проход read и отдельный write.

## Проверь себя

Не называй шаблон без доказательства.

- Чем Character отличается от байта и почему text[0] неверен?
- Почему при малой сумме двигается left и что изменится без сортировки?
- Что возвращает write и почему оставшийся хвост не является результатом?

## Ответы к «Проверь себя»

- `Character` в Swift — расширенный графемный кластер: семейное emoji — один Character, но много кодовых единиц и байтов. Поэтому String не даёт индекса по Int — его позиции имеют тип `String.Index`, и `text[0]` просто не компилируется. Для двух указателей один раз делаешь `Array(text)` (память O(n)) и индексируешь массив, а не гоняешь `index(startIndex, offsetBy:)` в цикле.
- Массив отсортирован неубывающе, значит при текущем left любое уменьшение right сделает сумму только не больше — меньшую сумму это не исправит, поэтому `sum < target` двигает `left += 1`, а большая сумма — `right -= 1`. Каждый сдвиг отбрасывает элемент, который заведомо не войдёт в ответ, а `left < right` не даёт взять один элемент дважды. Без сортировки это доказательство рушится, а молча сортировать нельзя, если ответ должен содержать исходные индексы.
- `write` — длина принятого уникального префикса: на `[1,1,2,2,3]` это 3, а префикс `[1,2,3]`. Новое значение сравниваешь с `values[write - 1]` — последним принятым, и только тогда пишешь `values[write] = values[read]` и увеличиваешь write. Элементы при проходе не удаляются, поэтому хвост после write — старые значения, которые read уже прочитал, а не часть ответа.

# ГЛУБЖЕ

## Индексы вместо массива

Для огромного текста память на Array может быть неприемлема. Тогда храни String.Index, сравнивай текущие Character и двигайся от концов осторожно: endIndex указывает за последний Character. Начни с пустой строки, прежде чем делать index(before:endIndex). Выбор памяти и читаемости проговаривай, а не называй массив единственным Swift-решением.

## Каноническое равенство Unicode

Swift сравнивает Character с учётом канонической эквивалентности. Предсоставленное é и e с комбинируемым акцентом могут сравниваться равными, хотя UTF-8 различается. Это не сравнение исходных байтов; если задача про идентичность файла, выбирай Data, не строковый palindrome.

## Окно — родственник, не тот же инвариант

Для самой длинной подстроки без повторов обе границы двигаются вперёд: правой расширяешь окно, левой убираешь конфликт. Здесь нужно хранить повторения или последние позиции, поэтому одного сравнения краёв недостаточно. Не применяй встречный шаблон только потому, что увидел слово «строка».

## Числа вне учебной границы

Для произвольного Int операция a+b может переполниться. Если такие входы разрешены, выбери контракт с addingReportingOverflow либо другой безопасной арифметикой. В основе числа малы намеренно; &+ нельзя подставить как «исправление», потому что переполненная сумма меняет смысл сравнения с target.
