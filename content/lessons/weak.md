## Кто нужен после закрытия

Назови владельца проигрывателя: пока открыт диктант, это экран 18. Проигрыватель должен сообщать экрану об окончании, но эта обратная связь не должна продлевать жизнь экрана.

Мы специально сохраним проигрыватель снаружи. После закрытия экрана повторный finish должен быть безопасным и не отправлять сообщение исчезнувшему получателю.

## Пишем в лоб: обратная ссылка сильная

Проследи две стрелки: экран → проигрыватель, проигрыватель → делегат-экран. Если delegate — обычное var, получается retain cycle: цикл сильного владения. ARC не разрывает его за нас.

```swift
protocol DictationDelegate: AnyObject {
    func didFinish()
}
final class DictationPlayer {
    var delegate: (any DictationDelegate)?
    func finish() { delegate?.didFinish() }
}
```

После screen = nil экран остаётся у delegate. Его deinit не появляется, а delegate == nil даёт false. В ступени 1 эта ошибка воспроизводится, затем связь очищается для завершения примера.

## Протокол разрешает слабую связь

Добавь AnyObject к контракту: делегатами могут быть только экземпляры классов. Без этого ограничения протокол мог бы описывать структуру, а weak не подходит для значения.

```swift
final class DictationPlayer {
    weak var delegate: (any DictationDelegate)?
    func finish() { delegate?.didFinish() }
}
```

weak не удерживает объект. Поэтому свойство — var Optional: при освобождении получателя Swift автоматически устанавливает nil. Вызов delegate?.didFinish() просто пропускается, если получателя уже нет; any обозначает значение с этим протокольным контрактом.

## Экран остаётся обычным владельцем

Теперь допиши сторону экрана. Слабым делается обратный путь, а не обе связи: проигрыватель нужен экрану и должен жить вместе с его работой.

```swift
final class DictationScreen: DictationDelegate {
    let id = 18
    let player = DictationPlayer()
    init() { player.delegate = self }
    func didFinish() { print("Готово \(id)") }
    deinit { print("Экран освобождён") }
}
```

init связывает проигрыватель с текущим экраном. Методу didFinish доступен id экрана; deinit даст наблюдаемую отметку, когда сильных владельцев экрана больше нет.

## Отложенное действие переживает экран

Проверь другое время жизни: replay сохранён снаружи и может быть вызван после закрытия. Здесь нельзя обещать, что self всё ещё существует.

```swift
func makeReplay() -> () -> Void {
    return { [weak self] in
        guard let self else { print("Экран закрыт"); return }
        print("Повтор \(self.id)")
    }
}
```

Это метод DictationScreen с id 18. guard let временно получает сильную ссылку для выполнения тела, если объект ещё жив. Если нет — печатается «Экран закрыт». Само сохранённое действие продолжает существовать и безопасно вызывается.

## Когда подходит unowned

Не выбирай unowned ради короткой записи. Такая ссылка тоже не владеет объектом, но при обычном доступе к уже освобождённой цели программа аварийно завершится. Нужна доказанная гарантия: цель живёт при каждом обращении.

```swift
final class DictationHint {
    unowned let owner: DictationSession
    init(owner: DictationSession) { self.owner = owner }
    func show() { print(owner.id) }
}
```

В этой модели подсказка доступна только через живую сессию: сессия хранит её в private-свойстве и не отдаёт наружу. Аналогия: weak — обратный адрес, который могут стереть; unowned — адрес с обязательством владельца быть доступным при обращении.

## Проверим гарантию владельца

Посмотри, кто может получить DictationHint из предыдущего раздела. Никто снаружи: private lazy var создаёт подсказку при первом showHint, а метод использует её внутри живой сессии.

```swift
final class DictationSession {
    let id = 18
    private lazy var hint = DictationHint(owner: self)
    func showHint() { hint.show() }
}
```

session.showHint() печатает 18. Если изменить интерфейс и вернуть hint наружу, старое обещание уже не доказано. Для отложенного replay из прошлого раздела выбираем weak, потому что действие может пережить экран.

## Итог: обратная связь не удерживает

Собери делегата и пройди три события: finish при живом экране, очистка screen, проверка делегата. В этом примере есть внешний владелец проигрывателя, но нет внешнего сильного владельца экрана.

```swift
protocol DictationDelegate: AnyObject {
    func didFinish()
}
final class DictationPlayer {
    weak var delegate: (any DictationDelegate)?
    func finish() { delegate?.didFinish() }
}
final class DictationScreen: DictationDelegate {
    let id = 18
    let player = DictationPlayer()
    init() { player.delegate = self }
    func didFinish() { print("Готово \(id)") }
    deinit { print("Экран освобождён") }
}
var screen: DictationScreen? = DictationScreen()
let player = screen!.player
player.finish()
screen = nil
print(player.delegate == nil)
```

Вывод: «Готово 18», «Экран освобождён», true. Повторный player.finish() после очистки ничего не печатает. weak выбран по поведению после закрытия, а не как украшение любого свойства.

## Проверь себя

Закрой ключ и объясни стрелки владения.

- Почему delegate нужен AnyObject?
- Что меняется в сохранённом replay после освобождения экрана?
- Какая часть интерфейса сессии позволяет использовать unowned у подсказки?

## Ответы к «Проверь себя»

- `weak` можно поставить только на ссылку на экземпляр класса: она не удерживает объект и при его освобождении сама становится `nil`. Без `AnyObject` протокол мог бы принять и структуру, а для значения `weak` не подходит, поэтому компилятор не разрешит `weak var delegate`. `AnyObject` ограничивает делегатов классами, и обратная связь проигрыватель → экран перестаёт быть сильной, цикл разорван.
- Замыкание держит экран через `[weak self]`, поэтому само действие живёт дальше, а `self` внутри становится `nil`. `guard let self else { print("Экран закрыт"); return }` отсекает этот случай: печатается «Экран закрыт», а не «Повтор 18». Сохранённый replay безопасно вызывать после закрытия, и он не продлевает жизнь экрана.
- `unowned` допустим, потому что подсказка лежит в `private lazy var hint` и используется только внутри `showHint()` живой сессии — наружу её не отдают. Значит, при каждом обращении `owner` гарантированно жив, а `unowned` к освобождённой цели привёл бы к аварии. Если сделать `hint` доступной снаружи, гарантия больше не доказана, и выбираешь `weak`.

# ГЛУБЖЕ

## unowned тоже бывает Optional

Уточни ответ на собесе: unowned не обязательно не-Optional. Возможна unowned var ссылка типа T?, но она не становится nil автоматически при освобождении цели. Если программа допустила исчезновение цели, корректность такой связи нужно поддерживать самой.

weak подходит, когда исчезновение получателя ожидаемо. Не подменяй этот выбор правилом «weak медленнее, значит всегда unowned»: цена не заменяет гарантию жизни.

## Сильный захват не всегда утечка

Нарисуй полный путь: один внешний владелец может хранить действие с сильным захватом экрана, пока идёт нужная операция. Сам по себе такой захват ещё не доказывает цикл. Если действию нужен только снимок id, capture list [id = self.id] сохраняет значение Int без захвата всего self.

Если экран хранит это же действие или объект, который его хранит, появляется обратная цепочка. Если действие завершается и удаляется, удержание может быть временным. Для диктанта мы явно разрешили вызов после закрытия, поэтому weak отражает контракт.

## Слабый делегат без владельца

Проверь, кто удерживает делегата снаружи. Если создать его прямо в присваивании слабому свойству и нигде больше не сохранить, получатель исчезнет до события. Слабая связь не делает управление временем жизни за тебя.

В нашей миссии экран удерживается screen, пока открыт. В отдельном сервисе нужен другой сильный владелец получателя. Добавление weak может убрать цикл и одновременно обнаружить отсутствие такого владельца.

## Отмена и weak решают разные задачи

Представь, что проигрыватель продолжает дорого считать после закрытия экрана. weak убирает удержание получателя, но не останавливает работу источника. Нужен отдельный stop или отмена операции по её контракту.

Не прячь единственный способ остановки за deinit объекта, который ещё может удерживаться. Сначала заверши работу явно, затем проверь граф владения.
