## Две точки, одно название

Давай сначала различим место и подпись: точки 51 и 52 обе называются «У входа», но стоят в разных координатах. Нажатие на 52 должно выбрать именно 52, а не первую строку с таким названием.

MapKit даёт карту и географические объекты. Координаты — широта и долгота в градусах; это положение на Земле, не пиксели экрана. Здесь данные локальные, геолокация пользователя и поиск в интернете не нужны.

## Пишем в лоб: название стало идентификатором

Посмотри на результат выбора. Модель Fountain и points зададим в следующем разделе; у двух записей одна подпись.

```swift
let selectedID = 52
let chosen = points.first { $0.title == "У входа" }
print(chosen?.id ?? 0)
```

Печатается 51. Код не использовал selectedID и выбрал первую подходящую подпись. Исправлять координаты не нужно: потерялось правило идентичности.

## Опишем точки один раз

Теперь введи модель. Identifiable означает, что у каждого элемента есть id; он нужен ForEach, чтобы различать записи при обновлении.

```swift
import MapKit
struct Fountain: Identifiable {
    let id: Int
    let title: String
    let coordinate: CLLocationCoordinate2D
}
```

Один id — один фонтанчик. Название может повторяться, координаты могут изменяться; id при этом остаётся прежним. Для проверки используем следующие данные.

```swift
let points = [
    Fountain(id: 51, title: "У входа",
        coordinate: .init(latitude: 55.75, longitude: 37.61)),
    Fountain(id: 52, title: "У входа",
        coordinate: .init(latitude: 55.76, longitude: 37.62))
]
```

## Покажем Marker

В body экрана уже доступны points. Давай сначала разместим обычные метки, без собственной кнопки на каждом месте.

```swift
Map {
    ForEach(points) { point in
        Marker(point.title, coordinate: point.coordinate)
    }
}
```

Marker — стандартная метка MapKit. Map строит содержимое карты из этих элементов; массив задаёт данные, а не порядок по географическому расстоянию. Пока мы лишь показываем места.

## Выбор хранится отдельно

Добавь в экран `@State private var selectedID: Int?`. Optional позволяет сказать «ничего не выбрано». Передадим Binding этому состоянию, как в state.

```swift
Map(selection: $selectedID) {
    ForEach(points) { point in
        Marker(point.title, coordinate: point.coordinate)
            .tag(point.id)
    }
}
```

При выборе метки Map связывает её tag с selectedID. Типы совпадают: id — Int, состояние — Int?. Даже когда ForEach может дать tag автоматически, явная запись здесь показывает контракт. id — номер на ключе, title — наклейка на двери; одинаковые наклейки не делают двери одной.

## Восстановим подпись из данных

Не дублируй название в отдельном состоянии. Найди модель по id; для локальной проверки это обычная функция, не работа карты.

```swift
func caption(for id: Int?, points: [Fountain]) -> String {
    guard let id, let point = points.first(where: { $0.id == id }) else {
        return "Выбери точку"
    }
    return point.title
}
```

При 52 вернётся «У входа», при 99 или nil — «Выбери точку». В UI тот же поиск можно выразить вычисляемым chosenPoint. Если точка исчезла из данных, Optional не даёт обращаться к несуществующей записи.

## Фильтр меняет доступный выбор

Пройди 52 → фильтр, оставляющий только 51. В новых данных выбранного id больше нет. Не делай вид, что 52 всё ещё доступен: проверь contains(where:) и присвой selectedID = nil.

Это правило проверим письменно в ступени 6. Оно относится к данным и работает без касания настоящей карты. Для необычной метки существует Annotation: она принимает координату и собственное SwiftUI-содержимое вместо стандартного Marker.

## Собираем карту выбора

Окей, модель и экран помещаются в самостоятельный пример. Передай ему points из локального источника.

```swift
import SwiftUI
import MapKit
struct Fountain: Identifiable {
    let id: Int
    let title: String
    let coordinate: CLLocationCoordinate2D
}
struct RefillMap: View {
    let points: [Fountain]
    @State private var selectedID: Int?
    private var chosenPoint: Fountain? {
        points.first { $0.id == selectedID }
    }
    var body: some View {
        VStack {
            Map(selection: $selectedID) {
                ForEach(points) { point in
                    Marker(point.title, coordinate: point.coordinate)
                        .tag(point.id)
                }
            }
            Text(chosenPoint?.title ?? "Выбери точку")
        }
    }
}
```

- Метки различай по id, не по подписи и не по индексу массива.
- Binding связывает выбор Map со состоянием экрана.
- Отсутствующую модель показывай как отсутствие; при фильтре очисти недоступный выбор.

## Проверь себя

Закрой код и пройди одно нажатие от метки к тексту.

- Зачем tag, если у двух точек одинаковое название?
- Почему выбранное название получаем из points, а не сохраняем второй строкой?
- Что должно случиться с selectedID после скрытия выбранной точки?

## Ответы к «Проверь себя»

- `Map(selection: $selectedID)` записывает в состояние именно tag выбранной метки, поэтому каждому `Marker` ставишь `.tag(point.id)` с тем же типом `Int`, что и у `selectedID: Int?`. Название у точек 51 и 52 одинаковое, и поиск по `title` всегда находит первую, то есть 51. id — номер на ключе, title — наклейка на двери: одинаковые наклейки не делают двери одной.
- Название — часть модели, а выбор хранит только id; вторая строка в `@State` стала бы копией, которая расходится с данными при правке или исчезновении точки. Поэтому подпись вычисляешь: `points.first { $0.id == selectedID }` и `chosenPoint?.title ?? "Выбери точку"`. Если точки с этим id уже нет, Optional честно даёт отсутствие, а не старую подпись.
- После фильтра выбранного id может не оказаться среди видимых точек, и делать вид, что 52 всё ещё доступна, нельзя. Проверяешь `points.contains(where: { $0.id == selectedID })` и при отсутствии присваиваешь `selectedID = nil`. Тогда текст под картой вернётся к «Выбери точку», а не будет ссылаться на скрытую метку.

# ГЛУБЖЕ

## Источник локальных данных

Не заставляй карту самой искать тестовые точки. Передай данные из источника с явным контрактом; для этого нужен знакомый протокол.

```swift
protocol FountainSource {
    func fetchPoints() -> [Fountain]
}
struct LocalFountainSource: FountainSource {
    let rows: [Fountain]
    func fetchPoints() -> [Fountain] { rows }
}
```

RefillMap получает массив. Такой источник не запрашивает местоположение и не делает сеть; настоящая загрузка — отдельная реализация.

## Камера не является выбором

Смотри, на что меняешь состояние: MapCameraPosition управляет видом карты, selectedID — выбранным объектом. Камеру можно связать через Map(position: $camera, selection: $selectedID).

Для перехода к области присвой camera = .region(region), где MKCoordinateRegion содержит центр и span — ширину охвата в градусах. Кнопка движения камеры не обязана выбирать метку. Этот отдельный навык проверяется в банке.

## Своё содержимое Annotation

Если фонтанчик нужно показать с количеством выходов воды, дай Annotation координату и простой Text или Image. Это собственный вид метки, а не новый способ хранить модель.

Назови назначение символа и добавь accessibilityLabel, если картинка сама не объясняет действие. Не превращай каждую метку в отдельную модальную форму; открытие подробностей можно поручить кнопке выбранного места.

## Локальные точки и настоящая карта

Не путай отсутствие своей сети с гарантией полностью автономной подложки. Данные фонтанчиков локальны, но MapKit может получать картографические материалы через системные сервисы.

Для этой партии карту не монтируем и геолокацию не запускаем. Проверяем компиляцию UI и алгоритм выбора отдельно. Доступ к позиции пользователя, разрешения и маршруты потребуют собственной проверки на устройстве.
