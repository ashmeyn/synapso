## Действие выполняется позже

Есть черновик 11 с текстом «План». Мы подготовим действие сохранения, поменяем текст на «Новый план», затем вызовем действие. Оно должно увидеть актуальный текст.

Замыкание — передаваемый кусок кода вместе с доступом к значениям из места создания. Его можно вызвать сразу или сохранить на потом. Сегодня проверим оба свойства без таймера и файлов: «сохранение» в учебном примере печатает текст.

## Пишем в лоб: ожидали снимок, получили новое значение

Сначала угадай эту короткую программу.

```swift
var text = "План"
let save = { print(text) }
text = "Новый план"
save()
```

Вывод — «Новый план». Замыкание использует захваченную изменяемую переменную, поэтому читает её значение при вызове. `let save` запрещает заменить само действие, но не замораживает text.

Для нашей кнопки это полезно. Для истории «какой текст был при создании действия» такое поведение стало бы багом. Сначала реши, нужен текущий текст или снимок.

## Capture list фиксирует значение

Квадратные скобки перед `in` — список захвата. Для строки `[text]` сохраняет значение на момент создания замыкания.

```swift
var text = "План"
let saveSnapshot = { [text] in print(text) }
text = "Новый план"
saveSnapshot()
```

Теперь вывод — «План». `in` отделяет описание захвата и параметров от тела. Обычный захват похож на чтение текущего документа, а `[text]` — на сохранённый снимок его текста.

Не переноси этот вывод на любой class: `[editor]` сохраняет ссылку на объект, а не глубокую копию всех его свойств. Этот случай разберём глубже; в основе снимок делаем именно строкой.

## Параметр и результат пишем явно

Возьми сначала замыкание без захваченного редактора. Тип `(String) -> String` означает: получает строку, возвращает строку. `uppercased()` возвращает её вариант в верхнем регистре.

```swift
let format: (String) -> String = { value in
    value.uppercased()
}
print(format("План"))
```

Вывод — «ПЛАН». Для уведомления о переименовании нужен тип `(String) -> Void`: он принимает новый текст, но ничего не возвращает. Optional-вариант `((String) -> Void)?` означает, что действия пока может не быть; `onRename?(value)` вызовет его только при наличии.

Так можно передавать в действие уже выбранный текст, а не заставлять его читать объект редактора. В практике попробуешь оба маршрута.

## Объект держит действие, действие держит объект

Теперь DraftEditor имеет `var text = "План"` и `var onSave: (() -> Void)?`. Ниже — его метод; `() -> Void` означает действие без параметров и результата.

```swift
func configure() {
    onSave = { print(self.text) }
}
```

Редактор хранит замыкание, а оно сильно удерживает self — этот же редактор. Получается цикл владения: убрать внешнюю ссылку недостаточно. `deinit` — код, выполняемый при освобождении экземпляра; из-за цикла он не сработает в этой проверке.

Важно именно кольцо. Сильный захват объекта в замыкании сам по себе не всегда утечка. Здесь объект и его собственное сохранённое действие удерживают друг друга.

## weak self разрывает кольцо

Замени только способ захвата. Это метод того же DraftEditor.

```swift
func configure() {
    onSave = { [weak self] in
        guard let self else { return }
        print(self.text)
    }
}
```

`weak` не удерживает объект живым. Если его уже освободили, self внутри действия — nil; guard завершает вызов. Если редактор ещё жив, guard получает его и удерживает на время выполнения этого тела.

Для проверки создай optional editor, настрой действие, заведи `weak var probe = editor`, сохрани копию onSave и присвой editor = nil. probe станет nil. Вызов оставшейся копии действия ничего не напечатает и не упадёт.

## Хранение действия и @escaping

Если действие передают в метод, а он сохраняет его после своего завершения, параметр нужно пометить `@escaping`. Этот отдельный помощник запоминает переданный код.

```swift
final class SaveSlot {
    var action: (() -> Void)?
    func install(_ action: @escaping () -> Void) {
        self.action = action
    }
}
```

Не путай разрешение хранить действие с его вызовом: install ещё ничего не выполняет. В нашем configure литерал замыкания присваивается свойству напрямую, поэтому отдельного параметра @escaping там нет.

Перед сохранением спроси две вещи: какие значения действие должно увидеть позже и кого оно удерживает. Для счётчика версии редактора хранимое действие читает актуальную revision через weak self так же, как сейчас text.

## Собираем безопасное действие

Пройди жизнь объекта по строкам: пока editor существует, действие читает новый текст; после editor = nil остаётся только слабый доступ.

```swift
final class DraftEditor {
    let id = 11
    var text = "План"
    var onSave: (() -> Void)?
    func configure() {
        onSave = { [weak self] in
            guard let self else { return }
            print(self.text)
        }
    }
    deinit { print("Редактор освобождён") }
}
var editor: DraftEditor? = DraftEditor()
editor?.configure()
editor?.text = "Новый план"
editor?.onSave?()
weak var probe = editor
let savedAction = editor?.onSave
editor = nil
print(probe == nil)
savedAction?()
```

Вывод: «Новый план», «Редактор освобождён», true. Последний вызов savedAction ничего не добавляет.

- Нужен снимок строки — захвати `[text]`.
- Нужен параметр события — передай его в замыкание.
- Собственное сохранённое действие не должно бессрочно удерживать владельца; weak self подходит, если после закрытия действие можно пропустить.

## Проверь себя

Закрой итог и нарисуй две стрелки владения мысленно.

- Почему обычный save увидел новый текст, а saveSnapshot — старый?
- Какая стрелка создаёт цикл в DraftEditor и какую убирает weak self?
- Почему оставшееся действие безопасно вызвать после освобождения и что произойдёт в guard?

## Ответы к «Проверь себя»

- Обычный `save = { print(text) }` захватывает саму изменяемую переменную и читает её значение в момент вызова, поэтому после `text = "Новый план"` печатает новый текст. `saveSnapshot = { [text] in print(text) }` через список захвата сохраняет значение строки на момент создания замыкания — это снимок, и он печатает «План». `let save` здесь ничего не замораживает: он лишь запрещает заменить само действие.
- Первая стрелка: редактор хранит действие в `onSave`. Вторая: замыкание `{ print(self.text) }` сильно удерживает `self`, тот же редактор, — вместе они держат друг друга, и `deinit` не сработает даже после `editor = nil`. `[weak self]` убирает вторую стрелку: действие больше не удерживает редактор, а редактор по-прежнему хранит действие.
- Действие держит редактор через `weak`, поэтому после освобождения `self` внутри него становится `nil`. `guard let self else { return }` видит `nil` и тихо завершает вызов: `savedAction?()` ничего не напечатает и не упадёт. Если редактор ещё жив, guard получает его и удерживает только на время выполнения тела.

# ГЛУБЖЕ

## Снимок ссылки не копирует объект

Представь `let action = { [editor] in print(editor.text) }` для существующего class-редактора. Список захвата сохраняет ссылку на этот экземпляр и удерживает его; изменение его text будет видно при вызове.

Если нужен старый текст, захватывай `[text = editor.text]`, то есть строковое значение. Попробуй сначала назвать, что именно копируется: значение строки или ссылка на объект. Это помогает не приписывать capture list глубокое копирование.

## Почему не unowned по умолчанию

В нашей миссии действие переживает редактор. Поэтому unowned self не подходит: оно не удерживает владельца, но предполагает, что он ещё жив при обращении. Нарушишь предположение — получишь ошибку времени выполнения.

weak даёт Optional и позволяет пропустить действие. Выбирай unowned только при доказанном общем жизненном цикле; желание убрать guard такой гарантией не является.

## Цикл можно разорвать и прекращением хранения

Если объект явно завершает работу и ставит onSave = nil, сильная обратная ссылка из его действия исчезает. Это возможное управление жизнью, но команда завершения должна действительно выполниться.

Не рассчитывай почистить такое кольцо только в deinit: до него как раз нельзя дойти из-за удержания. Для действия, которое должно свободно пережить закрытие владельца, слабый захват остаётся простым решением.

## Короткая запись не меняет время захвата

После явного параметра можно встретить `$0`, первый аргумент замыкания. Например, `{ $0.uppercased() }` — короткая версия format с известным типом `(String) -> String`.

Не сокращай код, пока не можешь назвать момент создания и вызова. Асинхронное действие добавит ещё требования к потокам и передаваемым данным; @escaping само по себе не означает ни фон, ни параллельность.
