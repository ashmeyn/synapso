scenario: Перед оплатой нужно найти первую позицию корзины, для которой запрошенного количества нет на складе. Функция возвращает id этой позиции или nil, если все товары доступны.
goals:
- превращать условие задачи в сигнатуру, примеры и каркас функции
- выбирать место для проверки, раннего `return` и итогового `nil`
- проверять порядок результата и менять каркас при новом требовании

## Сначала договариваемся о результате

Смотри: нам нужен номер проблемной позиции, чтобы экран подсветил именно её. «Первая» означает первую по порядку корзины. Количества в этом уроке уже проверены: запрос положительный, остаток неотрицательный.

```swift
struct CartItem {
    let id: Int
    let quantity: Int
    let stock: Int
}
let cart = [
    CartItem(id: 20, quantity: 1, stock: 3),
    CartItem(id: 70, quantity: 4, stock: 2),
    CartItem(id: 10, quantity: 2, stock: 0)
]
```

Здесь ответ — 70. Номер 10 меньше, но его позиция идёт позже. Если проблем нет, номера ответа вообще не существует.

## Пишем в лоб и теряем слово «первая»

Тут стажёры часто заводят переменную и переписывают её при каждой проблеме. Код выглядит разумно, но вернёт последнюю недоступную позицию.

```swift
func lastUnavailableID(in items: [CartItem]) -> Int? {
    var result: Int? = nil
    for item in items {
        if item.quantity > item.stock { result = item.id }
    }
    return result
}
print(lastUnavailableID(in: cart) as Any) // Optional(10)
```

Остановись на этом примере: ошибка возникла из требования к результату. Нам не нужен «последний запомненный номер». Нам нужно закончить поиск при первой проблеме.

## Шаг первый: обещаем правильный тип

Окей, начни с одной строки, даже если тело пока не придумал. Вход — массив позиций, выход — номер или отсутствие номера.

```swift
func firstUnavailableID(in items: [CartItem]) -> Int? {
    // Пока ничего не нашли.
    return nil
}
```

`[CartItem]` описывает вход, `Int?` — оба исхода. Это пока заглушка, не решение. Зато ты уже знаешь, что функция должна вернуть и почему ноль не подходит как запасной ответ: он мог бы быть настоящим `id`.

## Шаг второй: проходим в нужном порядке

Смотри на пустое тело как на три места: проход, действие над позицией, ответ после прохода. `for-in` берёт элементы массива в его порядке.

```swift
func firstUnavailableID(in items: [CartItem]) -> Int? {
    for item in items {
        // Проверим текущую позицию здесь.
    }
    return nil
}
```

Пока нам не нужен отдельный массив ответов или счётчик: результатом будет один номер. Для пустой корзины цикл не выполнится, и функция сразу вернёт `nil`.

## Шаг третий: решаем за одну позицию

Теперь забудь на минуту про весь массив. Можешь проверить одну позицию? Нужно сравнить, сколько пользователь просит, с тем, сколько есть.

```swift
let item = CartItem(id: 70, quantity: 4, stock: 2)
let unavailable = item.quantity > item.stock
print(unavailable) // true
```

`>` важен: когда запрос равен остатку, товар доступен. После правильного условия остаётся решить, что делать при `true`.

## Шаг четвёртый: заканчиваем поиск

Вот здесь ставим `return item.id` внутри цикла. `return` завершает всю функцию, поэтому следующая недоступная позиция уже не сможет заменить первую.

```swift
func firstUnavailableID(in items: [CartItem]) -> Int? {
    for item in items {
        if item.quantity > item.stock { return item.id }
    }
    return nil
}
```

Последний `nil` означает «проверили все позиции, проблемы нет». Если поставить его внутри цикла после `if`, первая доступная позиция остановит проверку всей корзины — это уже другой баг.

## Подвох: ровно столько, сколько осталось

Проверь пограничный случай руками, прежде чем считать задачу решённой. Пользователь просит две штуки, на складе две: условие `>` ложно, значит проблемного номера нет.

```swift
let exact = [CartItem(id: 90, quantity: 2, stock: 2)]
print(firstUnavailableID(in: exact) as Any) // nil
print(firstUnavailableID(in: []) as Any) // nil
```

Тебя спросят: «Почему не `>=`?» Потому что равенство разрешено условием задачи. Такой короткий пример помогает проверить требование лучше, чем долго смотреть на цикл.

## Собираем функцию без подсказок

Окей, попробуй сначала написать её сам, а затем сравнить. Порядок рассуждения такой: вход и выход → проход → проверка одного элемента → два места возврата.

```swift
struct CartItem {
    let id: Int
    let quantity: Int
    let stock: Int
}
func firstUnavailableID(in items: [CartItem]) -> Int? {
    for item in items {
        if item.quantity > item.stock { return item.id }
    }
    return nil
}
let cart = [
    CartItem(id: 20, quantity: 1, stock: 3),
    CartItem(id: 70, quantity: 4, stock: 2),
    CartItem(id: 10, quantity: 2, stock: 0)
]
print(firstUnavailableID(in: cart) as Any) // Optional(70)
```

- Если ответ может отсутствовать — вырази это типом результата.
- Если нужен первый подходящий элемент — проверь порядок прохода и верни его сразу.
- Если цикл закончился без ответа — верни отсутствие ответа после цикла.

## Проверь себя

Объясни вслух, что произойдёт с каждой позицией корзины. Если можешь назвать только итог, пройди пример ещё раз и назови точную строку выхода.

- Почему для нашей корзины ответ 70, хотя недоступен и товар 10?
- Что сломается, если перенести `return nil` внутрь цикла после проверки?
- Какой результат нужен при пустой корзине и при запросе, равном остатку?

## Ответы к «Проверь себя»

- Нужна первая недоступная позиция по порядку корзины, а не самая маленькая. `for-in` идёт по массиву по порядку, на `id 70` условие `4 > 2` истинно, и `return item.id` сразу завершает всю функцию. До товара 10 проверка уже не доходит, поэтому он не может заменить ответ, как это было с переменной в `lastUnavailableID`.
- Тогда первая же доступная позиция вернёт `nil` и остановит проверку всей корзины. Для нашей корзины товар 20 доступен (`1 > 3` ложно), и функция ответит «проблем нет», не дойдя до 70. `return nil` стоит после цикла, потому что означает «проверили все позиции, проблемы нет».
- В обоих случаях нужен `nil`. При пустой корзине цикл не выполнится ни разу, и функция сразу дойдёт до `return nil` после него. При запросе, равном остатку, `2 > 2` ложно, потому что равенство разрешено условием задачи, — поэтому в условии `>`, а не `>=`.

# ГЛУБЖЕ

## Задачу поменяли: нужны все проблемные позиции

Смотри, теперь первый `return` мешает: экран хочет подсветить каждую проблему. Меняем результат на `[Int]`, заводим массив и возвращаем его после полного прохода.

```swift
func unavailableIDs(in items: [CartItem]) -> [Int] {
    var result: [Int] = []
    for item in items {
        if item.quantity > item.stock { result.append(item.id) }
    }
    return result
}
```

Это и есть смысл каркаса: место результата, проход, шаг, возврат остаются понятными, но содержимое выбирается под требование. Счётчик нужен для количества, массив — для всех номеров, словарь — для группировки. Иногда под задачу нужен другой проход: два указателя или окно.

## Проверка корзины не резервирует товар

Вот тут настоящая граница функции: мы проверяем известный нам снимок остатков. Между проверкой и оплатой другой покупатель может забрать товар. Локальный `nil` не обещает, что сервер разрешит покупку.

В рабочем приложении сервер повторно проверяет остатки при оформлении. Отрицательные количества и остатки тоже нужно проверять отдельно; здесь это явное условие входа. Не добавляй новые правила в цикл молча: сначала договорись, каким результатом сообщать о неверных данных.

## Как объяснить решение на собеседовании

Тебя спросят: «Какая сложность?» При n позициях в худшем случае проверим все n: O(n) времени. Дополнительное место для первой версии постоянно: O(1). Если проблема стоит первой, выйдем после одной проверки — лучший случай O(1).

Назови и набор проверок: пустая корзина, одна доступная позиция, точное равенство, первая проблема в начале и в конце, две проблемы с разными номерами. Так ты показываешь, что проверил обещание функции, а не просто запомнил форму цикла.
