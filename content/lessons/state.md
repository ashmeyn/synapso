## Что должно измениться на экране

Давай начнём с того, что увидит человек. Он открыл заметку 41: сверху написано «Купить билеты», ниже находится поле ввода. Ты меняешь в нём текст на «Заказать билеты» — верхняя надпись должна показать то же самое.

```swift
import SwiftUI
struct Note {
    let id: Int
    var title: String
}
```

Какое поле здесь должно меняться? `title`: именно его человек редактирует. `id` обозначает заметку и от переименования не меняется. Мы редактируем локальный черновик, а не отправляем изменения на сервер.

Экран в SwiftUI описывается структурой с `: View`. Её свойство `body` описывает содержимое. Запись `some View` означает, что содержимое является представлением; подробности этого типа разберём в отдельной теме.

## Пишем в лоб: обычного var недостаточно

Первый ход напрашивается сам: держим заметку в `var`, а кнопкой меняем заголовок. Давай проверим, разрешит ли это Swift. Здесь `Button` получает подпись и действие в фигурных скобках: этот код выполняется при нажатии. Но такой вариант не компилируется.

```swift
struct NoteScreen: View {
    var note = Note(id: 41, title: "Купить билеты")
    var body: some View {
        Button("Переименовать") {
            note.title = "Заказать билеты" // ❌ self is immutable
        }
    }
}
```

Компилятор сообщает `cannot assign to property: 'self' is immutable`. В этом действии нельзя так менять обычное свойство структуры `View`. Здесь проблема не в изменяемости поля `title`. Нам нужен способ менять состояние, пока SwiftUI управляет экраном.

## Один владелец черновика

Окей, оставляем заметку на экране, но отдаём её хранение SwiftUI: добавь `@State`. Это специальная обёртка свойства: SwiftUI управляет его хранилищем и отслеживает изменения, от которых зависит интерфейс. `private` оставляет состояние внутренним делом этого экрана.

```swift
struct NoteScreen: View {
    @State private var note = Note(id: 41, title: "Купить билеты")
    var body: some View {
        VStack {
            Text(note.title)
            Button("Переименовать") { note.title = "Заказать билеты" }
        }
    }
}
```

`VStack` располагает содержимое вертикально, `Text` показывает строку. Нажатие изменяет заголовок в хранилище состояния. SwiftUI обновляет зависящее от него представление: надпись должна стать «Заказать билеты».

Вот и первый рабочий шаг: кнопка меняет данные, а надпись читает их. Пока черновиком владеет `NoteScreen`, нам не нужно отдельно командовать надписи «обновись».

## Значение для чтения, связь для редактирования

Теперь вместо готового переименования нужен ввод. Что передать полю: сам текст или возможность его менять? `note.title` — строка, которую можно показать. `$note.title` — `Binding<String>` к тому же заголовку: связь с возможностью читать и записывать значение.

`@State` — оригинал документа у владельца, а Binding — доступ на редактирование того же документа, а не копия.

Замени `VStack` внутри предыдущего `NoteScreen` следующим фрагментом.

```swift
VStack {
    Text(note.title)
    TextField("Заголовок", text: $note.title)
}
```

`TextField` — редактируемое текстовое поле. Ему нужна связь, потому что оно должно записывать ввод обратно в черновик. Через `$note` мы получаем связь к состоянию, а `.title` выбирает его поле.

Если рука тянется поставить `$` везде, спроси себя: этому элементу надо только читать или ещё записывать? `Text` читает строку, а `TextField` должен менять её.

## Выносим поле, не создавая второй черновик

Поле уже работает. Давай вынесем его в `TitleEditor`, чтобы не держать всю разметку в родителе. Он получает `@Binding`, потому что владельцем остаётся родительский экран. Обёртка даёт дочернему представлению доступ к переданному значению без собственного независимого хранилища.

```swift
struct TitleEditor: View {
    @Binding var title: String
    var body: some View {
        TextField("Заголовок", text: $title)
    }
}
```

Внутри родительского `VStack` вызов будет таким:

```swift
TitleEditor(title: $note.title)
```

Посмотри на вызов: имя аргумента осталось `title`, но передаём мы связь, а не строку. В дочернем поле `$title` передаёт эту же связь дальше в `TextField`. Это не `inout`: перед вызовом нет `&`, и работа не заканчивается возвратом из одной функции.

## Проходим одно редактирование руками

Пока не переходи к практике: прогоним одну правку по цепочке. Сначала оба места показывают «Купить билеты». Пользователь заменяет содержимое поля на «Заказать билеты».

- `TextField` записывает новую строку через переданный Binding.
- `TitleEditor` обращается к заголовку черновика в родительском состоянии.
- В родительском черновике `note.title` теперь содержит «Заказать билеты».
- При обновлении интерфейса `Text(note.title)` показывает новую строку.

Родитель может тоже изменить `note.title`, например кнопкой: поле получит новое значение из того же источника. Двусторонняя связь означает чтение и запись одного состояния, а не пересылку между двумя копиями.

## Подвох: дочерний State выглядит похоже

А теперь проверим соблазнительный вариант: раз родителю помог `@State`, может, дать такой же ребёнку? У этого варианта собственное состояние, и родитель вызывает его как `TitleEditor()`, не передавая связь.

```swift
struct TitleEditor: View {
    @State private var title = "Купить билеты"
    var body: some View {
        TextField("Заголовок", text: $title)
    }
}
```

Ввод меняет только дочерний `title`. Родительский `note.title` остаётся прежним: верхняя надпись и поле расходятся. Получилось два черновика. Поле работает само по себе, но обещание «сразу обновить верхнюю надпись» мы потеряли.

Исправление — вернуть `@Binding var title: String` и передать `$note.title`. Даже одинаковый начальный текст не делает два хранилища одним. Если стереть весь заголовок, наш правильный вариант покажет пустую строку и в поле, и сверху: в этой миссии пустой текст разрешён.

## Собираем редактор с одним источником

Закрой предыдущие куски и назови роли двух структур: кто хранит, кто редактирует? Теперь собери их и сравни с итогом. Родитель хранит черновик, показывает его и передаёт связь. Дочерний элемент только редактирует полученный заголовок.

```swift
import SwiftUI
struct Note {
    let id: Int
    var title: String
}
struct NoteScreen: View {
    @State private var note = Note(id: 41, title: "Купить билеты")
    var body: some View {
        VStack {
            Text("Заметка \(note.id)")
            Text(note.title)
            TitleEditor(title: $note.title)
        }
    }
}
struct TitleEditor: View {
    @Binding var title: String
    var body: some View {
        TextField("Заголовок", text: $title)
    }
}
```

- Владелец локального черновика объявляет `@State`.
- Редактор чужого значения получает `@Binding`.
- Передача через `$` даёт связь; обычное чтение даёт само значение.

## Проверь себя

Представь, что напарник видит только две структуры и спрашивает, зачем здесь две разные обёртки. Объясни ему путь одной правки: от ввода до верхней надписи. Если застрял, начни с владельца черновика.

- Где хранится черновик заметки 41 и что именно меняет `TextField`?
- Почему `Text` получает `note.title`, а `TitleEditor` — `$note.title`?
- Что увидишь после стирания заголовка и почему дочерний `@State` нарушает нашу миссию?

## Ответы к «Проверь себя»

- Черновик хранится в `@State private var note` у `NoteScreen`: этот экран — владелец, и SwiftUI управляет хранилищем и следит за изменениями. `TextField` своей копии не держит: через переданный Binding он записывает строку прямо в `note.title` родителя. Поэтому после ввода меняется исходный черновик, и `Text(note.title)` при обновлении показывает новую строку.
- `Text` только показывает строку, ему хватает значения `note.title`. `TitleEditor` должен записывать ввод обратно, поэтому получает `$note.title` — `Binding<String>` к тому же заголовку, доступ на редактирование того же документа, а не копию. Сверяешь правило: элементу надо только читать — значение, ещё и записывать — связь через `$`.
- В правильном варианте стёртый заголовок даёт пустую строку и в поле, и в верхней надписи: источник один, а пустой текст в этой миссии разрешён. Дочерний `@State private var title` — второй, независимый черновик: ввод меняет только его, а родительский `note.title` остаётся «Купить билеты». Надпись и поле расходятся, и обещание «сразу показать тот же текст наверху» нарушено, даже если начальный текст совпадал.

# ГЛУБЖЕ

## Пересоздание описания не равно новому экрану

Погоди: SwiftUI может снова создать значение структуры `NoteScreen`. Не получится ли каждый раз «Купить билеты»? Здесь полезно разделить описание экрана и его хранилище состояния: SwiftUI связывает хранилище с идентичностью представления.

Пока идентичность `NoteScreen` сохраняется, изменение других данных и повторный расчёт `body` сами по себе не возвращают начальную строку. Удаление экрана из иерархии или смена его идентичности может привести к новому состоянию. Перезапуск приложения тоже не сохраняет наш черновик: для этого нужен отдельный механизм хранения.

Поэтому два разных открытия редактора могут получить разные черновики, хотя у обоих один тип `NoteScreen`. Важен конкретный экземпляр экрана в иерархии, а не одно название структуры.

## Постоянный Binding не проверяет редактирование

Допустим, тебе нужно просто посмотреть, как выглядит поле с готовой строкой. Для такого снимка подойдёт этот вызов. `.constant` создаёт Binding с фиксированным значением: записи через него не меняют исходные данные.

```swift
TitleEditor(title: .constant("Купить билеты"))
```

Если подставить его вместо `$note.title` на рабочем экране, пользовательский ввод не сможет обновить родительский черновик. Такой снимок не проверяет двустороннюю связь.

Хочешь проверить именно редактирование — открой весь `NoteScreen` из итога. У него есть владелец State, поэтому ввод может пройти до родительского черновика.

## Родитель сбрасывает тот же черновик

Теперь человек передумал и хочет вернуть исходный заголовок. Где должна действовать кнопка сброса? У того, кто хранит черновик. Не создавай второй State для поля — добавь действие внутрь `VStack` родительского `NoteScreen`.

```swift
Button("Сбросить") {
    note.title = "Купить билеты"
}
```

Пройди путь в другую сторону: родитель меняет `note.title`, дочернее поле читает его через Binding, оба места показывают исходную строку.

Если приложению нужна отмена до произвольного заголовка, пришедшего с сервера, исходное значение надо хранить отдельно и явно задавать момент его обновления. В этом уроке исходный текст фиксирован условием задачи.

## @State из параметра

А если передать начальный текст от родителя? Этот редактор принимает `title`, но затем живёт со своим черновиком. Не перепутай стартовое значение и постоянную связь.

```swift
struct DraftEditor: View {
    @State var title: String
    init(title: String) {
        _title = State(initialValue: title)
    }
    var body: some View {
        TextField("Заголовок", text: $title)
    }
}
```

`_title` — сама обёртка State; здесь мы задаём ей начальное значение. Для одной идентичности экрана хранилище создаётся при первом появлении: следующий вызов `init` с другой строкой не заменяет уже установленное состояние.

Родитель передал «Купить билеты», ребёнок набрал «Выбрать места». Родитель передал «Заказать билеты» тому же редактору — его локальный черновик по-прежнему «Выбрать места». Нужен общий редактируемый заголовок — используй `TitleEditor(title: $note.title)` с Binding. Нужно только показывать текущий текст — передай значение:

```swift
struct TitleLabel: View {
    let title: String
    var body: some View { Text(title) }
}
```

При обновлении родитель передаст новую строку в `TitleLabel`. Независимый State-черновик уместен, если этого требует задача.

## Та же связь для переключателя и счётчика

Проверь, не привязал ли ты правило только к строкам. Редактируемый `Bool` тоже требует Binding: переключатель должен записать новое значение владельцу. Этот фрагмент — отдельный маленький экран настройки, а не замена нашей заметки.

```swift
struct PinSetting: View {
    @State private var isPinned = false
    var body: some View {
        Toggle("Закрепить", isOn: $isPinned)
    }
}
```

`Toggle` переключает `false` и `true`. Если вынести его в ребёнка, ребёнку нужен `@Binding var isPinned: Bool`; владелец передаст `$isPinned`.

Счётчик работает по тому же правилу. Здесь новый экран задаёт диапазон от одного до пяти:

```swift
struct CountSetting: View {
    @State private var count = 1
    var body: some View {
        Stepper("Количество: \(count)", value: $count, in: 1...5)
    }
}
```

`Stepper` меняет число кнопками минус и плюс. `1...5` — включительный диапазон: ниже одного и выше пяти этот элемент не идёт. Читателю достаточно значения; полю, переключателю и счётчику нужна возможность записывать его.
