## Эстафета через init

Читалка: экран библиотеки → экран книги → список глав → строка главы. Размер шрифта живёт в модели настроек, а нужен он только строке, в самом низу.

```swift
@Observable
final class ReaderSettings {
    var fontSize = 17.0
}
```

Пишем в лоб: библиотека создаёт настройки и передаёт их в `BookScreen(settings:)`, тот — в `ChapterList(settings:)`, тот — в `ChapterRow(settings:)`. Экран книги и список глав шрифт не читают, они просто держат эстафетную палочку. Добавишь ещё один уровень — правишь ещё один `init`.

## Окружение — это Wi-Fi в квартире

У SwiftUI есть второй путь доставки данных — окружение (environment). Это набор значений, которые родитель кладёт один раз, а любая вью ниже по дереву читает сама, без параметров.

Как Wi-Fi: роутер в прихожей раздаёт сеть всем комнатам, проводов к каждой не нужно. Комната, где сеть не нужна, о ней и не знает. А отдельный роутер в спальне раздаёт свою сеть — только для своей комнаты.

## Модель через .environment

Владелец создаёт модель и кладёт её в окружение своего поддерева:

```swift
struct LibraryScreen: View {
    @State private var settings = ReaderSettings()
    var body: some View {
        BookScreen()
            .environment(settings)
    }
}
```

Читает тот, кому нужно, — строка главы:

```swift
struct ChapterRow: View {
    let title: String
    @Environment(ReaderSettings.self) private var settings
    var body: some View {
        Text(title)
            .font(.system(size: settings.fontSize))
    }
}
```

`BookScreen` и `ChapterList` теперь без параметра `settings`. Ключ поиска — сам тип `ReaderSettings`. Поменяли `fontSize` — строка перерисуется, как с любой `@Observable`-моделью из темы obs.

Обратная сторона: зависимость не видна в `init`. Если ни один предок не положил `ReaderSettings`, приложение упадёт при первом чтении — компилятор не предупредит. Проверяй, что `.environment(...)` стоит выше каждого места, где вью может появиться.

Когда что выбирать? Окружение — для сквозного, что нужно многим уровням: настройки, тема. Параметр `init` — для того, без чего экран не имеет смысла, например id книги: его видно в сигнатуре и его нельзя забыть передать.

## dismiss — значение окружения

Окружение несёт и системные значения: цветовую схему, локаль, динамический размер текста (`dynamicTypeSize`). Одно из самых нужных — действие `dismiss`, «закрой то, что показало меня».

```swift
struct NoteEditor: View {
    @Environment(\.dismiss) private var dismiss
    @State private var text = ""
    var body: some View {
        VStack {
            TextField("Заметка", text: $text)
            Button("Готово") { dismiss() }
        }
    }
}
```

Родитель показывает редактор через `.sheet(isPresented: $showsEditor) { NoteEditor() }`. Редактору не нужен `Binding` на флаг родителя: `dismiss` сам знает, кто его показал. `\.dismiss` — путь к значению внутри системного окружения.

Важно, где ты его объявил. `dismiss` закрывает ближайший показ, внутри которого прочитан: sheet или экран, открытый push в `NavigationStack`. Объявишь его в родителе — закроешь показ родителя (например, уйдёшь назад по стеку), а не sheet. Если родитель — корень, вызов ничего не сделает.

## Свой ключ окружения

Своё значение — например, поля страницы — объявляют двумя шагами: ключ со значением по умолчанию и свойство в `EnvironmentValues`.

```swift
struct PageMarginKey: EnvironmentKey {
    static let defaultValue = 16.0
}
extension EnvironmentValues {
    var pageMargin: Double {
        get { self[PageMarginKey.self] }
        set { self[PageMarginKey.self] = newValue }
    }
}
```

Кладут: `.environment(\.pageMargin, 24)`. Читают: `@Environment(\.pageMargin) private var margin`. Если никто не положил, вью получит `16` — не падение, а значение по умолчанию.

Значение течёт только вниз и только по поддереву. Для обычных ключей побеждает ближайший предок, который положил значение, — это и есть роутер в спальне. Соседняя ветка его не видит.

Отсюда правило для sheet. `.environment(...)` действует на то, что оборачивает. Содержимое sheet получает окружение той точки, где стоит `.sheet`, поэтому `.sheet` должен быть внутри, то есть раньше в цепочке модификаторов. Другой способ — положить значение прямо на содержимое: `.sheet(...) { NoteEditor().environment(settings) }`.

## Собираем

```swift
struct LibraryScreen: View {
    @State private var settings = ReaderSettings()
    @State private var showsEditor = false
    var body: some View {
        VStack {
            ChapterRow(title: "Глава 1")
            Button("Заметка") { showsEditor = true }
        }
        .sheet(isPresented: $showsEditor) { NoteEditor() }
        .environment(settings)
        .environment(\.pageMargin, 24)
    }
}
```

- Модель — `.environment(model)` у владельца, `@Environment(Тип.self)` у читателя.
- Закрыть показанный экран — `dismiss`, объявленный в нём самом.
- Свой ключ — `EnvironmentKey` с `defaultValue` и свойство в `EnvironmentValues`; побеждает ближайший предок.
- `.environment` оборачивает `.sheet` — тогда редактор в sheet получит и модель, и поля.

## Проверь себя

- Чем `.environment(settings)` лучше передачи модели через три `init` и чем хуже?
- Редактор открыт как sheet. Где объявить `@Environment(\.dismiss)`, чтобы «Готово» закрыло редактор, и что будет, если объявить его в родителе?
- `.environment(\.pageMargin, 24)` стоит на `VStack`, а внутри одна из строк обёрнута в `.environment(\.pageMargin, 8)`. Что увидит эта строка, её соседка и вью вне `VStack`?

## Ответы к «Проверь себя»

- Промежуточные экраны больше не держат чужую модель: её кладут один раз у владельца, а читает только тот, кому она нужна, — новый уровень вложенности не требует правки `init`. Цена — зависимость не видна в сигнатуре: если предок не положил модель, приложение упадёт при чтении, и компилятор об этом не скажет.
- В самом редакторе: `dismiss` закрывает ближайший показ, внутри которого прочитан, а редактор показан как sheet, значит, «Готово» его и закроет. Объявленный в родителе `dismiss` относится к показу родителя: если родитель открыт push, «Готово» уведёт назад по стеку, если он корень — не сделает ничего.
- Строка со своим модификатором увидит `8`: побеждает ближайший предок. Соседка внутри `VStack` увидит `24`. Вью вне `VStack` значения не получит и прочитает `defaultValue` — `16`.

# ГЛУБЖЕ

## @Entry вместо двух шагов

С Xcode 16 ключ объявляют одной строкой макросом: `extension EnvironmentValues { @Entry var pageMargin = 16.0 }`. Макрос сам создаёт ключ и `get/set` и работает и в проектах под iOS 17. Ручной `EnvironmentKey` встретишь в коде, написанном раньше, — понимай оба.

## Старый путь: @EnvironmentObject

До Observation модель-`ObservableObject` клали через `.environmentObject(model)` и читали `@EnvironmentObject var model: Model`. Механика та же — поиск по типу, падение при отсутствии. В новом коде с `@Observable` используют `.environment(model)`; в легаси встретишь оба.

## Превью и тесты

Превью — тоже корень дерева. Если вью читает `@Environment(ReaderSettings.self)`, превью обязано положить модель: `#Preview { ChapterRow(title: "Глава 1").environment(ReaderSettings()) }`. Иначе превью упадёт, как упало бы приложение.

## Окружение как DI — и где оно не к месту

Окружение — внедрение зависимостей (DI, подробно — в теме di) средствами SwiftUI: удобно для сквозных вещей вроде настроек, темы, сервиса аналитики. Для зависимостей, без которых экран не имеет смысла, явный параметр `init` честнее: его видно и его нельзя забыть. Хорошее правило — окружение для того, что нужно многим уровням, `init` — для того, что нужно этому экрану.
