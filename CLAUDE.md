# Synapso — правила для Claude Code

## Что это и для кого

Synapso — личная iOS-лаборатория Дана: 3D-карта знаний в виде мозга (76 тем), уроки-миссии, практика по 7 ступеням, банк задач, ран и интервальные повторы. Сайт собирается в один HTML-файл.

Дан переходит из барменства в iOS-разработку (цель — junior/middle). Приложение построено под его метод recall-first:

1. Узнавание ≠ воспроизведение. Статус темы растёт только после того, как Дан вытащил ответ из головы, и никогда после чтения.
2. Одна концепция за раз.
3. Объяснение идёт по схеме «что это → почему так устроено → какие последствия», с одной аналогией.
4. Каркас «вот скелет, заполни» лучше голой сократики.

Общение с Даном — на русском, код и термины — на английском. Не пиши, что тема «пройдена», если это не так.

## Карта репозитория

1. `content/lessons/<id>.md` — 76 уроков формата v2 (frontmatter + Markdown).
2. `content/steps/<id>.json` — 7 ступеней практики `[{id, title, prompt, code, key}]`.
3. `content/bank/<id>.bank.json` — банк задач по темам. `zz-live` нарочно последний: сборщик читает файлы по алфавиту.
4. `content/base/{content,tasks,bank,cases,ref}.json` — данные старой доски. `content.json` задаёт список тем (урок без записи здесь не соберётся), `ref.json` — `cheat` (шпаргалки), `one`, `follow`.
5. `engine/template.html` — движок (CSS, JS, three.js r128 вшит), на месте данных маркер `__DATA__`.
6. `scripts/build.py` — сборщик (docstring описывает форму данных). `scripts/split_lab.py` — достаёт template и data из сохранённой страницы артефакта.
7. `tests/` — Playwright: smoke всех тем, телефон, десктоп, практика на телефоне (портрет и альбом), объединение прогресса.
8. `docs/` — `content-format.md`, `history.md`, `backlog.md`, `chat-prompts.md`.
9. `dist/` (в .gitignore): `artifact.html` — голая страница для артефакта (doctype и обёртку добавляет хост), `index.html` — полный документ для GitHub Pages.

## Сборка и тесты

```
python3 scripts/build.py                  # dist/artifact.html + dist/index.html
python3 scripts/build.py --check lab.json # сверить данные с выгрузкой лаборатории
npm test                                  # Playwright по dist/index.html
```

Ожидаемая строка сборки: 76 topics · 76 lessons · 262 bank tasks (банк может только расти). CI (`.github/workflows/ci.yml`) гоняет сборку и тесты на каждый push и PR. `pages.yml` на push в main собирает и деплоит `dist/index.html` на https://ashmeyn.github.io/synapso/.

## Жёсткие правила

### Большие файлы

`engine/template.html` (~3700 строк, в том числе минифицированный three.js) и `dist/*` никогда не читай целиком. Только `grep -n`, `grep -o '.\{0,80\}слово.\{0,80\}'` или Read с `offset`/`limit`.

### Формат урока v2 (подробно в docs/content-format.md)

1. Шапка: `mission`, `scenario` (1–2 предложения), `goals` (список), `prereqs` (список id тем).
2. `mission` = `ОПЕРАЦИЯ N · ЗАГОЛОВОК`, заголовок целиком заглавными, N = позиция темы на карте (порядок `BRANCHES` в шаблоне).
3. Без предпосылок строку `prereqs` не пиши вообще: `prereqs: []` ломает парсер (получается список из символов).
4. Разделы `##`. Строка `# ГЛУБЖЕ` отделяет углублённый слой. Разрешено: абзацы, ```swift, списки `- `, плашки `> `, `код`, **жирный**.
5. Голос ментора, одна аналогия. Сценарии — обычные приложения, без бара и кафе.
6. Строки кода в уроке, ступенях и банке — до 80 символов. Без пустых строк внутри кода и в его конце.
7. В прозе пиши «ступень N», а не «s3». Идентификатор в начале предложения сохраняет регистр кода (`hitTest`, а не `HitTest`).
8. Шпаргалка (`ref.cheat[id]`) должна совпадать с уроком: при правке урока проверь её.

### Ступени и банк

1. Каждая цель урока проверяется хотя бы одной письменной ступенью, а не только устной s5.
2. Ступени базового слоя не опираются на ГЛУБЖЕ. s6/s7 переносят идею на новый элемент.
3. Условие ступени не называет ответ. «Найди ошибку» содержит настоящую ошибку, а не заглушку (иначе тип «Допиши»).
4. Не «исправь тестовый JSON» вместо кода. Имена переменных и классов — под модель; у свойства и метода разные имена.
5. Банк тренирует навык, которого нет в ступенях, — три разных экрана, не повторяющие экраны других тем.
6. Общий каркас (стек CoreData и т. п.) выноси в урок, в ступенях оставляй только новую часть.
7. Типы банка: `Предскажи вывод`, `Допиши`, `Найди ошибку`, `Перепиши`, `Устно`. id задач уникальны (сборщик проверяет).

### Решения по интерфейсу (не менять без Дана)

1. Монохром + циан `#2DE2E6`, фиолетовый только на заставке.
2. Шрифты: Handjet (UI, заголовки, подписи), IBM Plex Mono (текст), JetBrains Mono (код, без лигатур и переносов). Размеры через переменные `--fs-*`: 11/13/15/30.
3. Десктоп: интро → 3D-карта, теория открывается по клику, фон реагирует только на курсор над пустым фоном, кастомный курсор. Маршрут — линия внизу «ТЫ ЗДЕСЬ / ДАЛЬШЕ», карточка с одной главной кнопкой и «Уже знаю — сдать проверку».
4. Телефон (с 01.11, заменяет старое решение «Только десктоп»): `PHONE` = `(pointer: coarse)` и ширина < 980 → класс `html.phone`. Без интро, список тем вместо 3D-карты, без WebGL, циклов rAF, печатной машинки и декоративных анимаций. rAF в покое = 0. Принудительно: `#phone` / `#desktop` в URL.

### Телефонный гейтинг

Всё новое для телефона — только под `if (PHONE)` в JS или `html.phone …` в CSS. Десктоп должен остаться без изменений. Определение — инлайн-скрипт в начале шаблона (`grep -n 'classList.add("phone")'`).

### Прогресс

Прогресс живёт в localStorage под ключами `pm.*` (`pm.steps.*`, `pm.srs.*`, `pm.doneAt.*`, `pm.known`, `pm.bank*`, `pm.runs` и др.; с 02.11 честный статус — `pm.recall.*`, `pm.out.*`, `pm.grade.*`, `pm.rans.*`, `pm.outAns.*`, `pm.legacy`, `pm.honest`; «Корни» — `pm.roots.*`, `pm.rootsSkip.*`; с 03.11 возвраты ошибок — `pm.back`, подсказка карты — `pm.mapHint`). Не переименовывай и не меняй формат без миграции в движке и без поддержки старых файлов экспорта. Лаборатория и Pages — разные origin, прогресс переносится экспортом/импортом или через приватный gist (`pm.gist`, токен только на устройстве). С 02.11 импорт и gist **объединяют** прогресс (`mergeProgress` в шаблоне, блок `merge:begin`…`merge:end`, тест `tests/merge.js`): ступень берёт лучшую оценку, SRS — более позднюю дату повтора. Новый ключ прогресса — добавь правило в `mergeProgress`, иначе при конфликте остаётся локальное значение.

## Порядок работы

1. Ветка от main → маленькие коммиты с понятными сообщениями.
2. `python3 scripts/build.py` и `npm test` локально → PR → CI зелёный.
3. Превью для Дана: опубликовать `dist/artifact.html` в лабораторию (см. ниже) или Pages-превью. Для визуальных правок — скриншоты до/после (телефон 390×844, десктоп 1440×900).
4. Дан пишет «ок» → merge в main → Pages деплоит.
5. Новые записи: партии уроков и сверки → `docs/history.md`, задачи → `docs/backlog.md`.

Откатная точка — тег `v1.0-lab57` (состояние лаборатории v57 от 01.11.2026).
