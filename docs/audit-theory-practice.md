# Аудит «теория → практика» (04.11.2026)

Вопрос Дана: если человек прочитал только основу урока (без ГЛУБЖЕ), сможет ли он решить 7 ступеней практики?

Как проверяли: 1) скрипт сверил идентификаторы из ключей ступеней с основой урока, предпосылками и всеми более ранними темами; 2) пять агентов прочитали все 77 тем глазами ученика (только основа + ранние темы, без своих знаний) и оценили каждую ступень: ok — решается по основе; stretch — решается, но нужен неочевидный скачок (норма для ступеней 6–7, проблема для 1–4); gap — нужно то, чего основа не даёт (нет нигде или только в ГЛУБЖЕ). Ключевые выводы перепроверены по исходникам (Toggle/Stepper, `center.post`, `Set.remove`).

## Итог

- 539 ступеней: **483 ok (90%) · 35 stretch · 21 gap**.
- 77 тем: **56 — «да, решается по теории»**, 21 — «в основном», ни одной «нет».
- Ступени 1–4 почти всегда решаются по основе; проблемы собраны на ступени 6 (перенос) — ключ там часто берёт приём из ГЛУБЖЕ.
- Главная системная дыра: `Toggle(…, isOn:)` и `Stepper(…, value:in:)` есть только в ГЛУБЖЕ state, а писать их по памяти требуют obs 6–7, flowui 6, mvvm 6–7 (5 из 21 gap). Урок mvvm ссылается на «Stepper из state», которого в основе state нет.

Частично закрывается чатом 11 (идёт): err 6 (`Result` в основу err), urls 5 (`@MainActor` в основу urls), patt 6 (ступень переписывается — проверить, что новой нужна только `post`, показанная в основе).

## Gap — ступень требует того, чего нет в основе

- **opt · ступень 6** — Условие требует optional chaining (user.name?.count и тип Int?), а ?. объясняется только в ГЛУБЖЕ («Задачу усложнили: имя внутри адреса»). Плюс нужна интерполяция "\(name) · \(count ?? 0)", которой в базе нет.
- **func · ступень 6** — Ссылка на функцию как на значение (let calculator: ([Int], Int) -> Int? = totalMinutes(for:bufferMinutes:)) и правило, что у переменной-функции значение по умолчанию не работает, есть только в ГЛУБЖЕ. В базе функция ни разу не сохраняется в переменную.
- **hof · ступень 6** — reduce(into: [String: Int]()) { result, name in ... } и сабскрипт словаря [name, default: 0] есть только в ГЛУБЖЕ hof. default: впервые появляется в базе только в более поздних bigo и setdict.
- **err · ступень 6** — Result<(String, Int), Error>, его инициализатор Result { try ... } и случаи .success/.failure есть только в ГЛУБЖЕ («Result как сохранённый исход»), причём без switch. Условие подсказывает форму инициализатора, но то, что Result — enum с associated values success и failure, база не говорит.
- **setdict · ступень 6** — Ключ опирается на values.enumerated() и деструктуризацию for (index, value). Обе записи есть только в ГЛУБЖЕ setdict («Та же идея в two-sum»). Без них индекс элемента получить нечем: индексный цикл в базах тоже не показан.
- **obs · ступень 6** — Toggle("Вещи собраны", isOn: $plan.isPacked) нужно написать самому. Инициализатор Toggle с isOn: есть только в ГЛУБЖЕ state (и в готовом коде s6 state). Связка @Observable/@State/@Bindable при этом из базы.
- **obs · ступень 7** — Stepper("…", value: $plan.participants, in: 1...4) и поведение на краях диапазона объясняются только в ГЛУБЖЕ state. К тому же это «проверка по памяти» того, чего база не давала.
- **flowui · ступень 6** — Toggle("Экспресс +100", isOn: $express) есть только в ГЛУБЖЕ flowui и ГЛУБЖЕ state. Тернарный оператор подсказан в условии, поэтому он не проблема.
- **mvvm · ступень 6** — Логика displayMessage подробно описана в базе прозой, но во View нужен Toggle("Показать номер", isOn: $viewModel.includeNumber). Toggle с isOn: не показан ни в одной базе до nav, есть только в ГЛУБЖЕ state и flowui.
- **mvvm · ступень 7** — Stepper(..., value: $viewModel.copies, in: 1...3): база отсылает к state, но там Stepper только в ГЛУБЖЕ. Остальное (totalWeight, weightText) в базе есть.
- **urls · ступень 5** — Вопрос «Почему await не разрешает менять любой UI из любого контекста?» и key «изменение UI требует нужной изоляции MainActor»: в основе есть только «async не означает … в фоне», а MainActor появляется лишь в ГЛУБЖЕ («Результат для экрана»), в ранних темах его нет.
- **eq · ступень 4** — Ключ проверяет удаление через saved.remove(lookup) != nil и saved.isEmpty: Set.remove(_:) и то, что он возвращает Optional, не показаны ни в eq, ни в setdict (там только insert(...).inserted и contains). Плюс промпт не говорит, какие именно строки проверки дописать, а ключ меняет let saved на var.
- **eq · ступень 7** — «найди и удали по второму» требует Set.remove(_:) != nil — API нигде в базе не показан (см. ступень 4).
- **objc · ступень 2** — Ключ требует player.responds(to: selector) — API есть только в ГЛУБЖЕ («Проверка возможности не проверяет сигнатуру»), в базе его нет.
- **collection · ступень 6** — Prompt требует «проверь размерности и число subitems»: widthDimension.dimension, heightDimension.isEstimated и group.subitems нигде в базе не показаны.
- **collection · ступень 7** — Проверка «содержимое обеих секций» требует snapshot.itemIdentifiers(inSection:) — в базе есть только itemIdentifiers без секции; этого API нет ни в базе, ни в ГЛУБЖЕ.
- **patt · ступень 3** — «Опубликуй 21» требует center.post(name:object:userInfo:). В основе есть только addObserver и removeObserver, post нет ни в одном уроке. Создание локального NotificationCenter() тоже не показано.
- **patt · ступень 6** — Та же проблема: проверка требует center.post(name:object:userInfo:), а его нет нигде.
- **uitest · ступень 6** — Ключ требует Bundle(for:).url(forResource:withExtension:), UIImage(contentsOfFile:), XCTUnwrap и XCUIScreenshot.image. Ни одного из этих API нет ни в одном уроке; основа показывает только screenshot и XCTAttachment.
- **feature · ступень 2** — Контракт «непустой title после trim» требует trimmingCharacters(in: .whitespacesAndNewlines), а этого API нет ни в одном уроке. Set.insert(_:).inserted известен из setdict.
- **feature · ступень 4** — «[] только если файла нет» требует отличить отсутствие файла от других ошибок: CocoaError .fileReadNoSuchFile (или FileManager.fileExists). Ни того, ни другого нет ни в одном уроке.

## Stretch на ступенях 1–4 (там скачка быть не должно)

- **opt · ступень 3** — Для "/users/\(id)" нужна интерполяция строк, а в базе opt её нет ни в одном примере. Краткая форма guard let id else тоже не показана; полная guard let id = id выводится из урока.
- **flow · ступень 1** — Ключ ждёт формат печати Optional("СРОЧНО 3") и nil при print(... as Any). В базе flow и в более ранних темах печать Optional и as Any не объясняются (впервые это появляется в skel).
- **hof · ступень 2** — Нужно вернуть кортеж return (recipients, amounts). Тип ([String], [Int]) дан в сигнатуре, но запись кортежа-значения не показана ни в базе hof, ни в более ранних темах.
- **codable · ступень 4** — Решаемо, но это «исправь тестовый JSON» вместо кода (нарушает правило ступеней 4 из CLAUDE.md); многострочная raw-строка #"""…"""# в основе не показана, хотя тут её только читают.
- **valref · ступень 3** — Функция, меняющая var-свойство class-параметра без inout, в базе не показана кодом; выводится из «let фиксирует ссылку» + «inout для значений». Решаемо, но это перенос уже на ступени 3.
- **vclc · ступень 3** — Контроллер есть в «Итоге», но ручной контекст (loadViewIfNeeded(), прямой вызов viewWillAppear(false), подмена loadChapter между вызовами, @MainActor-функция с assert) в базе кодом не показан — loadViewIfNeeded только упомянут.
- **vclc · ступень 4** — Проверка требует задать controller.view.bounds.size.width и вручную вызвать viewDidLayoutSubviews(); такой каркас в базе не показан, есть лишь фраза «можно вызвать методы вручную».
- **frame · ступень 2** — Нужно «самостоятельно вычислить origin» по center и bounds.size, но center в базе не определён, а формула origin = center − size/2 дана только в ключе; вывести её можно лишь из примера с масштабом (центр (100,80) → начало (20,40)).
- **layout · ступень 4** — Ключ меняет root.bounds.size.width и вызывает root.setNeedsLayout() — setNeedsLayout в базе не встречается ни разу; пример с повторным layout на ширине 200 есть только в ГЛУБЖЕ.
- **table · ступень 3** — Ручной вызов source.tableView(table, cellForRowAt:) и конструктор IndexPath(row:section:) в базе не показаны — «вызови его методы для существующей строки» только прозой.
- **hit · ступень 3** — Ключ использует front.isHidden и front.isUserInteractionEnabled; в тексте базы есть только «скрытую view, отключённое взаимодействие», имена свойств появляются лишь в «Ответах к Проверь себя».
- **collection · ступень 2** — Ключ проверяет itemSize.widthDimension.isFractionalWidth/.dimension и groupSize.heightDimension.isEstimated — этих свойств в базе нет; prompt явно требует только порядок id.
- **collection · ступень 3** — Инициализатор UICollectionView(frame:collectionViewLayout:) в базе не показан («уже существуют collectionView»); угадывается по аналогии с UITableView(frame:style:).
- **debug · ступень 4** — Баг «индекс ≠ идентичность» в основе debug не разбирается (появляется лишь в review). Возвращаемое «Не найдено» для удалённой ячейки в условии не названо, его надо перенести из select.
- **feature · ступень 3** — Actor-репозиторий с generation и Task.checkCancellation пишется только по прозе раздела «Два обновления». Части известны (async, actor, RefreshGate из sysd), но образца тела нет; для ступени 3 скачок большой, хотя тема задумана как итоговая сборка.
